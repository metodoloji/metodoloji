## Retrospective Findings (End of Sprint)

- **What went well:** the third value already meant the right thing. UNKNOWN is "cannot establish", and a forced completion is exactly that — so the fix added no concept, only the record that lets the existing concept be reached. The trap (one forced stage locking the run into forcing every later one) was the same bug seen from the operator's side, and closing the record closed both.
- **Could be improved:** the witness was derived from the SPEC since E-056, and that was invisible while every witness happened to be true. The lesson is sharper than "record more": a derived record must say which inputs it was derived FROM — spec, observation, or an explicit override.
- **Actions:**
  - Action 1: never derive a record from the spec alone when an override can bypass the observation — mark provenance on the record — Owner: maintainer
  - Action 2: keep the gate untouched when the fix is about the record; a forced stage still refuses nothing except the evidence it overrode — Owner: maintainer
