## Rollback Plan

Revert the push commit (and this record's commit). The changes are additive:

- The ledger surfaces are warn-only: CHECK 9 never returns an issue, the commit advisory never
  blocks, and a project without a ledger reports zero open entries.
- `skeleton.install()` only copies the ledger when it is absent; `--force` no longer overwrites
  an existing ledger (append-only data preserved).
- The state/quality-gate readers tolerate missing, legacy and malformed ledgers.
- The consistency fix is one `stdin=subprocess.DEVNULL` argument and a test count.

A revert restores the pre-E-108 behaviour (no ledger install, no digest entry, no audit line)
without touching project data.

## Known Risks

1. **Format ownership is split.** The reader now tolerates every shipped writer form
   (`### DW-NNN`, flat `- source_spec:`, legacy `## Deferred from:` headings) through one
   parser, but the writers still emit their own shapes; canonicalization remains
   `bmad-loop-sweep --migrate`'s job. A writer that invents a new shape is invisible until the
   parser learns it.
2. **The commit advisory is warn-only by design.** Open deferrals are a normal project state;
   this release does not turn them into a gate.
3. **Installed-plugin lag.** This checkout is 0.2.23; the session's installed cache is 0.1.57.
   Target projects see the integration only after a release/reinstall.
4. **This repo's ledger is still legacy.** The digest reports `DW=0 (newest legacy)` until
   `bmad-loop-sweep --migrate` runs; the content is counted, but no `DW-NNN` ids exist yet.
5. **CHECK4 does not classify `proposed`.** A record opened with that word fails the classifier
   during its own gate measurement; open new records as `planned`. Recorded in the ledger.
6. **E-100 stays advisory-blocked.** E-112 scopes only the one-line invariant fix, not a
   re-measurement of the Hermit upstream bench.
