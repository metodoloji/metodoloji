# Implementation Readiness: IR-007 — Date a command completion to the code state it ran in (E-064)

- **Date:** 2026-10-17
- **Status:** READY
- **Research inputs:** E-064 (APPROVED + VERIFIED — the dating and its measurement); carries E-063, the measured baseline failure (command_silence_rate = 1.0 with the paired control failing by silence), and the doctrine of E-053/E-058/E-056 (date a decision to a code state, bound every read, a gate refuses while a view reports)
- **Design documents:**
  - PRD: none
  - UX Spec: none
  - Architecture Plan: none
- **Success criteria:**
  - A completed `command` stage whose tracked code state moved is delivered UNKNOWN naming both states — Metric: command_silence_rate; Source: `python scripts/bench/bench_workflow_evidence.py` (2 movement shapes × 3 read surfaces: a new commit and a dirty tracked edit); Target: 0.0
  - A completed `command` stage whose tracked code state is unchanged answers CURRENT — Metric: command_hold_rate; Source: the same bench (3 control trials); Target: 0.0, with `false_alarm_rate` 0.0 as the artefact control
  - A command is never STALE and never blocks an advance, and an oracle that cannot answer yields UNKNOWN with the reason — Verify: `python -m pytest bmad/tests/test_workflow.py -q -k "command or code_state"`
  - One bounded probe per read pass, shared across an inventory and lazy when nothing needs it — Verify: `python -m pytest bmad/tests/test_workflow.py -q -k inventory_read`
  - Non-functional: no new dependency beyond the code-state oracle the board plane already uses (git), offline and deterministic — Verify: `python -m pytest -q` plus the bench, whose command bucket refuses to run without git rather than skipping silently
- **Instrumentation gaps:**
  - the probe's bound is DECLARED (a 5 s timeout and one call per pass); the bench scores the verdict, not the oracle's wall-clock, so a pathological repository's worst case is asserted rather than timed.
- **Technical dependencies:**
  - APIs: `git status --porcelain=v2 --branch` (the code-state oracle the board plane dates its own decisions to), `hashlib.sha256` (stdlib)
  - Libraries: none
  - Infrastructure: none new; the kernel still owns its storage under `.metodoloji/workflow/`
  - External services: none
- **Risk assessment:**
  - Risk 1: the dated verdict is noisier than silence → Mitigation: an unchanged code state answers CURRENT, so the verdict is informative rather than a permanent disclaimer; the paired control measures exactly that and fails an "always UNKNOWN" non-fix
  - Risk 2: a subprocess on the session edge → Mitigation: one probe per read pass, shared across the inventory, lazy when no command witness exists, and a declared timeout with a fail-open answer
  - Risk 3: the fingerprint silently over-claims (untracked files sit outside it) → Mitigation: every reason string says "tracked", and the known gap records that no fixture pins an untracked-file change
  - Risk 4: an existing run's command completions (recorded before dating) start reporting UNKNOWN → Mitigation: UNKNOWN never blocks, and the reason names the remedy (`re-complete the stage to date it`) — the same non-blocking shape E-056 gave legacy artefact completions
- **Gaps:**
  - the kernel does not re-execute a command to re-date it (a command has effects); re-establishing a moved verdict stays manual (`complete --force` after a re-run)
  - untracked-file changes are outside the fingerprint
  - a project that is not a git work tree can never answer CURRENT for a command completion — honest, and the price of having no oracle
- **Decision:** READY — the research input is approved and verified (E-064, APPROVED + VERIFIED); the closure is mechanical and offline
- **Next step:** proceed to sprint planning
