# Implementation Readiness: IR-008 — Deliver a run's declared artifact only inside its own project (E-067)

- **Date:** 2026-10-17
- **Status:** READY
- **Research inputs:** E-067 (APPROVED + VERIFIED — the containment and its measurement); carries E-066, the measured baseline failure (artifact_field_escape_rate = 1.0 with artifact_field_accepted_rate = 1.0 and a clean control), and the doctrine of E-060/E-062 (a run's evidence and its spec are claims about its OWN project) and E-058 (a gate refuses while a view reports)
- **Design documents:**
  - PRD: none
  - UX Spec: none
  - Architecture Plan: none
- **Success criteria:**
  - An out-of-root declared `artifact` is not delivered as the run's tracking location — `status.artifact` is None with a note naming what the spec declares, and the session advisory names it as outside instead of saying `tracked in <path>` — Metric: artifact_field_escape_rate; Source: `python scripts/bench/bench_workflow_evidence.py` (3 spellings × 2 surfaces); Target: 0.0
  - `create` refuses a spec whose declared `artifact` resolves outside the project root, naming the cause — Metric: artifact_field_accepted_rate; Source: the same bench (3 gate trials); Target: 0.0
  - An in-root declared `artifact` is still delivered verbatim by both surfaces — Metric: artifact_field_control_rate; Source: the same bench (2 control trials); Target: 0.0, with `false_alarm_rate` 0.0 as the artefact control
  - The containment is the shared `paths.outside` implementation, not a second opinion — Verify: `python -m pytest bmad/tests/test_workflow.py -q -k "declared_artifact or artifact_field"`
  - Non-functional: no new dependency, no new read on the session edge (the check is a string comparison and two `realpath` calls) — Verify: `python -m pytest -q` plus the bench, whose earlier buckets are re-measured in the same run
- **Instrumentation gaps:**
  - the bench scores what the surfaces DELIVER, not what an agent does with the path; the advisory detector matches the rendered sentence, so a differently-worded leak of the same path would evade it.
- **Technical dependencies:**
  - APIs: `os.path.realpath` / `os.path.commonpath` (stdlib, already wrapped by `bmad/workflow/paths.py`)
  - Libraries: none
  - Infrastructure: none new
  - External services: none
- **Risk assessment:**
  - Risk 1: the containment over-refuses and hides a legitimate durable pointer → Mitigation: an in-root `artifact` is delivered unchanged, pinned by the paired control that runs on both trees
  - Risk 2: an older tree's spec keeps its outside pointer and the run becomes unusable → Mitigation: the read side REPORTS (the run still works), the note names the remedy, and only the write path refuses to plant a new one
  - Risk 3: the new `artifact_note` key confuses a consumer that only knows `artifact` → Mitigation: `artifact` keeps its type (string or null) and its meaning (the pointer the surface can stand behind); the note is additive
- **Gaps:**
  - a declared artifact that does not exist yet is still delivered (ownership, not existence, is the boundary)
  - the kernel does not rewrite a saved spec — an outside pointer is reported, not fixed
- **Decision:** READY — the research input is approved and verified (E-067, APPROVED + VERIFIED); the closure is mechanical and offline
- **Next step:** proceed to sprint planning
