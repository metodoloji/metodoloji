# Implementation Readiness: IR-006 — Resolve a run's spec only from inside its own project (E-062)

- **Date:** 2026-10-17
- **Status:** READY
- **Research inputs:** E-062 (APPROVED + VERIFIED — the storage-plane containment and its measurement); carries E-061, the measured baseline failure (storage_escape_rate = 0.8333 on the restored pre-fix resolution), and the doctrine of E-008/E-060/E-056 (one sanitizer, one containment boundary, one implementation)
- **Design documents:**
  - PRD: none
  - UX Spec: none
  - Architecture Plan: none
- **Success criteria:**
  - A crafted slug that walks out of the specs dir resolves the run's OWN spec — Metric: storage_escape_rate; Source: `python scripts/bench/bench_workflow_evidence.py` (2 addressings × 3 read surfaces: the slug traversal and a stored `spec_file` naming an outside file); Target: 0.0
  - A state whose recorded `spec_file` points outside the root is not read (the run reports "no spec", and `complete` says so) — Verify: `python -m pytest bmad/tests/test_workflow.py -q -k "storage or sanitized or crafted"`
  - A legitimate run keeps resolving its own spec, from both candidates — Metric: storage_control_rate; Source: the same bench (3 control trials); Target: 0.0, and `false_alarm_rate` 0.0 as the paired evidence control
  - One sanitizer builds every filename from a slug, and one containment implementation serves both planes — Verify: `python -m pytest bmad/tests/test_workflow.py -q -k "containment_is_one_implementation or spec_path_is_built_from_the_sanitized_slug"`
  - Non-functional: no new dependency, offline and deterministic, fail-open preserved (an unresolvable spec is `{}`, never an exception) — Verify: `python -m pytest -q` plus the bench, both stdlib-only
- **Instrumentation gaps:**
  - "the spec came from outside" is inferred from what the surfaces DELIVER (a stage title, a computed next stage, an inventory entry), not from instrumenting which file was opened.
- **Technical dependencies:**
  - APIs: `os.path.realpath` / `os.path.commonpath` (stdlib)
  - Libraries: none
  - Infrastructure: none new; storage stays under `.metodoloji/workflow/`
  - External services: none
- **Risk assessment:**
  - Risk 1: sanitizing the slug changes the name of an existing run's spec file → Mitigation: `save_spec` writes through the SAME sanitizer, so the file a run's slug resolves to is the file the kernel wrote; the state's `spec_file` is the recorded fallback and stays confined-but-unchanged
  - Risk 2: containment makes a legitimate spec unreadable → Mitigation: the check is `realpath`-based on both sides, so a normal in-root file is unaffected, and the paired control measures exactly this failure mode at 0.0
  - Risk 3: a second containment implementation drifts from the first → Mitigation: `bmad/workflow/paths.py` holds the only copy, `evidence` re-exports it, and a test asserts the identity (`evidence.root_of is paths.root_of`)
  - Risk 4: a confined `spec_file` leaves a run reading as spec-less → Mitigation: that is the honest answer and an existing refusal path (`spec for '<slug>' is missing — cannot advance`); `UNKNOWN`/missing never silently advances
- **Gaps:**
  - the spec's `artifact` (documentation-output) field is still ungoverned by containment — its own record
  - a specs directory that is itself a symlink out of the root is refused by the same check but not fixture-covered (symlink creation is privileged on some hosts)
  - the read surfaces report a confined spec as "no spec" rather than naming the containment — a surface-contract change this record does not make
- **Decision:** READY — the research input is approved and verified (E-062, APPROVED + VERIFIED); the closure is mechanical and offline
- **Next step:** proceed to sprint planning

## Notes

- Plugin internals: the containment governs the kernel's own storage resolution (the spec a run is read against), not a product surface.
- The rule is a SHIPPED POLICY: a run's workflow definition is a claim about the project the run lives in, so the kernel does not need a setting to decide where it may read it from.
