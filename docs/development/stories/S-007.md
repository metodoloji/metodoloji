## User Story

**As a** maintainer of the metodoloji plugin
**I want** a completed command stage to say whether the tracked code state it was run in still holds
**So that** a green test suite recorded long ago is never delivered as if it had just passed

## Notes / Tracking

### Blockers
- none

### Progress Updates
- 2026-10-17: E-063 baseline measured (measured=1.0, control 1.0 by silence — the plane answered nothing at all on every surface) → E-064 (0.0 / 0.0, APPROVED + VERIFIED). Command completions are dated to the tracked code state; unchanged answers CURRENT, moved answers UNKNOWN naming both states, and the dating never blocks.

### Decisions
- 2026-10-17: the code state is the board plane's own notion (a commit plus the tracked working-tree state), so the kernel does not invent a second definition of "the code moved".
- 2026-10-17: a command is NEVER STALE. A look cannot falsify "this argv exited 0", so the plane reports what it can compare and refuses to pretend it can falsify; `complete` therefore never refuses an advance over an UNKNOWN command.
- 2026-10-17: the probe is ONE bounded call per read pass and lazy — the E-058 rule, applied to a subprocess: an inventory that classifies every run pays once, and an artifact-only project pays nothing.
- 2026-10-17: the fingerprint covers TRACKED files only, and every verdict string says "tracked" out loud rather than letting the word "code state" over-claim.
- 2026-10-17: the existing test that asserted "a command witness is None" was reversed by this story (it encoded rule 5's old doctrine); it now pins the dated witness instead. The reason is recorded in QR-022.
