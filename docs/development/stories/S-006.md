## User Story

**As a** maintainer of the metodoloji plugin
**I want** the kernel to resolve a run's workflow definition only from inside that run's project
**So that** a slug or a recorded `spec_file` can never make the plane read a file the run does not own and adopt it as the run's definition

---

## Acceptance Criteria

> For the story to count as "done", all criteria must be met

- [AC-001] **Given** a slug that walks out of the specs directory **When** any read surface resolves the run's spec **Then** it delivers the run's OWN definition (its own titles, its own next stage, its own evidence kinds) — never the outside file
  - Experiment: E-062
  - Type: agent-verifiable
  - Measured: true
  - Verify: python scripts/bench/bench_workflow_evidence.py
- [AC-002] **Given** a state whose recorded `spec_file` points outside the project root **When** the run is read **Then** nothing outside is opened: the spec resolves as missing, and `complete` refuses with the existing "spec … is missing" message
  - Experiment: E-062
  - Type: agent-verifiable
  - Measured: true
  - Verify: python -m pytest bmad/tests/test_workflow.py -q -k "stored_spec_file or in_root_spec"
- [AC-003] **Given** a legitimate run (in-root spec, matching slug) **When** it is read **Then** its own spec still resolves — from the slug-named file or from the recorded `spec_file` — with no false refusal
  - Experiment: E-062
  - Type: agent-verifiable
  - Measured: true
  - Verify: python scripts/bench/bench_workflow_evidence.py
- [AC-004] **Given** the two planes' containment boundary **When** either one asks whether a path is inside the project **Then** both call one implementation, and every filename built from a slug goes through one sanitizer
  - Experiment: E-062
  - Type: agent-verifiable
  - Measured: true
  - Verify: python -m pytest bmad/tests/test_workflow.py -q -k "containment_is_one_implementation or spec_path_is_built_from_the_sanitized_slug"
