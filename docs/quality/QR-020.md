## Findings

- **Finding 1 (design, accepted in review):** containment lives in the ONE matcher, not in spec validation or per caller. That keeps a stored witness — written by an older tree or edited by hand — under the same rule as a freshly declared path, and it keeps the completion refusal and the read verdict from drifting into two opinions about what "outside" means. It is also why the bench can force-complete an out-of-root stage to probe the read surfaces: the READ side must be safe on its own.
- **Finding 2 (asymmetry, deliberate):** the gate refuses, the view reports. A gate answers "may this advance?" (no, with the cause named); a view answers "is this still true?" (cannot be established). `UNKNOWN` never blocks an advance and never appears in `stale_evidence`, which is what keeps the containment from turning an unreadable path into a false emergency.
- **Finding 3 (fixture integrity, resolved in review):** the bench's baseline mode SIMULATES the pre-fix behaviour for the gate bucket (no such code path remains to call), while the fixed tree is measured through the real surfaces. The pre-fix behaviour itself was measured directly on the unfixed tree in E-059 (`escape_read_rate=1.0`, `escape_accepted_rate=1.0`), so the recorded red is a measurement, not a model.
- **Finding 4 (known gap, recorded):** containment governs the `artifact` evidence path only. The kernel's own storage paths (`store.py`), the spec's `artifact` output field and `command` evidence (`"this argv exited 0"` cannot be re-derived without re-running it) are separate claims, recorded in IR-005's Gaps, E-060's Known Gaps and plan §13. A TOCTOU race between resolution and read is likewise named and unclosed.
- **Finding 5 (report-only, expected):** the freshness plane now reports E-056 and E-058 as `[STALE]` ("file(s) in the claim's scope changed since it was recorded") because this iteration edited `bmad/workflow/evidence.py`, `bmad/tests/test_workflow.py` and the bench again. This is the documented report-only behaviour under `[hooks] freshness = warn`: neither claim is invalidated — the same bench re-measured both of them green in this iteration's own run (`stale_evidence_rate=0.0000 (0/12)`, `unbounded_read_rate=0.0000 (0/6)`), and neither was measured on a tree it does not describe (unlike E-053, which needed the `Re-Measured-By: E-054` follow-up).
- **Finding 6 (pre-existing, not caused by this change):** `scripts/check-plugin.sh` still reports the same 11 `UNVERIFIABLE` records (E-024 … E-034) it reported before this work — the documented machine-local key contract. Audit §3b is green: every edited file sits inside an approved Code Scope, and E-059's REJECTED baseline is the deliberate red the gate requires.
