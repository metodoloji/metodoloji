## Documentary Checks (Manual Review)

### Code Review
- **Reviewer(s):** Acceptance Auditor, Edge Case Hunter (parallel adversarial layers), plus the guard and the commit gate as mechanical reviewers
- **Review date:** 2026-11-06
- **Comments (summary):**
  - §1 no longer compares bytes: it extracts the heading sequence and every table's header row, so a shipped template and a live ledger can finally be different files with the same shape. The failure message prints the differing structure lines instead of `files differ`.
  - §7 closes the loop the old §1 was standing in for: a placeholder in the live ledger is an error, and a template with no placeholder is an error. The two halves of the pair are now each checked for their own job.
  - The negative test grew a fifth stage that appends `[X items]` to the live copy and expects exit 1. A checker that cannot go red on the failure it names has not been tested.
  - **Review finding #1 (recorded, not fixed):** the structure extractor treats any line beginning with `#` as a heading, including the fenced `# TODO: …` example in the TODO Comment Standard. Both files must therefore keep that block identical. That is the standard's own text, so requiring it is defensible, but the check cannot tell a heading from a fenced comment; recorded in IR-016's Risk 3 rather than hidden.
  - **Review finding #2 (recorded, not fixed):** the `--broken` control is a re-implementation of the pre-fix *decision contract* inside the bench (byte identity, no placeholder check), not the pre-fix script executed from git. It is faithful for the seven samples it scores — byte identity rejects every differing pair and accepts the identical-shape pair, which is why the control lands at 0/7 — but it is a model, and E-116 says so in its Theory.
  - **Review finding #3 (scope, recorded):** `scripts/tests/test_check_techdebt.py` and the `scripts/check-plugin.sh` §6c note sit outside E-116's declared Code Scope. The test file is named in the record's Planned Tests; the comment correction rides along because it explained the retired byte-identity rule. Both are listed in IR-016's Instrumentation gaps and here.
  - **Review finding #4 (fixed in review, small):** the bench carried `TD-000` as a fixture id, which the real §6 scanned out of `scripts/bench/` and reported as a dangling reference. Changed to a recorded id (`TD-016`), so the shipped tree stays HEALTHY under its own checker.
