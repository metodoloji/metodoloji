## Findings

- **Finding 1 (why this looked finished, recorded because it is the lesson):** the read was already BOUNDED (E-058) and dated (E-064), so it was affordable — and affordability had been the plane's standard for three iterations. Necessity is a different question: a budget answers "can we pay?", and the lookup never needed to buy anything. The bench had no metric for work a surface does not need, which is why the gap survived a hardening that was explicitly about this very read.
- **Finding 2 (design, accepted in review):** the deletion is behaviour-preserving BY CONSTRUCTION, not by careful reimplementation: `store.list_slugs` lists exactly the files the inventory enumerated (one row per `*.state.json`), so the "0 / 1 / many" answer cannot drift. The corrupt-run case is pinned by a test rather than assumed, because that is the one place the inventory did something extra.
- **Finding 3 (placement, deliberate):** the rule moved from a CLI helper into the kernel (`engine.resolve_slug`). That is what makes it testable and benchable without spawning a process, and it keeps the read rules in one module — the CLI keeps a delegate purely so its refusal wording, exit codes and the existing CLI tests stay untouched.
- **Finding 4 (measurement honesty):** this bucket counts matcher calls, a RESOURCE count rather than a verdict, so the implementation cannot define its own expectation (the expectation is arithmetic: a name question needs zero artifact reads). The paired control is the load-bearing half — a resolver that answered "no single run" would score 0.0 here and break the CLI, and the control fails exactly that.
- **Finding 5 (pre-existing, not caused by this change):** `scripts/check-plugin.sh` still reports the same 11 `UNVERIFIABLE` records (E-024 … E-034) it reported before this work — the documented machine-local key contract. Audit §3b is green: every edited file sits inside an approved Code Scope; the earlier hardening records report `[STALE]` as report-only under `[hooks] freshness = warn`, and their own buckets were re-measured green in this iteration's run.
