## Findings

- **Finding 1 (measurement integrity, corrected in review):** the first baseline run recorded `storage_escape_rate=1.0`. Its detector looked the inventory row up by the RAW slug, so an absent row scored as a difference — and that masked a real finding: the inventory is immune to the slug addressing by construction, because it enumerates filenames and a sanitized filename carries no separator. The corrected detector (which also resolves the sanitized spelling) gives **0.8333**, E-061 was re-gated with that number and the reason recorded in its Known Gaps, and the immunity is now pinned by a test. A trial-scoring bug is part of the measurement, and it hid a fact the fixture was already producing.
- **Finding 2 (design, accepted in review):** the fix completes two rules instead of introducing one. The sanitizer is E-008's rule, extracted to `store.safe_slug`; the containment is E-060's boundary, moved to `bmad/workflow/paths.py` so both planes call one function (identity asserted by a test). That is why no behaviour the kernel itself writes changes: `save_spec` writes through the same sanitizer the read uses.
- **Finding 3 (asymmetry, deliberate):** a confined `spec_file` reads as "no spec" (`{}`) rather than gaining a bespoke refusal on the surfaces. The existing refusal path already names it on `complete` (`spec for '<slug>' is missing — cannot advance`), fail-open is preserved, and changing what `status`/`next`/`list` report for an unresolvable spec is a surface-contract change recorded as a follow-up instead of being smuggled into a containment fix.
- **Finding 4 (bench strength, improved in review):** `--baseline` no longer models the storage plane's red — it installs the pre-fix `load_spec` verbatim, so the recorded baseline is produced by the old resolution rather than asserted about it. The delivery and gate buckets keep their modelling, and the docstring says which is which.
- **Finding 5 (pre-existing, not caused by this change):** `scripts/check-plugin.sh` still reports the same 11 `UNVERIFIABLE` records (E-024 … E-034) it reported before this work — the documented machine-local key contract. Audit §3b is green: every edited file sits inside an approved Code Scope; E-056/E-058/E-060 report `[STALE]` as report-only under `[hooks] freshness = warn`, and their own buckets were re-measured green in this iteration's run.
