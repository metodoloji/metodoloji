## Experiment: E-128 — The unused verticals leave the tree

- **Date:** 2026-11-12
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The plugin shipped three module verticals - GDS (game), WDS (web design) and CIS (creative intelligence) - that were fully wired into the engine but never exercised in this repository: zero records, zero run keys, zero on-repo sessions. Keeping them cost 58 skills, 56 customization TOMLs, ~7 MB of bodies, two parallel runtimes (WDS memory/sync, the Node.js bmad/wds/scripts toolchain) and four separate repair commits on WDS alone. The removal is complete only if no half-removal survives: a dangling manifest row, a catalog row, a config section or an engine prefix table entry would route a user into a skill that no longer ships.
- **Hypothesis:** H-128: "vertical_removal_accuracy == 1.0"
- **Measurement Metrics:** vertical_removal_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped tree at this commit. Procedure: scripts/bench/bench_vertical_removal.py runs twelve probes over the closed population - skill directories, tool skills, customization TOMLs, module data, the skill manifest, the help catalog, bmad/config.toml, the engine registries (blackboard_chain.py, blackboard_handoff.py, mirror.py), the handoff lint, and the shipped skill-count claims in every document and manifest. Control: --broken overlays one phantom vertical skill (skills/gds-gdd/SKILL.md) so the bench must fail the same claim; a module-level guard keeps the phantom out of the real run. Reproducibility: stdlib only, deterministic, no network.
