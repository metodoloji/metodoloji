## Experiment: E-139 — The deferred-work ledger is correct and stable end to end

- **Date:** 2026-11-13
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The ledger had a format document, a template, a parser and three writers, and the four disagreed. The parser counted legacy bullets to EOF and reported only canonical status:open entries, so nine real deferred findings read as DW=0 in the orient digest — the number a reader acts on said 'nothing to do'. The writers were worse: bmad-quick-dev and bmad-dev-auto emitted '- source_spec: ...' bullets that no version of the format ever defined, and bmad-code-review emitted a '## Deferred from:' heading with free-form bullets, so every new deferral landed as un-migrated legacy content and the ledger could never become canonical. The remedy text on three shipped surfaces named bmad-loop-sweep, a skill removed in E-138, leaving an instruction with no mechanism. And the migration path itself had no tool: converting the nine legacy items was a hand edit. A ledger is stable when four things hold: every writer emits the same shape, the parser counts the same thing every surface reports, a mechanical path converts history without losing text, and the conversion is idempotent.
- **Hypothesis:** H-139: "deferred_work_integration_accuracy == 1.0"
- **Measurement Metrics:** deferred_work_integration_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped tree at this commit. Each runs the shipped surface against a fixture tree; the CLI checks call the real module. Control: --broken runs the pre-fix surfaces materialised from the pinned pre-E-108 revision and asserts the CLI's absence, so the bench must fail the same claim. Two unit suites pin the properties the bench cannot see: hooks/engine/tests/test_deferred_work.py (13 parser cases) and scripts/tests/test_deferred_work_cli.py (18 CLI cases, including losslessness and idempotence).
