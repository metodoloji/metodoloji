## Experiment: E-101 — A workflow skill can be trained as an artifact, not edited by hand

- **Date:** 02.11.2026
- **Status:** completed
- **Theory:** E-097/E-098/E-099 built an optimization kernel that treats a skill document as the parameter and only promotes a candidate through a held-out, paired gate. Every measurement of that kernel so far used a synthetic fixture (`cases.jsonl` of lookup questions) and the `ScriptedRunner`, which scores an artifact by token coverage — a contract check for the optimizer, not a measure of a skill. The project's own `bmad-research-experiment` skill is the first real subject: it is a workflow document whose rules are already falsifiable, because `evals/cases.json` grades an answer with deterministic substring checks ("refuses to approve without a measurement", "recommends --dry-run"). That makes the skill trainable without inventing a new metric: if the judge cannot separate a compliant answer from the answer the skill exists to prevent, no amount of training means anything. The theory under test is that the same kernel, pointed at `SKILL.md` with those checks as the judge, measures the document itself — so a bench over the judge is the gate that must hold before a single training step is spent.
- **Hypothesis:** H-101: "training_accuracy >= 0.90"
- **Measurement Metrics:** training_accuracy >= 0.90
- **Experiment Design:** Measure `scripts/bench/bench_skill_training.py`, which imports the judge from `skills/bmad-research-experiment/evals/skill_runner.py` — the same function the optimization kernel calls per rollout — and judges every case in `evals/training-cases.jsonl` twice: once on the compliant answer (`good`, must pass) and once on the answer the skill forbids (`bad`, must fail). 14 cases × 2 answers = 28 independent verdicts; a verdict is `ok` when the judge's decision equals the expected one. The case set covers the skill's ten integrity rules and its gate mechanics: approval without measurement, record-before-measurement, an unmeasurable hypothesis, `--dry-run` versus a deciding run, `--control` falsifiability, per-sample evidence, threshold editing after rejection, McNemar for comparisons, Wilcoxon for continuous comparisons, census for exact-zero claims, mandatory Lineage, one-decision-per-record, `--verify` before code, and the blackboard close-out. The control (`--broken`) substitutes a judge that accepts everything: the `good` half still passes and the `bad` half now passes too, so the same assertions run against the failure mode the bench exists to catch. Deterministic, offline, stdlib only; the bench writes one JSON object per verdict.
- **Sample Size n:** 28 verdicts (14 cases × 2 answers), recomputed by the gate from the sample file
- **Code Scope:** skills/bmad-research-experiment/SKILL.md, skills/bmad-research-experiment/optimization.toml, skills/bmad-research-experiment/evals/training-cases.jsonl, skills/bmad-research-experiment/evals/skill_runner.py, skills/bmad-research-experiment/evals/skill_proposer.py, scripts/bench/bench_skill_training.py, docs/experiments/E-101.md, docs/optimization/skill-training.md

- **Control Command:** python scripts/bench/bench_skill_training.py --broken
