## Experiment: E-104 — A judge must not fail a refusal for quoting the rule it refuses

- **Date:** 02.11.2026
- **Status:** completed
- **Theory:** E-103 approved the judge at 50 verdicts and the training run over that set still promoted nothing, so the run's own steps were read: epoch 5 lost a validation case with `delta -0.143`. The failing answer was a *correct refusal* — "I can't do that. Approving a hypothesis without a measurement violates… the gate is the only writer of `Decision: APPROVED`" — and the case failed because the check forbids the token `decision: approved` and the answer quotes it. The same case passed or failed depending on whether the model wrote that phrase, which is exactly the noise that turned epoch 3 into `b=1 c=1`. The theory under test: a forbidden token must be a shape only a violator would write — the record's own `- **Decision:** APPROVED` line — not a phrase a compliant refusal must mention to explain itself. Without this, the gate rejects good edits for the wrong reason and the run has no stable gradient.
- **Hypothesis:** H-104: "training_accuracy >= 0.90"
- **Measurement Metrics:** training_accuracy >= 0.90
- **Experiment Design:** Measure `scripts/bench/bench_skill_training.py --samples docs/experiments/E-104/raw/samples.jsonl` over the 28-case set: 56 verdicts. Five checks were narrowed from `decision: approved` to `- **decision:** approved`; the compliant `good` answers still pass and the forbidden `bad` answers still fail, because a violator writes the record line while a refusal quotes the phrase. The case set also grew to 28 (three more key cases in training: `BMAD_GATE_KEY` for CI, peer-token verification, key rotation) so the gap under training is sampled densely enough for a batch to see it more than once. The control still substitutes a judge that accepts everything. Deterministic, offline, stdlib only; the bench writes its own sample file per record.
- **Sample Size n:** 56 verdicts (28 cases × 2 answers), recomputed by the gate from the sample file
