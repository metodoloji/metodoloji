## Experiment: E-082 — Malformed or unreadable registries are reported, not fatal

- **Date:** 29.10.2026
- **Status:** completed
- **Theory:** E-075 through E-081 made external-context discovery shared, deterministic and version-aware on the surfaces it can inspect. The finder's failure surface stayed narrower than its call sites: it reports a missing registry, an unsafe (escaping) registry and oversized entries, but a registry path that is a regular file, a broken link, or a directory that cannot be listed raises `NotADirectoryError`/`PermissionError` out of `find_contexts()`. An individual `context.md` that cannot be read raises after its size check passed. Every workflow stage that runs the finder (research, architecture, readiness, dev-story, code review, production readiness) then gets a traceback instead of a context result, so a corrupt working tree breaks the stage rather than degrading it to "no registered context".
- **Hypothesis:** H-082: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the current consistency bench and its `--broken` seeded-defect control. Add behavior probes for a registry path that is a regular file, a broken registry symlink, an oversized entry beside a readable sibling, and (where the platform can make a file unreadable) an unreadable entry beside a readable sibling. Each probe must yield a result object with an attributable status or warning, and the CLI must still exit 0 with JSON. Extend the consistency contract with those probes and seed removal of the non-directory guard in broken mode. Reproducibility is local and offline.
