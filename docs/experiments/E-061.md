## Experiment: E-061 — The storage plane resolves a run's spec from outside the project root

- **Date:** 17.10.2026
- **Status:** REJECTED
- **Theory:** E-060 confined the ARTIFACT read to the project root. The kernel's own storage plane was left unconfined, and it is addressed by two strings that are not filenames until the kernel makes them one. (1) A SLUG. `store.state_path` sanitizes the slug (`[alnum._-]`, everything else `_`) — that is E-008's fix, written for the state file — but `store.load_spec` joins the RAW slug into the specs dir, so a slug like `../../../../loaded` resolves to a JSON file beside the project root, and the kernel reads it as the run's workflow definition. (2) A stored `spec_file`. `load_spec` falls back to `state["spec_file"]` and opens it wherever it points; a state left by an older tree, or edited by hand — the same legitimacy E-060 accepted for a stored witness — makes the fallback an out-of-root read. Both are the E-008 seam reopened one filename over: the sanitizer exists, but the spec path was never routed through it, and nothing confines the stored path. The consequence is not a cosmetic read: the spec decides which stages exist, what evidence they demand, and where the run goes next, so an outside spec silently replaces the run's own definition on every read surface (and at `complete` time).
- **Hypothesis:** H-061: "storage_escape_rate <= 0.0"
- **Measurement Metrics:** storage_escape_rate <= 0.0 (with `storage_control_rate <= 0.0` carried as the paired false-refusal control, parsed from the same bench output)
- **Experiment Design:** Inputs — `scripts/bench/bench_workflow_evidence.py`, extended with a fourth bucket beside the delivery, read-budget and artifact-escape ones. Storage bucket: 2 addressings x 3 read surfaces (6 trials), with an outside spec planted BESIDE the trial's project root and the run's own state produced legitimately first (analyze completed on artifact evidence, brief completed as a note stage), so the trial isolates SPEC RESOLUTION — the artifact, the witness and the completed set are identical whatever the addressing does. The outside spec declares the SAME stage ids with a different title (`MAP` / `OUTSIDE MAP`), a different next stage (`done` / `outside-done`) and a different evidence KIND for the unwitnessed stage (note / artifact), so a leak is observable on all three surfaces: the peek shows the outside stage's title, the computed next step names the outside-only stage, and the inventory classifies the unwitnessed completion only when the spec in force calls it an artifact stage (1 entry owned, 2 leaked). The two addressings are a slug that walks out of the specs dir and a stored `spec_file` naming the outside file. The two are not equally reachable, and the measurement says so: the INVENTORY enumerates the files it finds, so it addresses a run by its sanitized filename — a name that carries no separator and therefore cannot traverse — which makes the slug addressing observable on `status` and `next` only, while the stored `spec_file` is observable on all three. Control: an in-root run with a matching slug (3 trials) must deliver its OWN shape on all three surfaces — the failure mode of a containment applied too eagerly — and must stay 0.0 on BOTH trees, because that failure is not this experiment's hypothesis. Procedure — `python scripts/bench/bench_workflow_evidence.py --baseline`, which restores the pre-fix `load_spec` verbatim rather than modelling it, so the recorded red is the red the old resolution produces (the fixed tree is measured by the same bench without the flag).
- **Sample Size n:** 6 (storage escape trials; the control's 3 trials are reported separately as `storage_control_rate` and the gate parses the denominators from the bench output)
- **Code Scope:** scripts/bench/bench_workflow_evidence.py, docs/experiments/E-061.md
- **Lineage:** E-060 (the plane this measures one level down: that hardening confined what the run READS as evidence, and its Known Gaps recorded "the kernel's own storage paths (`store.py`) and the spec's `artifact` output field are not governed by this claim" — this is that record, opened), E-008 (the seam itself, verbatim: `store._state_path` sanitized the slug while a second path built it raw — the same disagreement, one filename over, surviving that fix), E-009 (the file seam beside it: a malformed file from outside must end in a decision, and here the file is read as a definition), E-056/E-058 (the plane's read surfaces, which now deliver this leaked definition to the operator, the session edge and the completion gate), E-055, E-057 and E-059 (the same bench's earlier baselines, all REJECTED on a scope this draft re-treads — the bucket-plus-control pattern and the "a surface that carries no verdict delivers a false success" lesson are theirs, and E-059 is the nearest sibling: it measured a READ reaching outside the root through a path the run did not own, which is what this bucket measures one string over), E-037 (the class: an artifact asserting a fact nobody measured — the plane asserted "this run's spec" about a file it never checked it owned)
