## Experiment: E-183 — The gate must see every verb that writes a code path

- **Date:** 2026-11-17
- **Status:** completed
- **Record Kind:** experiment
- **Theory:** The guard's write surface is a table of command words in hooks/engine/modules/bash_targets.py: each branch names the destination its verb writes, and guard() gates only the targets that table yields. Probing the shipped extractor with seventeen write forms against a gated code path (src/zzz_probe.py) on 2026-11-17 found three verbs that name no target at all: rsync copies its destination (last operand), ln creates or replaces the link name (last operand), and git restore rewrites the working tree exactly like git checkout -- (which is covered, but only because that branch requires the -- separator). All three reached guard() as read-only commands and were allowed, while the same intent spelled with cp, mv, install or git checkout -- is denied. The omissions are not stylistic: they are a fail-open write surface on the same gated path the other verbs close.
- **Hypothesis:** H-183: "write_surface_accuracy == 1.0"
- **Measurement Metrics:** write_surface_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped hooks/engine/modules/bash_targets.py and the pre-E-183 tree at git 89db961. Procedure: scripts/bench/bench_bash_write_surface.py drives guard() in its own process over twelve commands against a gated code path (src/zzz_probe.py) in this repository, half of them writes that must be denied and half reads or out-of-tree destinations that must be allowed: rsync destination, prefixed rsync, rsync whose gated path is only the SOURCE, ln destination, ln whose destination is outside the tree, git restore, git restore with a redirect, cp, mv, touch, a directory listing and git status. Control: --broken runs the same twelve probes against 89db961, where rsync, ln and git restore name no target. Reproducibility: stdlib only, offline, deterministic (no clock or network dependence; every probe is a fixed string and the expected verdict is stated once).
