## Experiment: E-031 — The documented [HYPOTHESIS] opt-out must hold at commit time too, not only at write time

- **Date:** 12.10.2026
- **Status:** completed
- **Theory:** A real Claude Code session (muse-spark-1.3-contributor-free,
  2026-10-1x) ran `git commit` and got stuck for ~16 minutes: it kept repositioning
  the working tree and finally reasoned about "the methodology's approved
  hypothesis exception for S-002" while hunting for the hook that blocked it.
  Reading the code shows the exception is honored by exactly one of the two
  gates. `_validate_story_metadata` (write time) treats `[HYPOTHESIS]` as the
  documented opt-out — "The [HYPOTHESIS] tag is an explicit opt-out from the
  Experiment field requirement" (`docs/bmad/research-methodology.md` §"Hypothesis",
  bridge §1) — and passes a story whose ACs are all `[HYPOTHESIS]` with
  `Experiment: —`. `_orphan_story_reason` (commit time, via
  `_check_all_stories_quality`) instead read the raw text, filtered `Experiment: —`
  out, and declared the same story an ORPHAN, so `git commit` denied it with
  "Story experiment validation failed for S-002.md: Story has no experiment
  reference …". That is the E-018..E-030 class once more — a guarantee exists
  only where its wiring is — here with the two gates reading the same fact two
  different ways (one parser, one contract, two verdicts). The contradiction is
  measured, not inferred: the SAME story content yields `_validate_story_metadata
  → (True, '')` and `_orphan_story_reason → 'Story has no experiment reference …'
  → _check_all_stories_quality → deny`. The fix makes the commit-time probe read
  the AC metadata through the SAME parser the write-time validator uses
  (`_parse_ac_metadata`) and honour the `[HYPOTHESIS]` opt-out, so a story is an
  orphan only when some AC is neither experiment-linked nor a hypothesis. The
  control is preserved: an AC with a bare `Experiment: —` and no tag is still an
  orphan, and the legacy text probe still runs when no AC metadata parses.
- **Hypothesis:** H-031: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-031 claim (it drives
  `_validate_story_metadata` and `_orphan_story_reason` on an all-hypothesis
  story and demands agreement plus no orphan denial, drives the real
  `_check_all_stories_quality` commit check on the same story, and demands the
  orphan rule still fires on the non-hypothesis control), plus the regression

  check pins that the code under test still passes the full suite, which now
  includes the E-031 tests (`test_hypothesis_story_is_not_an_orphan`,
  `test_unlinked_non_hypothesis_ac_is_still_an_orphan`,
  `test_write_and_commit_gates_agree_on_a_hypothesis_story`). The probe is
  falsifiable by construction: dropping the `is_hypothesis` clause from
