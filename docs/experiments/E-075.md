## Experiment: E-075 — External context registry is installed and consumed from the current project tree

- **Date:** 28.10.2026
- **Status:** completed
- **Theory:** The prior iteration documented an external-technology registry and placed lookup rules in selected skills, but the checked-in behavior exposes two risks: repository init owns its directory/template contract in `bmad/scripts/skeleton.py`, while skills are instruction-driven and may search a README that does not enumerate entries. E-047 measures agreement across init declarations; E-050 measures whether init-copied docs promise paths the installer creates; generic skeleton tests exercise every declared pair and directory. This iteration makes the registry a real installed project artifact and clarifies discovery from `*/context.md`, while retaining the human index only for navigation. The measured claim is that the methodology's existing self-consistency suite remains at least 90% accurate with a falsifiable control.
- **Hypothesis:** H-075: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Run `python scripts/bench/bench_consistency.py` against the current working tree; it derives repository consistency checks and prints the measured ratio. The E-047/E-050 rules plus the generic skeleton test paths provide direct evidence for the init/template behavior; the workflow instruction paths are checked for consistent registry discovery and version handling during this iteration. Reproducibility is offline and deterministic on a fixed tree.
