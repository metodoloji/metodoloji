## Experiment: E-019 — The bridge §N.N drift audit must read every surface that cites the bridge, not only custom/*.toml

- **Date:** 10.10.2026
- **Status:** completed
- **Theory:** `check-custom.sh` §7 exists for one job: a live file that cites
  `dev-skill-to-methodology-bridge.md` must not point at a section the bridge
  does not contain. It listed exactly one surface — `custom/*.toml` — so the
  other shipped surfaces that name the bridge went unread. Reading the tree
  rather than the promise shows the seam is real: the bridge is also cited by
  `skills/*/SKILL.md` (three QR feeders) and by `commands/init.md`; §7 never
  opens them. And the drift is not hypothetical — it is already present. Both
  review feeders claim they feed the QR under `bridge.md §1.1 and §3.1`, but
  the bridge document has no §1.1 (its only top-level section is `## §1
  General Context`); the 16 sibling feeder TOMLs that quote the same contract
  say `§1 and §3.1`. So a live SKILL.md has been telling the agent to read a
  section that does not exist, and the audit whose entire purpose is to catch
  exactly that reported `checked bridge users: 33 / HEALTHY`. Root cause is the
  class E-002/E-017/E-018 named: the guard is only as wide as its hardcoded
  surface. The fix widens §7 to every bridge-citing surface (custom overrides,
  `skills/*/SKILL.md`, `commands/*.md`), repairs the one dangling reference,
  and pins both the invariant and §7's scope with a bench check so the audit
  cannot silently narrow back.
- **Hypothesis:** H-019: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-019 claim (it extracts
  the bridge's real section set from `docs/bmad/dev-skill-to-methodology-bridge.md`,
  walks every bridge-citing file across `custom/*.toml`, `skills/*/SKILL.md`
  and `commands/*.md`, and demands every `§N.N` / `section N.N` / `bolum N.N`
  reference resolves; it also pins that §7 still scans `skills/*/SKILL.md`),
  plus the regression tests by name. Control — the bench's own "pytest suite
  green (falsifier)" check pins that the code under test still passes the full
  suite, which now includes two new tests in
  `scripts/tests/test_selfcheck_scripts.py` (the bench check returns `None` on
  this tree; §7's SKILL.md scope is asserted directly). The probe is falsifiable
  by construction: reintroducing `§1.1` into
  `skills/bmad-review-edge-case-hunter/SKILL.md` turns the new bench check red
  (`§N.N not in bridge → 1.1`) and makes the widened §7 report
  `checked bridge users: 37 / MISS: … §N.N not in bridge → 1.1` where the old
  §7 reported `33 / HEALTHY`. Reproducibility — stdlib only, no network,
  deterministic: the check reads the tree and the bridge document as they are,
  and a fixed tree yields a fixed x/y; the measurement reports the tree as it
  is, independent of this record (E-001).
