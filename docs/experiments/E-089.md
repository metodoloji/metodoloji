## Experiment: E-089 — The external-context registry is one validated, versioned, generated surface

- **Date:** 30.10.2026
- **Status:** completed
- **Theory:** The external-context workflow grew two independent scripts and a hand-maintained README, and a full audit found 28 architecture defects (F-01…F-28) that no single instrument could see. The authoring CLI (`external-context.py`) and the finder (`find-external-contexts.py`) each carried their own copy of the field schema, slug rules, Turkish folding, ref comparison and path handling, so the two halves could disagree about the same file. `prepare` interpolated a Windows path straight into `re.sub` (F-01), statuses were an unversioned free string with no `stale`/`superseded`/`revalidating` distinction (F-02), `refresh` left a revalidated entry looking `reviewed` (F-03), `discard` deleted a reviewed entry with no `--force` (F-04), the README index was hand-edited and could drift from the folders (F-05), `check` had no warnings/strict split so CI could not fail on a stale registry (F-06), the finder scored template labels and stopwords as evidence (F-07/F-08), it returned drafts as registered context (F-09), ref matching mishandled ranges, bare minor lines and SHA prefixes (F-10), results carried no matched terms, snippet, status or freshness flags (F-11/F-12), and the registry had no migration path, no atomic writes, no advisory lock, no boundary guard, and no archive (F-13…F-28). The theory under test is that a single shared module owning schema, folding, ref semantics, freshness and safe writes — with one generated index and one strict audit — removes the disagreement, and that the consistency bench can detect each regression when it is re-seeded.
- **Hypothesis:** H-089: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the repository consistency bench and its `--broken` seeded-defect control. Consolidate the two CLIs onto `scripts/external_context_common.py` (schema version 2, field parsing, Turkish folding, semver/range/SHA ref matching, freshness and revalidation dates, atomic writes, advisory lock, project-boundary guard). Rewrite `external-context.py` around `prepare`, `finalize`, `check`, `refresh`, `discard`, `list`, `rebuild-index`, `migrate`; generate the README index between markers; split findings into errors and warnings with `--strict`; archive discarded entries under `.archive/` with `ARCHIVED.md`; require `--force` for any ever-reviewed entry. Rewrite `find-external-contexts.py` to score with field weights, IDF and stopword/template removal, report `matched_terms`, `snippet`, `status`, freshness and revalidation flags, and accept ranges, bare minors and SHA prefixes. Pin every behavior with unit tests, a golden retrieval fixture, and a bench contract plus a re-seeded defect per contract. Reproducibility is local, deterministic and offline; the finder accepts `--today` so freshness is not wall-clock dependent.
