## Experiment: E-083 — Template field labels are not searchable context content

- **Date:** 29.10.2026
- **Status:** completed
- **Theory:** E-075 through E-082 made external-context discovery shared and resilient, and the finder intentionally weighs identity fields (`slug`/heading, `Project relevance`, `Aliases`) above body mentions. The relevance values were never extracted, though: `relevance` is built from the whole metadata line, so the template's own labels ("Project relevance", "Aliases") are scored as content at relevance weight, and the complete file text — labels included — is also the fallback haystack. Every registered entry therefore matches queries that contain template vocabulary ("project", "relevance", "aliases", "analyzed", "revalidate") at weight 2, even when its values never mention the topic. As the registry grows, those boilerplate hits crowd out the entries that actually discuss the requested technology.
- **Hypothesis:** H-083: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the current consistency bench and its `--broken` seeded-defect control. Probe the finder with entries rendered from the shipped template: a query made only of field labels must return no entries, while the same entries must still match their title and their field values. Extract only field values for identity scoring and exclude metadata bullets from the fallback body. Extend the consistency contract with the label/value probes and seed the old whole-line extraction in broken mode. Reproducibility is local and offline.
- **Sample Size n:** measured from the bench output
