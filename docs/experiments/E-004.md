## Experiment: E-004 — Bind the gate decision to the claimed metric (multi-metric benches)

- **Date:** 07.10.2026
- **Status:** completed
- **Theory:** The gate's authority rests on rule "reality is mechanical": the
  decision must be bound to the metric the hypothesis claims, parsed from the
  measurement run's own output. Behavior probing shows `run_and_measure`
  selects the FIRST `metric_*` line in stdout. A bench that legitimately
  prints several metrics (or a decoy first line) therefore has its decision
  bound to whichever line came first — an approval computed over the wrong
  number, HMAC-signed and VERIFIED (the MISMATCH advisory fires only when the
  first line is NOT the claimed metric, and `--verify` turns it into
  ADVISORY-BLOCK, but the token still carries the wrong value). The steering
  belongs at the parse site: choose the line whose stem matches the claim.
- **Hypothesis:** H-004: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; the gate's pytest suite now covers the
  claimed-metric selection, same-stem conflict fail-closed, and distinct-stem
  tolerance. Control — the bench's own "pytest suite green (falsifier)" check
  pins that the code under test still passes the full suite. Reproducibility —
  stdlib only, no network, deterministic (a fixed tree yields a fixed x/y);
  the measurement reports the tree as it is, independent of this record.
