## Experiment: E-140 — The audit verifies once and parses each glob once

- **Date:** 2026-11-13
- **Status:** completed

- **Theory:** check-plugin.sh took 157 s on this corpus, which is why the commit gate outran the 10 s hook budget and every commit in this session needed a wrapper script. Two independent causes, both measurable. First, §3 verified each record in its own Python process and §3b verified the whole corpus again: 270 interpreter starts for 0.24 s of actual verification work, because verify() is pure file reading and HMAC. Second, the gate's scope matcher re-parsed every glob for every comparison: 1,184,988 parses of a few hundred distinct patterns, 95 s of §3b's 117 s. freshness.py already carried a memo for the second defect (E-132 measured 114,109 parses there); the gate's copy, which is what §3b and the guard actually call, never got it. Both fixes are safe by construction — a corpus pass calls the same verify(), and the glob parser is pure — but both are invisible when they regress, so each needs a falsifier that fails when the shortcut is deleted.
- **Hypothesis:** H-140: "audit_throughput_accuracy == 1.0"
- **Measurement Metrics:** audit_throughput_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped tree at this commit. Procedure: scripts/bench/bench_audit_throughput.py runs five checks — the corpus pass completes the whole corpus under a 10 s budget (measured 0.59 s), it agrees with a per-record --verify on a sample, each distinct glob parses at most twice across 320 comparisons, check-plugin.sh consumes the pass with no per-record spawn in its §3 loop, and the gate stays stdlib-only. Control: --broken runs the pre-fix shape (per-record verification, uncached matcher, no corpus pass) and must fail the same claim; it measured 0.40. Reproducibility: stdlib only, deterministic apart from the wall-clock budget, offline.
