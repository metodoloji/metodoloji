## Experiment: E-017 — A corrupt file must never take the decision path: the engine's config reader and the remaining check scripts

- **Date:** 09.10.2026
- **Status:** completed
- **Theory:** E-009 named the class and named the surfaces it left: "the gate
  (run_experiment.py) and the check scripts". E-016 closed the gate; this
  closes what was actually left, and the ordering turned out to matter. The
  engine's own config reader (`hooks/engine/modules/config.py`) sits on the
  **gate-mode decision path** — `hook_gate_mode()` is what decides whether the
  guard denies, warns, or is off — and both of its read sites caught only
  `OSError`, which a `UnicodeDecodeError` (a `ValueError`) is not. Behavior
  probes on a binary `custom/config.toml` show the consequence directly: the
  decision path RAISES instead of deciding. A crash there is not a crash — it
  is a hook that returns no decision, and a runner may read "no decision" as
  an allow. That is precisely the failure mode E-006 and E-007 were written to
  end, so the fix is judged by its direction, not merely by its silence: the
  defaults must still apply, leaving `code_guard = hard` (fail-CLOSED) on an
  unreadable config. Two more seams completed the survey. `_replay_events`
  opened the board's event log and caught `OSError`, but the decode error
  surfaces while ITERATING the file (inside `for line in f`), so a binary log
  escaped as a crash and took `read_board` and `chain_health` with it — the
  diagnostics path that exists to explain a problem. And
  `scripts/check-triggers.py`, an audit whose whole job is to report, read a
  skill file with no guard at all, so one corrupt `SKILL.md` crashed the audit
  and reported nothing (a runner that ignores the traceback sees success).
- **Hypothesis:** H-017: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-017 claim on all
  three seams (a binary `config.toml` must still yield `code_guard=hard` and
  `quality_gate=soft` with `_validate_hooks_config` reporting cleanly — the
  fail-closed direction, not merely no-crash; a binary snapshot + event log
  must fold to an empty board with `chain_health` still `ok`; and the trigger
  audit must name the unreadable file and exit 1), plus the regression tests
  by name. Control — the bench's own "pytest suite green (falsifier)" check
  pins that the code under test still passes the full suite, which now
  includes one test per seam. Reproducibility — stdlib only, no network,
  deterministic: each probe builds its own fixture in a temporary directory
  and restores the live config afterwards, and a fixed tree yields a fixed
  x/y; the measurement reports the tree as it is, independent of this record
  (E-001).

- **Known Gaps:** an undecodable event log folds to an EMPTY board rather than
  a partially-replayed one — the same all-or-nothing the malformed-line skip
  already implies — and `_replay_events` never writes that empty board back
  (the `any(...)` guard in `read_board` keeps a lost/undecodable log from
  wiping a snapshot), so the bytes stay the only copy. On an unreadable
  config the gate defaults win by design; that means a config corrupted into
  invalid UTF-8 silently stops honoring overrides until it is repaired —
  correct as a fail-closed direction, but no one is TOLD: a distinguishable
  "config unreadable" signal on the audit path would be better and is not in
  this record's scope. `_frontmatter` still has no guard of its own; the
  guard lives at its one call site in `main`, which is the only production
  caller today (a second caller would re-open the seam — hence the test). The
  other check scripts were not exhaustively probed for this class:
  `check-methodology.sh`/`check-plugin.sh`/`check-custom.sh` are shell and
  delegate their parsing to `awk`/`grep`/`diff`, and `bump-version.py` reads
  only the version-owned manifests inside the repo; none was driven with a
  binary payload here. `blackboard`'s remaining `open(..., encoding="utf-8")`
  sites sit behind the board lock and are covered through `_replay_events`/
  `_read_snapshot` only — an unwrapped reader added later would re-open the
  class without any test noticing.
