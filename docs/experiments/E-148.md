## Experiment: E-148 — The customization tree has one owner too

- **Date:** 2026-11-13
- **Status:** completed
- **Record Kind:** contract
- **Theory:** E-147 removed the six retired config paths and left the plugin with one config owner. The customization tree still had two: `custom/<skill>.toml` held every team override and `skills/<skill>/customize.toml` held the skill's own defaults, and only the merge made them one answer. That is the same duplicate-owner shape E-146/E-147 closed for the central config, one directory over — and it carried the same defect: because the skill lives inside the plugin, the resolver derived the project root from the skill's path and therefore always found the PLUGIN root, so a target project's `custom/` override was never read at all. Two layers were advertised and one of them was dead. The fold gives each skill one file: its team content merges into its own `customize.toml`, `custom/` leaves the tree, and the resolver is told which project to read instead of guessing.
- **Hypothesis:** H-148: "bridge_fold_accuracy == 1.0"
- **Measurement Metrics:** bridge_fold_accuracy == 1.0
- **Experiment Design:** Inputs: the plugin tree at this commit, a baseline fixture captured from the PRE-fold tree (`scripts/bench/fixtures/bridge-fold-baseline.json` — the resolver's full output for all 48 skills, plus the 42 skills that carried a team file), and the pre-fold resolver read from git commit a3a9891. Procedure: `scripts/bench/bench_bridge_fold.py` runs four checks — (1) the plugin ships no `custom/` tree, (2) all 48 skills resolve to exactly their pre-fold output, (3) each of the 42 team-bearing skills carries its former content in its own `customize.toml`, and (4) a project's `custom/<skill>.toml` actually reaches the resolver through `--project-root`. Control: `--broken` runs the pre-fold resolver from commit a3a9891 against the folded tree, so the control is the old reader rather than a paraphrase of it; it fails cases 1 and 4 and is reported non-discriminating on case 2 (the fold is value-preserving, so the old reader reproduces the values by construction). Reproducibility: stdlib only, deterministic apart from git availability, no network.
