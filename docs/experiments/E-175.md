## Experiment: E-175 — The chain speaks to the human

- **Date:** 2026-11-16
- **Status:** completed
- **Record Kind:** contract
- **Theory:** Measured 2026-11-16 on a real project using this plugin: every workflow surface was model-facing. SessionStart and Stop injected additionalContext, every CLI command printed JSON to the agent, and the audit hook returned additionalContext; the codebase contained no systemMessage at all. The person driving the session therefore saw nothing of the chain: a run advanced stage by stage, and the only human-readable view was raw JSON scrolling past in the transcript. The workflow skill said 'report to the user', but nothing enforced it, so it depended on the model remembering. The gap is structural, not a wording bug: the kernel had one channel and it was the model.
- **Hypothesis:** H-175: "workflow_visibility_accuracy == 1.0"
- **Measurement Metrics:** workflow_visibility_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped hook entry point (hooks/engine/main.py) driven as a subprocess with a JSON payload on stdin, exactly as the harness invokes it, against throwaway projects that do and do not hold a declared run. Procedure: scripts/bench/bench_workflow_visibility.py runs twelve probes. Control: --broken runs the same probes against the pre-fix tree at git ebc4ddf, where no hook sets systemMessage and no PreToolUse threshold asks. Reproducibility: stdlib only, offline, deterministic (fresh temp project per probe).
