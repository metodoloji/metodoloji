## Experiment: E-185 — git's own rename verb names its destination

- **Date:** 2026-11-20
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The guard gates what bash_targets names: a command word that yields no target is judged as a read. The table gated mv's destination operand, but under git it had no mv arm at all, so git mv docs/x.md src/a.py created a gated file while naming no target and reached guard() as a read (probe of the shipped extractor, 2026-11-20: four git mv spellings allowed while mv docs/x.md src/a.py is denied). This is the same fail-open class E-183 closed for rsync/ln/git restore and E-184 closed for flag-carried destinations and separator-less checkout.
- **Hypothesis:** H-185: "git_mv_target_accuracy == 1.0"
- **Measurement Metrics:** git_mv_target_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped hooks/engine/modules/bash_targets.py and the pre-E-185 tree at git 55c8608. Procedure: scripts/bench/bench_git_mv_target.py drives guard() in its own process over fifteen commands against a gated code path (src/zzz_probe.py): six git mv renames whose destination is gated (a rename into the path, a rename inside it, -f, -v, a trailing-slash directory, and the -- separator), three twins that already denied (mv, cp, git restore), and six invocations that must stay allowed (a dry run, --help, a bare verb, a one-operand usage error, a rename outside any code path, and a listing). Control: --broken runs the same fifteen probes against 55c8608, where git mv names no target. Reproducibility: stdlib only, offline, deterministic; every probe is a fixed string and its expected verdict is stated once.
