## Experiment: E-091 — The strict-audit test must not assume the day it runs

- **Date:** 31.10.2026
- **Status:** completed
- **Theory:** `test_check_strict_turns_warnings_into_failures` builds a complete entry dated `2026-10-30`, calls `finalize`, then rewrites the **first** revision row from `v0.31.0` to `v0.30.0` and expects `check --strict` to warn that the last revision row does not name the analyzed ref. That expectation silently depends on the calendar: on the day the fixture was written, `finalize` sees that the last row already records today's review and appends nothing, so the mutated first row is also the last. On any later day `finalize` appends a fresh `| <today> | v0.31.0 | reviewed |` row, which still names the analyzed ref, so the audit correctly reports no warning and the test fails. A test that passes only on its authoring date is not a regression guard — it is a scheduled failure that makes the suite red for a reason unrelated to the code.
- **Hypothesis:** H-091: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the repository consistency bench and its `--broken` seeded-defect control. Replace the hard-coded first-row rewrite with a search for the **last** revision row that names the analyzed ref, wherever `finalize` put it, and change only that row's ref; fail loudly if no such row exists so the fixture cannot drift silently. The audit behavior under test is unchanged: a last row that names a different ref than `Analyzed version/ref` must warn, and `--strict` must turn that warning into a failure. Reproducibility is local, deterministic and offline; the test no longer reads the wall clock.
- **Sample Size n:** measured from the bench output
- **Code Scope:** scripts/tests/test_external_context.py, docs/experiments/E-091.md
- **Lineage:** E-089 (schema-2 revision history and the strict audit this test pins), E-086 (refresh/review dates), E-087 (the revision row must name the analyzed ref) — this record inherits their date and revision-history contract and makes the guard independent of the day it runs.
- **Control Command:** python scripts/bench/bench_consistency.py --broken
