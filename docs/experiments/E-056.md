## Experiment: E-056 — Date every stage completion to the evidence that satisfied it, and re-derive it on every read

- **Date:** 17.10.2026
- **Status:** completed
- **Theory:** The freshness plane (E-053) dates a BOARD claim to the code state it was written against and derives `CURRENT | STALE | UNKNOWN` on every read. The workflow kernel carries the same class and was measured on it by E-055: a stage's evidence is checked once, at `complete`, and the run then delivers the completion forever — a foundation the workspace has moved past (artifact deleted, declared token removed, glob match gone) is still handed to the agent as satisfied work. The remedy is the same doctrine applied to the same kind of claim: a completion is a claim about the workspace, so it must CARRY a witness (the predicate that satisfied it) and its verdict must be DERIVED from the artifact on disk, never stored as "done". Three-valued, because "artifact unreadable" and "completed before witnesses existed" are neither satisfied nor broken. Predicate-sensitive rather than digest-sensitive, because the claim is "this artifact carries the declared tokens" — an edit that keeps them stays CURRENT, and the bench's paired false-alarm control (the `rewritten-with-token` and `glob-other-match` fixtures) rejects the digest-only design. Report-only on the read surfaces (`status`, `next`, the session-edge advisory), with one hard refusal where the kernel's own doctrine already refuses: `complete` will not advance onto a foundation whose evidence no longer holds, and `--force` remains the escape hatch.
- **Hypothesis:** H-056: "stale_evidence_rate <= 0.0"
- **Measurement Metrics:** stale_evidence_rate <= 0.0 (with false_alarm_rate reported as the control metric)
- **Experiment Design:** The SAME bench and oracle as the E-055 baseline — `scripts/bench/bench_workflow_evidence.py` builds a throwaway project per trial, drives the run through its own public API (`create` → `complete` → `status`/`next_stage`) and probes both read surfaces, n=8 stale + 8 current trials. The only difference is WHAT the surfaces deliver: every trial's artifact predicate is re-applied by an oracle that never imports the module under test (`pathlib.glob` + `str.count`), and a trial now leaks only if a surface still presents the completed stage as anything other than STALE. Controls unchanged: the oracle's expectation vector (`trials: stale=8 current=8`) fails a fixture that stopped producing both classes, the paired false-alarm rate fails a "the file changed ⇒ stale" non-fix, and `--baseline` reproduces the pre-fix delivery semantics and must return 1.0 — the bench is its own negative test on the fixed tree. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
- **Sample Size n:** 16 (8 stale + 8 current trials; the gate parses the denominators from the bench output)
- **Code Scope:** bmad/workflow/advisory.py, bmad/workflow/engine.py, bmad/workflow/evidence.py, bmad/tests/test_workflow.py, scripts/bench/bench_workflow_evidence.py
- **Lineage:** E-055 (the measured baseline this record closes: same bench, same claim, measured=1.0 REJECTED on the unfixed kernel — its `scripts/bench/bench_workflow_evidence.py` scope is re-tread here, so its lesson is carried), E-054 (the board plane re-measured at the landed commit; the "code moved, content identical" lesson is why this plane is predicate-sensitive rather than digest-sensitive), E-053 (the freshness plane: witness + derived verdict + the three-valued vocabulary — this record carries that doctrine onto the workflow evidence plane), E-052 (the first measured baseline of the class; the method — throwaway fixture, independent oracle, paired false-alarm control, `--baseline` negtest — is re-tread here), E-037 (the class itself: an artifact asserting a fact nobody measured — here, that a recorded completion is still true)
