## Experiment: E-116 — A ledger that checks its shape, not its twin: structure-only identity and a placeholder gate

- **Date:** 07.11.2026
- **Status:** planned
- **Theory:** TD-017 (opened by QR-030) records a contradiction inside the debt checker: §1 of `scripts/check-techdebt.sh` demands that `templates/tech-debt.md` and `docs/development/tech-debt.md` be byte-identical, so the shipped template and the live ledger can never differ — and a template that must carry `[X items]` therefore forces the live ledger to carry `<X items>` too, or the live ledger forces the template to ship this repository's debt history. The check made the two files agree instead of making the live one correct: the metrics block stayed at template placeholders and the trend table stopped at SP-003 while the audit printed HEALTHY. A reporting half needs its own invariant: the template owns the SHAPE (headings and table columns), the live ledger owns the CONTENT (no placeholders, real numbers), and each is checked for its own job. This record was first written as E-114 on 06.11.2026. Upstream `main` already carries an unrelated E-114 (the orient epic-roll-up experiment), so pushing this record under that id would overwrite another history; the record and its `raw/` samples were renamed to E-116 before the push. The rename edits the record id inside the checked files' own comments, so the decision is re-measured on the tree that carries the rename. E-115, which re-anchored the local record on the landed tree at `2b88743`, is marked `Re-Measured-By: E-116`; the id and the anchor moved, the claim, the command and the seven samples did not.
- **Hypothesis:** H-116: "techdebt_reporting_accuracy >= 0.95"
- **Measurement Metrics:** techdebt_reporting_accuracy >= 0.95
- **Experiment Design:** Seven isolated fixture trees, each holding a copy of the auditor with the candidate contract applied, a template and a live ledger. The bench mutates one property per sample and asks the auditor for the verdict the reporting contract demands: a live ledger with the template's headings and table columns but different content passes §1; a ledger missing a section or carrying a changed table column fails it; a live ledger containing a template placeholder fails the new §7; a template that carries placeholders is allowed, while a template with no placeholder fails; and a live ledger carrying this repository's long history next to a generic template is not drift. The bench applies the candidate contract to a copy only when the shipped script does not carry it; on this tree that transform is a no-op (the shipped checker already carries the §1 marker and §7), so the samples measure the shipped contract — the same post-write state E-115 documented. The advisory block (not scored) also reports whether the shipped template still has its placeholders, whether the shipped ledger is clean, whether the shipped tree is HEALTHY, and whether `--negtest` names the placeholder stage. The control is the pre-fix contract: byte identity restored in §1 and §7 silenced, which fails every sample that depends on the two files differing. Deterministic, offline, stdlib + POSIX shell only; each sample writes its own verdict, and the aggregate is recomputed from those samples by the gate.
- **Sample Size n:** 7 checks
- **Census:** The seven checks enumerate the reporting contract the ledger owns: three §1 shape verdicts (content differs passes, missing section fails, changed table column fails), three §7 placeholder verdicts (live fails, template allowed, template without placeholders fails) and one whole-file verdict (a live ledger with history is not drift). They are the surface itself, not a sample drawn from a larger population; no sampling inference applies to the verdict, and the control still has to fail the claim.

- **Known Gaps:** A shape check cannot judge prose: a live ledger with the right headings and no placeholders can still carry a stale sentence. The placeholder grammar is the one the shipped template uses (`[X …]`, `[Y …]`, `[TBD]`, `[PLACEHOLDER]`), so a novel placeholder wording could slip past §7 until the grammar is extended. Rewriting the shipped template to a generic shape is a content change for every future project that starts from it — the initial ledger becomes a template to fill rather than a copy of this repo's history, which is the point, but a project that already installed the old copy keeps its own file (the installer never overwrites an existing ledger). The record's own file is deliberately outside Code Scope: the rename edits this file and the checked comments in the same commit, and a record that witnessed its own file would go stale on the commit that approves it. The `scripts/check-plugin.sh` §6c note and the test comments are carried by the story (S-015) rather than this Code Scope, the same boundary IR-016 records.
