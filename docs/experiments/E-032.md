## Experiment: E-032 — The native↔methodology mirror hop must read in BOTH directions, or a QR that declares the record leaves its native story unrecorded

- **Date:** 12.10.2026
- **Status:** completed
- **Theory:** A real Claude Code session (muse-spark-1.3-contributor-free) ran
  `git commit` and was denied while it reasoned about S-002; the tree held a
  done native story (`docs/development/native/1-2-resolve-cyan-accent-alias.md`,
  sprint-status `1-2-…: done`) and its generated methodology record
  (`docs/development/stories/S-002.md`), with a QR the run had just created
  (`docs/quality/QR-002.md`). Reading the gate shows the pair is recognised in
  one direction only. `_find_done_stories_without_record` already hops
  native → record ("a generated methodology record is the SAME work unit as the
  story it mirrors … its `| Native Story |` field names that story"), so a QR
  that declares the NATIVE story covers the generated record. The reverse hop —
  a QR that declares the METHODOLOGY record, i.e. `| Story | S-002 |`, which is
  exactly what `create-qr-record.py` writes — was never read, so the mirrored
  NATIVE story looked unrecorded and the commit was denied with "Story status is
  'done' but no QR record found for 1-2-…". Measured, not inferred: on a temp
  target project with that pair, `_find_done_stories_without_qr` returned
  `['1-2-resolve-cyan-accent-alias']` and `_check_gate_records` returned deny;
  with the QR declaring `S-002` the same pair was split — the record covered
  (its file stem matched) and its mirror not. This is the E-018..E-031 class
  once more — a guarantee exists only where its wiring is — here a one-way
  link standing in for a symmetric identity. The fix builds the record→native
  map from each generated record's own `| Native Story |` declaration (matched
  by the record's FILE STEM, the key `_declaration_covers` itself uses) and lets
  a QR that covers the record cover the mirrored native story, so the pair is one
  work unit in both directions.
- **Hypothesis:** H-032: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-032 claim (it builds a
  temp target project with the done native story, its generated record and one
  QR, drives the real `_find_done_stories_without_qr` for BOTH declaration forms
  — the methodology key and the native slug — demanding the pair is covered, and
  demands an unrelated control QR still flags it), plus the regression tests by
  name. Control — the bench's own "pytest suite green (falsifier)" check pins
  that the code under test still passes the full suite, which now includes the
  E-032 tests
  (`test_qr_declaring_the_methodology_record_covers_the_native_story`,
  `test_native_story_still_flagged_when_the_qr_is_unrelated`). The probe is
  falsifiable by construction: disabling the new reverse hop turns the bench
  check red (`QR declaring 'S-002' left the pair unrecorded:
  ['1-2-resolve-cyan-accent-alias']`), while the unrelated control keeps the hop
  from over-covering. Reproducibility — stdlib only, no network, deterministic:
  the check reads the tree and drives the engine module on a fixed fixture; a
  fixed tree yields a fixed x/y; the measurement reports the tree as it is,
  independent of this record (E-001).
