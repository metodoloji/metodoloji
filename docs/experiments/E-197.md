## Experiment: E-197 — A config typo list names every key it rejected

- **Date:** 22.11.2026
- **Status:** completed
- **Record Kind:** contract
- **Theory:** Found live on a scratch methodology tree on 2026-11-22. A config.toml with five misspelled [hooks] keys — code_gard, blackbord, stop_gard, qualty_gate, freshnes — made every hook invocation write to stderr: "metodoloji: config error: Invalid [hooks] keys in ...: line 2: 'code_gard' (valid: blackboard, ...); line 3: 'blackbord' (valid: ...); line 4: 'stop_gard' (valid: ...)". Two lines were simply absent, with no marker and no count, so the message read as the complete list of what to fix; the operator fixes three, reruns, and meets the next two. The valid-key list also repeated verbatim on each line, which both bloated the message and left no room for the remainder. Under E-196's rule a bounded list is a claim about the whole list: the bound of three is fine, the silence is not. Fixing it also forced a layering fix — the shared join lived in utils, which imports config, and config validates itself at import time, so the join became a dependency-free module that utils re-exports (and which the duplicate-definition scan had to learn about).
- **Hypothesis:** H-197: "config_key_accounting_accuracy == 1.0"
- **Measurement Metrics:** config_key_accounting_accuracy == 1.0
- **Experiment Design:** Inputs: a scratch methodology root built per run (the working copy for the claim, git archive of PREFIX_REV for the control) holding only hooks/engine and a config.toml the bench writes — never the plugin's own config, which decides this repository's guard. Ten probes: the [hooks] list names three and counts two, the marker is singular for a single hidden key, a list that fits prints verbatim, the valid-key list appears exactly once, the [freshness] table counts its remainder too, named-plus-hidden arithmetic equals the number of typos, the real main.py on stderr names the remainder, stays silent on a valid config, uses the singular at four typos, and counted_list has exactly one definition (counting.py, absent from utils). Procedure: each probe rewrites config.toml, runs the validator in-tree (or the shipped hook for the three stderr probes) and reads the message. Control: --broken repeats this against E-196's commit bad08ce, which slices invalid_keys[:3] and repeats the valid list on every line — 2/10, the two passes being the behaviours the bound did not change (a fitting list is unmarked, a valid config is silent). Reproducibility: stdlib plus git, offline, deterministic.
