## Experiment: E-068 — Answering "which run did you mean?" derives evidence for every run

- **Date:** 17.10.2026
- **Status:** REJECTED
- **Theory:** The CLI's most common invocation carries no `--slug`: `status`, `next`, `resume` and `history` resolve the operator's run first, and the resolver answers a question about NAMES — which of these runs is the one? It answered it through the INVENTORY, and the inventory is a read surface that derives a verdict for every run (E-058: bounded artifact reads per completed stage; E-064: one shared code-state probe). So a lookup put the whole evidence plane behind a filename question: with a single run the resolver classified it and then `status` classified it again (two derivations for one answer), and with several runs it classified all of them just to discover the address was ambiguous. That is the class E-058 already ruled on one plane over — work a surface does not need is a defect, not a rounding error — applied to the lookup path the operator hits without asking for anything. The question needs the filenames the store already lists, nothing else.
- **Hypothesis:** H-068: "slug_resolve_read_rate <= 0.0"
- **Measurement Metrics:** slug_resolve_read_rate <= 0.0 (with `slug_resolve_control_rate <= 0.0` carried as the paired control — one run must still resolve to its own name, two or more must still stay ambiguous — parsed from the same bench output)
- **Experiment Design:** Inputs — `scripts/bench/bench_workflow_evidence.py`, extended with a seventh bucket. Two fixtures: a project with ONE run and a project with THREE, every run carrying a completed `artifact` stage so that any classification pass is observable. The detector counts calls to the plane's ONE matcher (`evidence.artifact_matches`, the choke point E-056 made single) while the resolution runs; the expectation is arithmetic — a name question needs ZERO artifact reads — so the implementation does not define what it is scored against. The trial also records what the CLI does next (classifying the answered run), so the double derivation is visible in the same measurement. Control: the answers must stay exactly as before (one run ⇒ its slug; three ⇒ unresolved), which fails a "say no single run" non-fix that would make the counter green and the CLI useless. `--baseline` installs the pre-fix resolver verbatim, so both trees run real code. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
- **Sample Size n:** 2 (resolution trials: single-run, ambiguous; the control's 2 trials are the same fixtures, scored for a wrong answer)
- **Code Scope:** scripts/bench/bench_workflow_evidence.py, docs/experiments/E-068.md
- **Lineage:** E-058 (the doctrine this bucket applies: a read surface on the operator's path must not pay for what its question does not need — and the bounded inventory it built is what makes the cost invisible rather than unbounded), E-064 (the shared code-state probe the inventory now owns, which the resolver was paying for as well), E-067 and E-066 (the preceding plane, and the same framing: the defect is in what a surface DOES for its answer, not in what it reports), E-062 (the inventory's own containment work, whose scope this draft re-treads through the same bench), E-060 and E-059 (sibling containment baselines on the same bench), E-056 (the one-matcher rule that gives this bucket a single countable choke point), E-055 and E-057 (the earlier baselines whose scope this draft re-treads, so their lesson is carried: a bucket needs a paired control).
