## Experiment: E-051 — The engine's dispatch modes were enumerated by hand in eight shipped surfaces, two of them wrong, and the only check near that claim hard-coded the list inside the bench and asked one direction

- **Date:** 15.10.2026
- **Status:** completed
- **Theory:** `_LAZY_IMPORTS` in `hooks/engine/main.py` is the only owner of the mode set (mode → module + handler), and eight shipped surfaces restate it by hand: the project-layout tree comments in README, GUIDE and KILAVUZ, the two runbooks' "beyond `pre`" prose, docs/CLAUDE.md's dispatch line, and the usage strings of `hooks/scripts/hook-entry.sh` and `hooks/scripts/run-hook.sh`. Nothing measured it: the one check near the claim (`_check_documented_modes`) hard-coded the seven names *inside the bench* and asked only whether each appeared somewhere in main.py's source — so a mode added to the map, a mode dropped from a doc and a renamed mode were all invisible, and no doc list was ever read. Measured 2026-10-15, before the repair: (1) README's project layout listed 5 of the 7 modes — "guard, quality, deploy, audit, stop" — omitting `pre` (the single mode hooks.json actually dispatches on every tool call, per docs/CLAUDE.md and GUIDE §9.1) and `session_start`; (2) `run-hook.sh`'s usage string (`<bootstrap|pre|guard|quality|deploy|audit|stop>`) omitted `session_start` while the script accepts and routes it — `bootstrap` goes to bootstrap.sh, every other name goes to hook-entry.sh → the engine, whose map contains `session_start`; the docs/CLAUDE.md line, both runbooks' trees and their §9 prose were correct (7 modes, or 6 with `pre` excluded by the sentence's own wording). A third, structural gap: the map's handler targets were never verified — a mode whose `def` is renamed dies at import time, and only a smoke run would notice.
- **Hypothesis:** H-051: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit plus a throwaway fixture tree (the docs, main.py, the three handler modules and the two shell scripts copied into `tmp_path`). Procedure — run `python scripts/bench/bench_consistency.py`; one check replaces the old one: `_check_engine_mode_lists`. It derives the mode set by parsing `_LAZY_IMPORTS` with `ast` (the dict literal, not a text grep), verifies that every declared handler is a top-level `def` in the module the map names (module AST again), and then reads eight anchored list sites, requiring each captured list to equal the derived set. Two legitimate deviations are declared per site rather than hard-coded into the expectation: the two §9 sentences say "beyond `pre`" in their own words, so they must list the set minus `pre`; and `run-hook.sh` routes one name that is not an engine mode (`bootstrap`), so its usage lists the set plus that name. A site whose anchor no longer matches is a failure, not a skip — a claim that cannot be read is not a measured claim (the E-049 discipline). Controls — the falsifier ran red BEFORE the repair on the shipped tree, naming README and `run-hook.sh` and their missing modes, and green after; on the fixture, five mutations each turn it red by name: adding a mode to the map (every list site goes red), dropping `pre` from README's list, inventing `lint` in docs/CLAUDE.md, renaming the run-hook usage anchor, and pointing `session_start` at a handler that does not exist. The new test also re-derives the mode set with its own `ast` pass (no bench import) and compares README's list, so the pin does not depend on the rule it pins. Reproducibility — stdlib only (`ast`, `re`), no network, deterministic.

The handler verification proves a top-level function of that name exists in the named module, not that it is the semantically right one (a map pointing `stop` at `audit()` would still pass if the name matched), and it does not import the modules, so a handler that exists but raises at call time is out of scope. `sync-hooks-json.py`'s `_HOOKS` / `_DISPATCHED_HOOKS` pair remains a separate hand-maintained list (it names the generated hook commands, not the engine's modes) and is deliberately not folded in here — `check-plugin.sh` §1b still owns the generated manifest. Finally, the rule reads lowercase identifiers only: a list written with different capitalisation or wrapped in code spans is read as a set of tokens, so a future author must keep the anchors' shape (the pattern is reported verbatim in the failure message when it stops matching).
