## Experiment: E-095 — The index rebuild is part of the mutation's transaction

- **Date:** 31.10.2026
- **Status:** completed
- **Theory:** E-092 made `finalize` validate a candidate before writing it and stated the registry's guarantee as "a registry command either completes and is indexed or leaves the entry byte-identical". E-093 and E-094 hardened the write boundary and source identity, but neither tested the last step of the sequence: `finalize` writes the accepted candidate and then calls `_write_index`, while `discard` moves the entry and then calls `_write_index`. Two probes on this host reproduced the missing half. With a registry README that has no generated markers and no `## Registered contexts` section, `finalize` raised `ContextError: registry README has no '## Registered contexts' section` and the entry nevertheless contained the new `Last reviewed on` value and a `| reviewed |` revision row. In the same setup, `discard` raised the same error while the entry was gone from the registry and present under `.archive/<stamp>-mastra/`, so a failed command still moved evidence. The theory under test is that the index rebuild must be preflighted before any entry mutation and rolled back together with it when it fails, for both commands, and that a normal index still regenerates.
- **Hypothesis:** H-095: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the focused index-transaction bench `scripts/bench/bench_external_context_transaction.py`: two deterministic failures (malformed README during `finalize`, the same during `discard`), two unexpected-error failures (`_write_index` raises after the entry was written or moved), and two paired success controls (a normal finalize registers and indexes, a normal discard archives and de-indexes). The `--broken` control disables the preflight and the three restore helpers in memory, reproducing the pre-E-095 order: the four failure cases mutate state while the two happy paths still pass. Add `_index_precheck(root)` that reads the same index text the writer will use and refuses before mutation when neither the generated markers nor the section exists; `finalize` and `discard` call it inside the registry lock. Wrap the mutation and rebuild in one `try`; on any failure restore the README bytes, and either the entry's exact pre-write bytes (`finalize`) or the moved folder (`discard`, after removing a partially written `ARCHIVED.md`). Add `atomic_write_bytes` to the shared module so a rollback restores exact bytes instead of normalising the newlines of a file this command did not create; `atomic_write_text` becomes its UTF-8 wrapper. Pin both structural refusals, both rollback paths and the two happy paths with unit tests, one consistency-bench contract, and the focused bench. Reproducibility is local, deterministic and offline.
