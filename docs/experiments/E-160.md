## Experiment: E-160 — A record is anchored to the code state it was measured against — one owner

- **Date:** 2026-11-14
- **Status:** completed
- **Record Kind:** contract
- **Theory:** Measured 2026-11-14 on this tree: the freshness plane had TWO implementations of what anchors a record's claim. `freshness.annotate()` is the owner — it dates a claim to the commit that last touched its record (the derived witness). The write-path consumer, `guard._record_freshness()`, re-implemented the anchor by hand from the record's `Witness` line and classified from THAT commit. The two disagreed on 41 of 155 shipped records, and both were wrong in the same direction for the newest records: the `Witness` line is written at HEAD, and the commit that lands the record then edits the record's own `Code Scope`. So `changed_since(witness)` counted the landing commit itself and every record was STALE at birth — 110 of 144 scoped records, 9 of them ONLY because of their own landing commit. That made `config.toml`'s documented hardening precondition unachievable: it says to set `[hooks] freshness = "deny"` once "the reported STALE set is empty", and the set could never empty. The plane could therefore never enforce, which is why `deny` locks the repo instead of protecting it. E-159 measured the same class one surface over: a rule that names an artifact nothing resolves.
- **Hypothesis:** H-160: "freshness_anchor_accuracy == 1.0"
- **Measurement Metrics:** freshness_anchor_accuracy == 1.0
- **Experiment Design:** Inputs: the plugin tree at this commit (155 shipped records) plus one throwaway git repo. Procedure: scripts/bench/bench_freshness_anchor.py enumerates the population by glob, never by hand list (the E-039 defect), and asserts four properties: (1) every record gets the same verdict from the guard and from the owner — the two implementations must agree on the whole corpus; (2) no record is stale only because of its own landing commit — for each record the bench finds the commit that last touched it, asks whether anything in its scope moved after that commit, and refuses a STALE verdict when the answer is no; (3) a commit inside the scope landing AFTER the record still reads STALE, so the fix cannot swallow the drift E-053 exists to catch; (4) every module-level compiled regex in the gate is read somewhere, which pins the two dead witness regexes this change removes. The repair deletes the guard's hand-rolled anchor and delegates to `freshness.annotate`, and removes the two declared-but-never-read witness regexes from the gate. Control: --broken re-derives the pre-fix anchor (classify from the `Witness` commit, no tree digest) and must score below the threshold. Reproducibility: stdlib + git, offline, deterministic.

- **Known Gaps:** (1) The plane still classifies on the commit only when `scope_digest = false`; a project that switches that off keeps the pre-E-053 noise, by design. (2) The derived witness dates a claim to the commit that last touched its RECORD, so a record edited for a typo re-dates its claim; a re-measurement is the honest remedy and the record says so. (3) The bench's born-stale probe skips a record with no landing commit (an uncommitted draft) — there is nothing to anchor to yet, and the gate refuses to decide an uncommitted record anyway. (4) The dead-regex probe covers module-level `re.compile` assignments only; a regex built inline or inside a function is not enumerated. (5) This record does not flip `freshness` to `deny`: the plane is now able to empty its STALE set, but flipping the policy is an operator decision for a clean corpus, and doing it here would gate this very commit. (6) The guard's dirty-tree behaviour is unchanged: the plane deliberately ignores uncommitted edits when the witness is derived, because a record cannot be stale against a tree that has not been committed — the commit is the unit of code state.
