## Experiment: E-106 — The promotion check must measure the artifact, not a stub, and never compare a version to itself

- **Date:** 03.11.2026
- **Status:** completed
- **Theory:** A promotion check is only a measurement if it runs the artifact under the same conditions the training used. Three defects broke that in the shipped kernel. First, `optimization eval` and `optimization report` built their `Optimizer` with `ScriptedRunner`, which scores whether the document *contains* required tokens — so the documented promotion check for a real skill was decided by substring presence, never by the model. Second, `cmd_report` re-measured the held-out split and overwrote `report.json`, so rebuilding a record could replace a live decision with an offline one (and spent model calls doing it). Third, `evaluate_heldout` compared `rows[0]` with `rows[-1]` unconditionally: after a run that accepted nothing, those are the same file, and the E-104 run reported `base 0.75` vs `candidate 0.50` — model noise presented as a candidate regression. The theory under test is that the promotion surface must (a) honour the runner the run was given, (b) rebuild from stored evidence instead of re-deciding, and (c) refuse to compare a version with itself.
- **Hypothesis:** H-106: "promotion_integrity_accuracy >= 0.90"
- **Measurement Metrics:** promotion_integrity_accuracy >= 0.90
- **Experiment Design:** Measure `scripts/bench/bench_promotion_integrity.py`: 40 samples in four groups of ten. (1) Runner wiring — `eval` and `report` are invoked through the CLI with five runner templates (`scripted` and four `command:` forms) and the constructed `Optimizer` must receive the matching runner type; ten samples. (2) Stored-evidence reuse — `Optimizer.report(heldout=<stored>)` must return the stored decision without calling `evaluate_heldout` (patched to raise); ten payloads. (3) Single-version trees — `evaluate_heldout` must report `applicable: false` instead of comparing `v0000` with itself; ten generated projects. (4) Two-version trees — after one committed version the same call must report `applicable: true`; ten generated projects. One JSON object per sample with a boolean `ok`. The control (`--broken`) emulates the pre-fix surface: scripted runner for every command, `report()` re-measuring, and a held-out check that never refuses; it must score below the threshold. Deterministic, offline, stdlib only; the bench writes its own sample file.
- **Sample Size n:** 40 samples (4 groups × 10)
- **Code Scope:** optimization/cli.py, optimization/loop.py, optimization/tests/test_loop.py, scripts/bench/bench_promotion_integrity.py, docs/experiments/E-106.md
- **Lineage:** E-105 (the feasibility guard this follows; both are preflight/promotion integrity), E-104 (the run whose held-out line compared `v0000` to itself), E-103 and E-102 (earlier harness and judge corrections in the same kernel), E-097 (the held-out promotion contract) — the loop, gate and version store are unchanged; what changes is the surface that reports and measures promotion.

- **Measurement Command:** python scripts/bench/bench_promotion_integrity.py --samples docs/experiments/E-106/raw/samples.jsonl
