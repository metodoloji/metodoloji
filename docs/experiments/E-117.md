## Experiment: E-117 — A drift check that tells divergence from expiry: TTL-normalized snapshot comparison

- **Date:** 09.11.2026
- **Status:** completed
- **Theory:** The shared mutation path enforces a 24-hour handoff TTL (`_mutate`; its code comment cites E-040, a record that does not survive in `docs/experiments/`), and the replay fold applies the same cleanup while rebuilding from the event log. The recorded snapshot, however, is only cleaned when the next mutation runs — reads are deliberately side-effect free. The doctor's drift check compares the replayed board against the snapshot without applying that same time-based rule, so a board that has merely been idle for a day reads `DRIFTED`: the replayed log has already dropped the expired handoff signal while the snapshot still carries it. The audit then says `NEEDS ATTENTION` and tells the operator to delete `blackboard.json`, which treats a clock-driven expiry as state corruption and spends a rebuild to make a healthy board look healthy. The diagnostic is the surface that has to answer the question it asks — "did the two representations diverge?" — not "has time passed?".
- **Hypothesis:** H-117: "board_drift_classification_accuracy >= 0.95"
- **Measurement Metrics:** board_drift_classification_accuracy >= 0.95
- **Experiment Design:** Twelve isolated fixture project roots. Each root is built through the shipped write paths (`post_alert`, `write_key`, `retire`) so the snapshot and the event log start in the state a real mutation produces; one deliberate mutation then creates the property under test (aging a handoff signal past the 24-hour TTL, adding a snapshot-only key/alert/link, adding a replay-only event, or retiring the signal). The bench asks the shipped drift comparator for its verdict and compares it with the fixture's declared truth. The stale-handoff cases are the discriminator: a correct comparator says "in sync" because both representations apply the same TTL, while a true divergence still says "drifted". The control is the pre-fix comparator — the same normalization without the TTL filter — which must fail every stale-handoff case it is asked to accept. Deterministic, offline, stdlib only; no network, no signing dependency, no temp path in the samples.
- **Sample Size n:** 12 checks
- **Census:** The twelve cases enumerate the drift comparator's decision surface: four states that must read in sync (empty board, fresh handoff, stale handoff alone, stale handoff beside a key that both representations carry) and eight states that must read drifted (a snapshot-only key, a snapshot-only fresh alert, a snapshot-only stale session alert, a snapshot-only link, a snapshot-only stale handoff, a fresh handoff missing from the snapshot, a retired stale handoff that is still absent from the replay after pruning, and a stale handoff plus a true key divergence). They are the surface itself, not a sample drawn from a larger one: every case names a distinct reason the two representations can disagree, and the two signals the comparator must not confuse (time and state) appear on both sides of the verdict.
- **Code Scope:** hooks/engine/modules/blackboard_diagnostics.py, scripts/bench/bench_board_drift.py
- **Lineage:** E-053 (the freshness plane's doctrine that a verdict is derived on every read, never stored), E-113 (the census framing and the `--broken` control shape this bench follows), E-116 (the reporting-half lesson: a checker must check the property its own file is for, not a proxy that can never disagree)
- **Control Command:** python scripts/bench/bench_board_drift.py --broken
- **Raw Samples:** docs/experiments/E-117/raw/samples.jsonl
