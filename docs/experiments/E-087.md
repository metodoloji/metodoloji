## Experiment: E-087 — A stale registry index line is reported instead of trusted

- **Date:** 29.10.2026
- **Status:** completed
- **Theory:** `finalize` is the only writer of the registry README line (`- [Name](slug/context.md) — ref (date)`), and `check` compares that index against the entries by link existence only — missing and dead links are findings, a line that still names an old ref, date or display name is not. E-086's `refresh` moves `Analyzed on` immediately, and the documented workflow lets the agent bump `Analyzed version/ref` in place; when the agent then sets `Status: reviewed` without re-running `finalize`, `check` reports `0 findings` and exits 0 while the README (the surface humans and downstream readers open first) claims `v0.30.0 (2026-10-20)` for an entry analyzed at `v0.31.0 (2026-10-29)`. A registry that stays green while its own summary is wrong is exactly the stale-index failure the registry README warns about in the other direction.
- **Hypothesis:** H-087: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the current consistency bench and its `--broken` seeded-defect control. Extend `check` so every registered entry's index line is parsed and compared against the entry's heading name, `Analyzed version/ref` and `Analyzed on`; any mismatch becomes an index finding that fails `check`, while an in-sync registry stays green and a drifted one turns red. Add unit tests for ref drift, date drift, name drift, an in-sync registry staying green, and `finalize` clearing the drift. Seed removal of the drift comparison in broken mode. Reproducibility is local and offline.
