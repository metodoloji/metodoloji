## Experiment: E-029 — The gate's remedy must run where it is printed: every record-chain remedy names the plugin's own script by a resolvable path

- **Date:** 12.10.2026
- **Status:** completed
- **Theory:** E-028 fixed the QR generator's story-title grammar so the gate's own
  remedy (`create-qr-record.py --story …`) finally produced a declaration the
  gate accepts, and left one follow-up open in its Known Gaps: the *path* the
  remedy prints is still the plugin's own file named relative to the cwd
  (`python3 scripts/create-qr-record.py …`). The guard runs in a TARGET project,
  which does not ship the plugin's `scripts/` tree — the observed session's
  `ls scripts/` proves it — so the remedy cannot be run where the gate prints
  it: the operator is told to execute a file that does not exist. The same
  unrunnable-path shape appears in the commit-time QR gate (which additionally
  names a literal `S-XXX` placeholder instead of the story the operator has),
  in the story-write methodology-record remedy, in the QR-coherence remedy, and
  in the research-experiment gate's own "gate key not found — run … --init-secret"
  messages (`python3 run_experiment.py …`, likewise relative to a cwd the
  operator does not have). This is the E-018..E-028 class once more — a guarantee
  exists only where its wiring is — applied to the *remedy* half of the gate:
  E-028 made the remedy's output valid, E-029 makes the remedy's command
  runnable. The fix anchors every plugin-script command at the engine's own
  plugin root (`config._METHODOLOGY_ROOT`, the root `_check_scope_coverage`
  already derives and `skeleton.py`/`orient.py` already print) and resolves the
  commit-gate QR remedy to the story files the operator actually has (with the
  gate's own key precedence), so the command is valid in a target project.
