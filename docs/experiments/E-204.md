## Experiment: E-204 — The freshness row counts the approvals its list withholds

- **Date:** 2026-11-22
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The commit/deploy freshness row names the approvals the code moved past, and it did so three at a time with no marker. It already stated the total ("5 approval(s) the code moved past") and then joined stale[:3] — the deny branch and the warn branch alike. Observed live on 2026-11-22 on a scratch project holding five APPROVED records the code moved past: the denial named E-900, E-901, E-902 and stopped. The cost is a retry loop with no diagnosis: an agent told five approvals are stale fixes the three it can see, commits, and is denied again by the two the sentence never mentioned — and the row's own remedy text (re-measure or retire) applies to each of them. The bound stays at three because the row is read on every commit; what changes is that the three now end in the repo's counted marker, so the list can no longer be mistaken for the whole set.
