## Delivery

**What shipped.** `evaluate_control_comparison()` in `run_experiment.py`, plus the
`--control-samples` flag and the record-level `- **Control Samples:**` fallback. Rule 7
now judges a comparison claim's control on the control's **own paired verdicts** by the
same McNemar rule that decides the subject: a control that also clears the test is
`REFUSED` (no token), one that does not is `verified`. The scalar `evaluate()` path is
untouched and still serves threshold claims (cases 4 and 5).

**Why it was a hole and not a bug report.** `--control` on a comparison raised
`threshold in '…' is not a number`, the operator removed the flag, and the record kept
`Falsifiability: UNVERIFIED`. The gate's own anti-self-deception check was therefore off
on exactly the records that choose between designs — and the skill documented the manual
workaround as if it were the intended workflow. A control that cannot run is not a
missing feature; it is a check that reads as satisfied.

**Control arm.** `--broken` grades the gate as it stood at `HEAD` (read out of git, not
from the tree), so the control reproduces the defect after the repair instead of measuring
the fix twice. It scores `2/5` — cases 4 and 5 pass there because the threshold path was
never broken — against `5/5` for the fixed gate. The bench refuses to score a revision
that already carries the fix.

**Three instrument defects found while measuring, each of which would have produced a
confident wrong number:**

1. `{samples}` was interpolated in the record but not in the `--run` command, so the probe
   wrote a file literally named `{samples}` and the gate reported the real path as
   unreadable — which reads like a missing fixture.
2. The control's paired file was read **before** the control command ran, i.e. before it
   existed. `raw samples unreadable` again, for the opposite reason.
3. The new error message quoted the old failure text, so a test asserting the old text is
   gone failed on the explanation. The assertion was narrowed to the caller-visible phrase
   (`threshold in`), not dropped.

**Verification.** `scripts/check-plugin.sh` → `STATUS: HEALTHY (all checks passed)`.
`test_run_experiment.py` → 106 passed, including three new cases that drive the CLI:
comparison control that also wins → exit 3, no Decision, `Falsifiability: REFUSED`;
control with no separation → APPROVED, `verified`; missing paired file → exit 2 naming
`--control-samples`.

**Docs corrected** (outside this repo, in the Hermes skill): `record-authoring.md` no
longer presents the manual paste as the workflow, and `bench-and-control-design.md` gains
the general rule that a control must be judged by the same statistic as its subject.

**Where the gap was found, and the follow-up it enables.** A real comparison record in
another project (knovara's E-001, BM25 vs `ts_rank`) declared a control, hit this crash,
and shipped with `Falsifiability: UNVERIFIED` plus the control's numbers pasted by hand.
That record is decided and is **not** reopened here — its samples are the ones its
approval hashed. Its control can now be recorded properly in a follow-up record there
whose `Lineage` names E-001, which is also the correct place to register the same-bench
re-measurement.

**Known gap.** `--control-samples` is not persisted into the record as its own field, so a
later reproduction cannot re-read which file backed the control; the `Falsifiability` line
carries the numbers and the verdict. Adding the field to the record schema is its own
record (the template and `create-record.py` both serve it).

committed here.
