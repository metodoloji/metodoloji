## Experiment: E-097 — An artifact optimizer ships only what a paired gate accepted

- **Date:** 02.11.2026
- **Status:** completed
- **Theory:** Two independent research lines converged on the same object. Microsoft's SkillOpt (arXiv:2605.23904) treats a skill document as the trainable state of a frozen agent and trains it with epochs, a textual learning rate (bounded add/delete/replace edits), a rejected-edit buffer and a held-out validation gate; its ablations attribute stability to bounded edits and gated selection, and it deploys a compact `best_skill.md`. Infini-AI-Lab's Hermit generalises the same move to a harness adapter: one Trainer runs a batch through the acting agent, scores it with a judge, hands the trajectories to an Evolver, checks the proposed adapter and commits the next version into a git tree that can be inspected and rolled back; `skillopt` is one of its supported evolution methods, alongside GEPA, Harness², ReHarness and others. Metodoloji contributes the third ingredient: a measurement gate that refuses a claim its control also clears, and records that bind a decision to the code state it measured. Nothing in this repository combined them — skills were hand-written, `bmad-eval-runner` produced run folders but gated no update, and no version history of an artifact existed. The theory under test is that one kernel can carry all three contracts at once: every candidate edit is bounded and measured on the same held-out cases as the incumbent, acceptance requires a paired exact McNemar decision with a real gain, a rejected direction is remembered, the held-out split is structurally unreachable from training, accepted candidates become an immutable hash-chained version, and the export ships the exact bytes that were measured.
- **Hypothesis:** H-097: "optimization_accuracy >= 0.90"
- **Measurement Metrics:** optimization_accuracy >= 0.90
- **Experiment Design:** Measure the focused kernel bench `scripts/bench/bench_optimization.py`. It evaluates 52 independent checks in eight families against the shipped modules: gate behaviour (clear gain accepted; tie, regression, sub-threshold gain, one-flip insignificance and unpaired/empty/tiny comparisons refused; McNemar symmetry and Wilson bounds), textual-edit bounds (the three budgets — absolute chars, document fraction, hunks — each refused on a diff the edit did not declare; ambiguous/missing anchors; no-op and emptying edits), rejected-edit memory (a repeat blocked, a new direction allowed, near-misses counted, persistence round-tripped, the prompt rendered), split integrity (determinism, seed sensitivity, disjointness, prompt-level leakage detection, unknown-split and duplicate-id refusal), predictor behaviour (prior before history, fitted after, interval coverage, a coverage feature that responds to a helpful edit, screening), the end-to-end loop (an improving edit accepted and versioned, the chain verified, tampering detected, resume not forking history, held-out never entering the baseline, promotion reported), and both exports (Hermit and SkillOpt complete and valid, the token budget enforced, an unmeasured export refused). The scripted runner scores token coverage deterministically and offline, so the bench measures the kernel's decisions rather than a model's ability. The `--broken` control disables the guarantees in memory — ties accepted, no significance test, budgets unbounded, the buffer blind, a seed-insensitive split that also leaks every case into train, no leakage detection, an unfitted predictor, an unverified chain, an export missing required files — while the same 52 assertions run. A benign rerun reproduces the same split and the same verdicts: no clock, no network, no randomness beyond the seeded hash. The bench writes per-check JSONL evidence and prints the aggregate its gate reconciles.

- **Known Gaps:** The scripted runner scores token coverage, not answers: the bench certifies the kernel's decisions and version discipline, not a model's accuracy, and any real performance claim needs `CommandRunner` with real cases. The predictor is a screening aid with a residual interval, not a calibrated probability, and it is fitted from the run's own history (a fresh run reports `source = "prior"`). Both exporters follow the documented shapes of Hermit and SkillOpt rather than vendoring a specific upstream schema; `validate()` checks this repository's promise and the export README names what to confirm against the installed version, so upstream drift fails loudly but is not detected automatically. Leakage detection is prompt-level: two different prompts for the same underlying task pass. The control shares the production code paths and disables them in memory rather than implementing an independent naive optimizer, so it proves the checks can fail, not that a different design would behave identically. The gate's `min_cases` guards a tiny validation split but cannot create power a small case set lacks.
