## Experiment: E-138 — The loop module leaves, its ledger format moves

- **Date:** 2026-11-13
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The BMAD Loop module is three skills that drive an external orchestrator installed from a public git repo. That orchestrator is not installed here (no bmad-loop CLI, no package, no _bmad/, no progress/ or bundles/), and two of the three skills are automation-only by definition: bmad-loop-sweep runs inside an orchestrator sweep session and bmad-loop-resolve runs on a run the orchestrator paused. Neither can ever fire without it, and the third - bmad-loop-setup, the skill that would have installed it - never ran either (no [modules.bmad-loop] in either config layer). But one structure is live and had to survive: the deferred-work ledger's canonical entry format. The ledger itself is real work - three writers append to it and nine findings sit in it from reviews of S-001 and SP-014 - yet its canonical format lived inside bmad-loop-sweep, and five shipped surfaces pointed there: the manifesto, the ledger template, the commit gate's remedy text, check-methodology's warning and the integration bench. Deleting the group without moving the format would leave every one of those pointing at a file that no longer ships - the dead-remedy class E-037 exists to stop. So the format moved to bmad-code-review, the skill that owns the review-time defer flow and the origin of every entry the ledger actually carries.
- **Hypothesis:** H-138: "loop_removal_accuracy == 1.0"
- **Measurement Metrics:** loop_removal_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped tree at this commit. Control: --broken overlays the phantom loop skill and a surviving second copy, so the bench must fail the same claim. Reproducibility: stdlib only, deterministic, no network.
