## Experiment: E-050 — The development wing's Post-Mortem record was promised by four shipped surfaces and shipped nowhere: no template, no directory, and the init-copied docs linked paths init never creates

- **Date:** 15.10.2026
- **Status:** completed
- **Theory:** The template inventory is derivable from the tree — `templates/*.md` is the shipped set and `bmad/scripts/skeleton.py` (`TEMPLATE_PAIRS` + `DIRECTORIES`, canonical since E-047) is the only owner of what `init` installs — but four shipped surfaces restate it by hand: the folder tree and the six `cp _template_X.md` recipes of the init-copied `docs/development/README.md`, the `_template_E/IR/...` shorthand in the three runbooks' plugin-tree comment, the record table and template references of GUIDE/KILAVUZ, and CHECK 8's hand-written scan list in `check-methodology.sh`. Nothing measured any of it. Measured 2026-10-15, before the repair: (1) the README's tree and its §6 recipe promised `_template_PM.md` and an `incidents/` directory — `git log --all` shows no `_template_PM.md` ever existed, `skeleton.TEMPLATE_PAIRS` shipped no PM pair, `DIRECTORIES` never created `docs/development/incidents`, and `templates/_template_PR.md` calls `docs/development/incidents/PM-XXX.md` its "Template:" while GUIDE/KILAVUZ send the reader to that same directory (`cd incidents/` has no directory to enter); (2) the copied `docs/development/README.md` and `docs/development/tech-debt.md` linked the manifestos as `../bmad/development-methodology.md`, `../bmad/research-methodology.md`, `../project-context.md` and `../bmad/usage-guide.md` — `init` deliberately never creates `docs/bmad/` in a project (runbook step 5), `docs/project-context.md` is a skill output that may not exist, and `usage-guide.md` was never shipped at all, so all four were dead links in every project while resolving inside the plugin dogfood; (3) the guide's own "Template missing? Format details in Development Methodology §3" pointed at the story-creation section, and §4 at implementation. The class is the project's recurring one (E-037): an artifact asserting a fact nobody measured — here a shipped inventory, restated by hand in four places and wrong in three directions at once.
- **Hypothesis:** H-050: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit plus a throwaway fixture tree (the same subset copied into `tmp_path`). Procedure — run `python scripts/bench/bench_consistency.py`; two new checks. `_check_installed_doc_paths` walks `skeleton.TEMPLATE_PAIRS` and judges every init-copied doc from inside a project that has ONLY the skeleton: (a) every `_template_*.md` it names must exist under `templates/`; (b) every `├── name/` line of its folder tree must resolve to `skeleton.DIRECTORIES`; (c) every relative markdown link must resolve to an installed destination or lie under an installed directory (`{metodoloji-root}`-form references and URLs are out of scope, since only the plugin-relative form was the bug). `_check_template_inventory_matches_the_shipped_one` compares the hand-maintained inventory BOTH directions: the `_template_A/B/... + tail` shorthand of README/GUIDE/KILAVUZ must equal the shipped `templates/_template_*.md` set exactly (a shipped template nobody lists is as wrong as a listed template nobody ships), and CHECK 8's scan scope — derived here from `TEMPLATE_PAIRS` as every `_template_*` pair landing under `docs/development/` — must list exactly those sources at their plugin paths and exactly their installed destinations. Controls — the falsifier ran red BEFORE the repair on the shipped tree (an unshipped PM template, an un-created directory, seven dead links, three runbook shorthand lists missing the PM family, a CHECK 8 scope missing the PM row) and green after; on the fixture, deleting the PM template, restoring the old relative link, dropping `docs/development/incidents` from `DIRECTORIES`, shortening a runbook shorthand, adding an undocumented `_template_ZZ.md` and narrowing CHECK 8's loop each turn a named check red. The existing CHECK 8 count assertion in `scripts/tests/test_check_methodology_template_leak.py` hard-coded `templates checked: 5`; it now derives the expected count from `skeleton.TEMPLATE_PAIRS` so that deleting a template from the audit moves the actual count away from the canonical one instead of moving the expectation with it. Reproducibility — stdlib only, no network, deterministic.

- **Known Gaps:** the rule proves that a copied doc's path claims resolve and that the inventory sets agree; it does not judge prose ("how to write a post-mortem" can be wrong and still pass), nor does it check the record tables of GUIDE/KILAVUZ, whose `record → output directory` rows are not derivable from the tree (QR's canonical record directory is `docs/quality/` while its template copy lands in `docs/development/`, so template destinations cannot stand in for record directories) — the PM row added to both tables is therefore pinned only by the local test, not by a derived rule. The folder-tree rule reads only `├──/└──` lines, so a tree drawn in another style loses its claim silently. The relative-link rule accepts a link that resolves under any installed directory, not that the exact file exists (a directory-level claim, deliberately: templates reference sibling directories they do not ship files for). The `{metodoloji-root}`-form references are out of scope by design — they are how the manifestos are correctly named, and no check can prove a plugin root from inside a project. Finally, the PM record family is now documented and installable but no enforcer validates PM records (no gate writes or checks them); this record does not add one, and the shipped surfaces do not claim otherwise.
