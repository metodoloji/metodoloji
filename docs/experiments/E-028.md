## Experiment: E-028 — The gate's own remedy must satisfy the gate: the record tooling must read every shipped story title

- **Date:** 10.10.2026
- **Status:** completed
- **Theory:** A field failure shows the guard's QR gate denying a commit for two
  stories and telling the operator to fix it with
  `python3 scripts/create-qr-record.py --story docs/development/stories/S-XXX.md`
  — the gate's own remedy. Reading the code shows that remedy cannot work. (1)
  `create-qr-record.py:extract_story_metadata` matched the story key with
  `^#\s+Story\s+(\S+)\s*:\s*(.+)$`, i.e. ONLY the legacy prose heading
  (`# Story 1.1: Title`). The shipped story template writes
  `# Story: S-XXX — [Story Title]` and the generated record writes
  `# Methodology Record: S-NNN`; for both the extractor returned an EMPTY key,
  so the QR record was written with `| Story |  |` — a declaration that covers
  nothing, which the guard correctly refuses. The operator who follows the
  gate's advice therefore loops forever, and in the observed session had to
  hand-edit the records instead. (2) The engine's own
  `extract_story_key_from_content` was off by one character in the other
  direction: `\S+` swallowed the separator, so `# Story S-002: Title` yielded
  the key `S-002:` — a token no declaration can equal. (3)
  `create-methodology-record.py:extract_story_metadata` had the same
  legacy-only title shape, so a story written from the shipped template
  produced an S record with an empty `Story Title`. The root cause is one
  grammar (`# Story: <key>` for the template / `# Methodology Record: <key>`
  for the record) parsed by three components that each recognised a different
  subset — the same "a guarantee exists only where its wiring is" class
  E-018..E-027 named, here on the record tooling. The fix introduces one story
  identity resolver for both generators (key + title, all three forms and the
  `| Story Title |` / `| Native Story |` rows), makes the engine stop at the
  colon, and pins the agreement with tests and a bench check driven off the
  shipped template file itself.
- **Hypothesis:** H-028: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-028 claim (it loads
  both generators and the engine, drives them on the shipped
  `templates/_template_S.md` and on each title form, and demands the same,
  non-empty key — template, native slug, legacy prose, methodology record —
  plus the engine's exact key on the `# Story:` forms), and the guard's own
  end-to-end tests now run the real generator against the real gate. Control —
  the bench's own "pytest suite green (falsifier)" check pins that the code
  under test still passes the full suite, which now includes the E-028 tests
  (`test_qr_generator_reads_every_shipped_story_title_form`,
  `test_generators_agree_with_the_engine_on_the_story_key`,
  `test_s_generator_reads_the_template_title_form`,
  `test_qr_generated_for_a_methodology_record_satisfies_the_gate`,
  `test_qr_generated_for_a_template_story_covers_it`). The probe is falsifiable
  by construction: reverting `extract_story_metadata` to the legacy-only
  pattern turns the new bench check red (`create-qr-record.py resolves no story
  key from the shipped story template; … key '' != 'S-002'`), and reverting the
  engine's colon fix turns it red (`engine story key 'S-002:' != 'S-002'`).
  Reproducibility — stdlib only, no network, deterministic: the check reads the
  tree and the scripts as they are, a fixed tree yields a fixed x/y; the
  measurement reports the tree as it is, independent of this record (E-001).
