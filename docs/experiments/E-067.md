## Experiment: E-067 — Deliver the run's declared artifact only when the run owns it

- **Date:** 17.10.2026
- **Status:** completed
- **Theory:** E-066 measured the last pointer the plane hands over without asking where it resolves: a spec's top-level `artifact` is repeated verbatim by `status.artifact` and by the session advisory (`tracked in <path>`), and `create` planted such a spec without a check — `artifact_field_escape_rate` 1.0 (6/6) with `artifact_field_accepted_rate` 1.0 (3/3) and the paired control clean. The theory behind the fix is the same boundary the two containment planes already settled, applied to the one thing they do not touch: this field is never OPENED, only repeated, so E-060 (never read an outside artifact) and E-062 (never resolve a spec from outside the project) both passed over it. A pointer an agent acts on is context, and context about a run must be about that run's project. So the kernel delivers the declared pointer only when it resolves inside the project root: `status.artifact` keeps the contained path and gains an `artifact_note` that is empty when the pointer is fine and names the spec's declaration plus the root when it is not, and the advisory says the same sentence instead of `tracked in <an out-of-root path>`; `create` refuses to plant such a spec at all, naming the cause, while the READ side keeps reporting for specs an older tree or a hand edit already carries — the same gate-refuses/view-reports asymmetry E-058 gave the evidence plane. The containment is not a new boundary: it calls `paths.outside`, the one implementation both planes already share (E-062), so "inside the project" keeps meaning exactly one thing.
- **Hypothesis:** H-067: "artifact_field_escape_rate <= 0.0"
- **Measurement Metrics:** artifact_field_escape_rate <= 0.0 (with `artifact_field_control_rate <= 0.0` carried as the paired control — an in-root `artifact` must still be delivered verbatim — and `artifact_field_accepted_rate <= 0.0` as the gate side — `create` must refuse an out-of-root declaration), all parsed from the same bench output
- **Experiment Design:** The SAME bench, fixtures and detectors as the E-066 baseline — `scripts/bench/bench_workflow_evidence.py` — with the only difference being where the declared pointer is allowed to resolve. Every earlier bucket is re-measured in the same run (delivery 12+12, read budget 6, artifact escape 9+3, storage 6+3, command 6+3), so the change is shown not to disturb the planes already hardened. Controls: `artifact_field_control_rate` fails a "strip every declared artifact" non-fix (a legitimate in-root pointer must survive), `false_alarm_rate` still fails a "mark everything UNKNOWN" non-fix on artifacts, and `storage_control_rate` stays 0.0; `--baseline` models the pre-fix delivery for this bucket (the recorded 1.0/1.0 was measured on the unfixed tree, and no unfixed path remains to call), so the recorded red stays reproducible on the fixed tree.
