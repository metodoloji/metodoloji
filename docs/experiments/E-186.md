## Experiment: E-186 — The run a story already declares is the run the kernel opens

- **Date:** 2026-11-20
- **Status:** completed
- **Record Kind:** contract
- **Theory:** Measured 2026-11-20 on this tree: the workflow kernel is a deterministic state machine, but every create path is caller-driven. create --builtin methodology-chain requires the caller to remember the story id as the slug AND to pass --flag tier=N, the branch flag that decides whether IR/SP are required; nothing consults the story record's own Rigor Tier, so a Tier 1 story adopted without the flag makes the run demand planning records its tier says it does not need. The session edge compounded it: advisory.peek and notice.* only ever describe runs that already exist, so an in-flight story with no declared run produced no signal at all. The result is not a broken kernel but an unused one: after 220 commits this project has no .metodoloji/workflow directory, and a story can be implemented start to finish while no run is ever declared.
- **Hypothesis:** H-186: "workflow_adoption_accuracy == 1.0"
- **Measurement Metrics:** workflow_adoption_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped workflow CLI (hooks/scripts/workflow.py) and the shipped hook entry point (hooks/engine/main.py session_start), driven as subprocesses against throwaway projects holding story records in the shipped dialect. Procedure: scripts/bench/bench_workflow_adopt.py runs twelve probes — seven drive adopt (tier-1 branch, tier-3 branch, canonical id resolution, and the four refusals: missing, ambiguous, done, existing run) and five drive the proactive offer (names an in-flight story, yields to an active run, ignores a done story, is read-only, stays bounded). Control: --broken runs the same twelve probes against the pre-change tree at git c302171, where no adopt subcommand exists and no offer is injected. Reproducibility: stdlib only, offline, deterministic; each probe gets a fresh temp project and its own process.
