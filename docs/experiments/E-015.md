## Experiment: E-015 — The tech-debt audit must see the code it governs: orphan markers and malformed IDs in the shipped tree

- **Date:** 09.10.2026
- **Status:** completed
- **Theory:** The debt standard this repo ships is explicit: a debt marker
  lives in the CODE as `# TODO: [TD-XXX]`, the inventory must never hide a debt,
  and the manifesto forbids hidden debt outright ("Debt cannot be hidden"). The
  instrument that is supposed to enforce that is `scripts/check-techdebt.sh`,
  whose §5 docstring promises "every `[TD-XXX]` in comments is in the
  inventory". Reading the behavior rather than the promise shows the gap: §5
  scans only `scratch/` and `custom/` — the free surfaces where an errant
  marker is least likely to matter — so the code the standard actually points
  at (`hooks/`, `scripts/`, `bmad/`, `skills/`) is never read. A repo-wide
  probe makes the failure concrete on the current tree: the only `TODO: [TD-…]`
  markers are in the two inventory files and the auditor itself, while
  `hooks/engine/modules/blackboard.py` carries a bare, malformed reference
  `(TD-14)` — the inventory records `TD-014`, zero-padded — and no check
  anywhere notices. A hidden marker and a dangling id share one root cause:
  the audit observes only two directories, and it matches one comment shape
  (`TODO: [TD-NNN]`) while every other `TD-NNN` reference in the tree goes
  unread. The fix is to widen the observation to the code trees and the free
  surfaces (docs/, templates/ and test directories stay out — they
  legitimately carry prose examples like TD-042 and synthetic test ids, and a
  naive whole-tree scan false-positives on them) and to add the reference half
  — a bare `TD-NNN` token must equal an inventory id or it is drift — then
  repay the one instance that is already in the tree.
- **Hypothesis:** H-015: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-015 claim (the widened
  §5 really scans the code trees, §6's malformed-reference path exists, the
  behavior probe runs the real audit and demands `STATUS: HEALTHY` on this
  tree, and the widened scope stays falsifiable in
  `scripts/tests/test_check_techdebt.py`), and the suite's pytest falsifier
  covers the new hermetic tests that drive the audit against a throwaway tree
  (a `TODO: [TD-999]` in `hooks/` is caught, a bare `TD-14` is caught, a TODO
  naming a real paid debt passes, and the inventory pair's own `TD-042`
  example does not false-positive). Control — the bench's own "pytest suite
  green (falsifier)" check pins that the code under test still passes the full
  suite. Reproducibility — stdlib + POSIX tools only, no network, deterministic:
  the audit derives everything from its own location, and a fixed tree yields a
  fixed x/y; the measurement reports the tree as it is, independent of this
  record (E-001).
- **Sample Size n:** 75 (informational — the gate parses the denominator from

- **Known Gaps:** §5/§6 scan text files with `grep`; a marker written inside a
  binary blob (an image, a zip) is not read, which is the correct limit — a
  debt marker only carries meaning where a human or an agent wrote it as text.
  The scan is scoped to the code trees (`hooks/`, `scripts/`, `bmad/`,
  `skills/`) plus the free surfaces (`custom/`, `scratch/`); `docs/`,
  `templates/` and test directories are deliberately out of scope, and this

  synthetic ids, and the first cut that scanned everything false-positived on
  exactly them. §6 only enforces the reference FORM (a bare `TD-NNN` must equal an
  inventory id); it does not prove the reference is semantically current — a
  code comment naming a paid debt stays legal, which is why the orphan-TODO
