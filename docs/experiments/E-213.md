## Experiment: E-213 — The session-start workflow offer counts every withheld story

- **Date:** 2026-11-22
- **Status:** planned
- **Record Kind:** contract
- **Theory:** The proactive offer names in-flight stories that no declared workflow run claims (E-186). It printed at most two and stopped scanning one row past that bound, so the tail could only ever say (+1 more): five in-progress stories with no run read as three, and thirty read as three too. Measured on 2026-11-22 with five S-*.md story records under docs/development/stories, the shipped sentence was 'PROACTIVE — no declared workflow run for S-101 (in-progress), S-102 (in-progress) (+1 more): …'. The marker also named no unit, so the reader could not tell withdrawn stories from withdrawn commands. The scan now counts the whole set (the files are read anyway) and the sentence goes through counted_list with noun story, so the remainder is the true count with its unit.
- **Hypothesis:** H-213: "workflow_offer_count_accuracy == 1.0"
- **Measurement Metrics:** workflow_offer_count_accuracy == 1.0
- **Experiment Design:** Inputs: a scratch project root per probe holding S-*.md story records under docs/development/stories with '- **Status:** in-progress'; the shipped audit._workflow_offer runs in a subprocess against the tree under test, with no run state unless the probe creates one. Five probes: one story prints whole with no marker; two stories print whole with no marker; five stories end '… (+3 more stories)' and never '( +1 more)'…; three stories end '… (+1 more story)'; a story whose slug already owns a .metodoloji/workflow state file produces no sentence at all. Procedure: one subprocess per probe; the probe prints JSON and the driver reads it. Control: --broken repeats the probes against E-210 commit f88ce5f (3/5) — there the five-story and three-story probes both read the same bare '(+1 more)'.
