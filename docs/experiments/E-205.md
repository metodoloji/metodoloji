## Experiment: E-205 — The freshness row reports the records its cap did not read

- **Date:** 2026-11-22
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The commit/deploy freshness row keeps the hot path cheap by reading at most _FRESHNESS_ROW_MAX_RECORDS (500) record files, and then reported the result as if the corpus ended there. Observed live on 2026-11-22 on a scratch project with 600 APPROVED records: the warn row named 500 stale approvals and the deny row blocked on those, while 100 records were never read — neither CURRENT nor STALE, just unvisited, with no mention that the scan had stopped. That is the failure E-002 named for module lists: a scan is only as wide as its bound, and a reader who is not told the bound believes the sweep was complete, so a stale approval in the last hundred stays invisible and unretired. The cap stays (a commit cannot walk an unbounded corpus), but a truncated scan now says how many record files it did not read — on the warn branch as its own SCAN line, on the deny branch inside the reason, and even when the visited records come back clean.
- **Hypothesis:** H-205: "freshness_scan_bound_accuracy == 1.0"
- **Measurement Metrics:** freshness_scan_bound_accuracy == 1.0
- **Experiment Design:** Inputs: a scratch project root per probe (the working copy for the claim, git archive of PREFIX_REV for the control) holding docs/experiments with 600 APPROVED records (100 for the under-cap probe), read through the shipped guard._freshness_chain_row with the verdict seam (_record_freshness) fixed to STALE or CURRENT and fr.blocks set per probe. Seven probes: the warn row carries a FRESHNESS SCAN line naming the unread count; the deny reason names it; a clean 600-record scan still reports the cap instead of returning silently; a 100-record corpus carries no SCAN line; the message states the unread count; the message states the cap value the code uses; and the decisions themselves are unchanged (warn allow, deny deny). Procedure: each probe builds its corpus, calls the shipped row with its seam values, and reads the warning text or the reason. Control: --broken repeats this against E-204's base commit f7cf51d, which slices e_records at the cap without a word — 2/7, the passes being the behaviours the change did not touch (a corpus under the cap stays silent, the decisions do not move). Reproducibility: stdlib plus git, offline, deterministic.
