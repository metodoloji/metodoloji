## Experiment: E-105 — A split too small to reach alpha must be refused before training

- **Date:** 03.11.2026
- **Status:** completed
- **Theory:** The paired gate is an exact McNemar test, so its power is discrete rather than continuous: at `alpha = 0.05` even a flawless edit (`b = n, c = 0`) cannot pass below six discordant pairs (`p = 2/2^6 = 0.031`; at five pairs `p = 0.0625`). The shipped spec asked for `gate.require_heldout = true` with `heldout_size = 4`, so `evaluate_heldout` could never accept any candidate — the four-epoch run over E-104's 28-case set promoted nothing, and its held-out line compared `v0000` with itself (`base 0.75` vs `candidate 0.50`, both `v0000`) because the two measurements were the same text and the difference was model noise. A spec whose validation or held-out split is smaller than the minimum decidable discordant count trains nothing by construction; `preflight` — the step whose entire purpose is to refuse a run that cannot work before it spends a token — never checked this arithmetic. The theory under test is that the kernel can decide feasibility from the configured alpha and the actual split sizes, and must refuse a spec that cannot promote anything.
- **Hypothesis:** H-105: "spec_guard_accuracy >= 0.90"
- **Measurement Metrics:** spec_guard_accuracy >= 0.90
- **Experiment Design:** Measure `scripts/bench/bench_gate_feasibility.py`: 40 generated specs over a grid of validation sizes 4–8, held-out sizes 3–8 and alphas 0.05/0.01, each with explicit split counts (val, held-out and two training cases) so the split is exactly the configured shape. For every spec the bench asks `optimization.preflight.check` for a verdict and records whether the verdict matches the arithmetic: a spec is feasible only when both splits meet `gate.min_discordant_pairs(alpha)` (6 at 0.05, 8 at 0.01). One JSON object per spec with a boolean `ok`. The control (`--broken`) runs the same grid with the feasibility guard disabled (the pre-fix behaviour), so infeasible specs pass falsely; it must score below the threshold. Deterministic, offline, stdlib only; the bench writes its own sample file.
- **Sample Size n:** 40 specs (5 validation sizes × 4 held-out sizes × 2 alphas)
- **Code Scope:** optimization/gate.py, optimization/preflight.py, optimization/tests/test_loop.py, skills/bmad-research-experiment/optimization.toml, scripts/bench/bench_gate_feasibility.py, docs/experiments/E-105.md
- **Lineage:** E-104 (the 28-case judge whose live run promoted nothing and whose held-out line compared `v0000` to itself), E-103 (the earlier "a small split cannot reach significance" finding, then only observed after the run), E-099 (the native SkillOpt contract and split names this spec uses), E-097 (the kernel's paired gate and held-out promotion contract) — the judge and the case set are unchanged; what is added is the preflight arithmetic that refuses an infeasible spec before a run.
