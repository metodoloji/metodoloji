## Experiment: E-177 — The audit trail stops inventing shell failures

- **Date:** 2026-11-17
- **Status:** completed
- **Record Kind:** contract
- **Theory:** In this checkout's own hook audit trail (2026-11-17), 23 records carry command_failed=glob_nomatch and 13 of them contain the harness's returnCodeInterpretation label 'No matches found' with empty stdout and stderr. audit.command_failure stringifies the whole tool_response mapping, so harness metadata is scanned as if it were process output: a grep that simply found nothing was reported to the agent as 'Command aborted by an unmatched glob — zsh cancels the whole line', a correction for an abort that never happened. The false class both injects a wrong correction into the session and corrupts the per-class failure baseline the trail exists to provide. The defect is structural — the classifier was given the call envelope instead of the command's output — not a wording problem, and the loose 'no matches found' signature would also fire on a tool's own prose once the envelope is removed.
- **Hypothesis:** H-177: "audit_failure_signal_accuracy == 1.0"
- **Measurement Metrics:** audit_failure_signal_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped engine modules (hooks/engine/modules/audit.py) and the pre-fix tree at git 205fa6d. Procedure: scripts/bench/bench_audit_failure_signals.py runs twelve probes in their own process against the tree under test — real zsh/bash abort strings, harness tool_response mappings with empty streams and a misleading returnCodeInterpretation label, a program's own 'no matches' prose, a real abort delivered on stderr inside a mapping, backslash and command-not-found streams, and three end-to-end audit() calls that decide whether a row is written at all. Control: --broken runs the same probes against 205fa6d, where the pre-fix classifier reads the envelope. Reproducibility: stdlib only, offline, deterministic (git archive prefix tree, no network, no clock dependence).
