## Experiment: E-069 — Resolve a run's name from the store's names, not from its evidence

- **Date:** 17.10.2026
- **Status:** completed
- **Theory:** E-068 measured the lookup path paying for the evidence plane: resolving a slug went through the inventory, which derives a verdict for every run, so a name question cost one derivation per run — and with a single run it cost two in total, because `status` then classified the run the resolver had already classified. The fix is a rule the plane already believes, applied to its own front door: a surface must not compute what its question does not need (E-058 bounded that computation; this removes it). `engine.resolve_slug` answers from `store.list_slugs` — the filenames the store already lists, one per state file, corrupt ones included — so the answer is identical while the derivations drop to zero; `status` then classifies the answered run exactly once. The CLI keeps its refusal for "no --slug and no single run", unchanged, because the inventory's count of rows and the store's count of files are the same count (the inventory enumerates the same files). The resolver is a kernel function rather than a CLI helper so the rule lives where the other read rules live and can be measured and tested without spawning the CLI.
- **Hypothesis:** H-069: "slug_resolve_read_rate <= 0.0"
- **Measurement Metrics:** slug_resolve_read_rate <= 0.0 (with `slug_resolve_control_rate <= 0.0` carried as the paired control — one run must still resolve to its own name, several must still stay ambiguous — parsed from the same bench output)
- **Experiment Design:** The SAME bench, fixtures and detector as the E-068 baseline — `scripts/bench/bench_workflow_evidence.py` — with the only difference being what the resolution does: no classification pass. The detector still counts calls to the plane's one matcher during the resolution, so the green is the absence of work, not a claim about it; the trial still records the classification `status` performs afterwards, which is now one run's worth instead of two runs' worth for a single-run project. Every earlier bucket is re-measured in the same run (delivery 12+12, read budget 6, artifact escape 9+3, storage 6+3, command 6+3, declared artifact 6+3+2). Controls: `slug_resolve_control_rate` fails a "always answer no single run" non-fix (it would make the counter green and the CLI useless), `artifact_field_control_rate` and `false_alarm_rate` stay 0.0, and `storage_control_rate` stays 0.0; `--baseline` installs the pre-fix resolver verbatim, so the recorded red is reproduced by running the old resolution. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
- **Sample Size n:** 2 (resolution trials: single-run, ambiguous; the control's 2 trials are the same fixtures scored for a wrong answer)
- **Code Scope:** bmad/workflow/engine.py, bmad/scripts/workflow.py, bmad/tests/test_workflow.py, scripts/bench/bench_workflow_evidence.py
