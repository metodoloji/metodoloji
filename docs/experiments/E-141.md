## Experiment: E-141 — A watch is identified by watcher, pattern and channel

- **Date:** 2026-11-13
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The blackboard's subscription plane deduped on (watcher, pattern) and ignored the channel, in both the direct write and the event-log fold. A skill that watched one pattern at SessionStart could not also watch it at Stop: the second subscribe returned ok:true, the watch never existed, and nothing reported the drop. unsubscribe had no channel argument either, so narrowing a removal was impossible. The defect had been recorded in this repository's own deferred ledger as DW-2 since the S-001 review and stayed unpaid because nothing measured it: the plane read looks healthy, the ack looks successful, and only a routing test that checks BOTH channels sees the hole. A subscription is a routing rule, so its identity is the whole rule — the three fields that decide where an alert goes — not the two that decide what it matches.
- **Hypothesis:** H-141: "subscription_channel_accuracy == 1.0"
- **Measurement Metrics:** subscription_channel_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped tree at this commit. Procedure: scripts/bench/bench_subscription_channels.py runs seven probes — two channels for one watcher coexist, both actually route an alert, a repeated triple stays idempotent (created:false), unsubscribe narrows to one channel, unsubscribe without a channel still clears the pair, an event-log replay reproduces the live board's channels, and the CLI exposes --channel on unsubscribe. Control: --broken imports the PRE-FIX modules from git under a separate package name and runs the same probes against them, so the control is the old code rather than a reimplementation; it scored 0.00. Reproducibility: stdlib only, deterministic, offline.
