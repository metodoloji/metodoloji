## Experiment: E-026 — Every negtest suite's stage count must be declared once and pinned to the stages that exist

- **Date:** 10.10.2026
- **Status:** completed
- **Theory:** E-023 pinned `check-plugin.sh`'s negtest count (`total_stages = 9`)
  to its `[N/total_stages]` banners and to both runbooks, and its Known Gaps
  named the follow-up verbatim: the sibling suites were left alone
  ("unifying the two counters under one bench check"). Reading the tree shows
  the gap is live. (1) `check-techdebt.sh` carries the exact pre-E-023 shape:
  `total_stages = 4` drives four `[N/total_stages]` banners **and** the closing
  `all {total_stages} negtest stages successful`, and nothing pins the declared
  count to the banners that exist — delete stage 3 and the run still prints
  "all 4 negtest stages successful" for a three-stage suite. (2)
  `check-custom.sh`'s `--negtest` has **no counter at all**: three hardcoded
  `print("[OK]   negative test N/3: ...")` string literals and no closing
  summary, so a deleted stage or a partial renumber desyncs silently — while
  both runbooks advertise "3 tests". The root cause is the class
  E-018..E-025 named — a guarantee exists only where its wiring is — and the
  fix is the shape those records used: declare one count per suite, drive the
  banners and a closing line from it, and pin the declared count to the stage
  indices that actually exist, deriving the suite set from the tree rather than
  a hardcoded tuple.
- **Hypothesis:** H-026: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-026 claim (it derives
  every shipped `scripts/*.sh`/`*.py` that declares a `total_stages` negtest
  counter, then requires, per suite, that the declared count equals the set of
  `[N/{total_stages}]` stage indices it prints — exactly `1..N` — and that the
  closing line uses the declared count; it also pins the runbooks' advertised
  check-custom count to that script's counter), plus the regression tests by
  name. Control — the bench's own "pytest suite green (falsifier)" check pins
  that the code under test still passes the full suite, which now includes the
  E-026 tests (`test_all_negtest_counts_match_their_stages`,
  `test_check_custom_negtest_has_one_counter`,
  `test_negtest_suites_cover_the_known_scripts`). The probe is falsifiable by
  construction: bumping `check-techdebt.sh`'s `total_stages` to 5 turns the new
  bench check red (`scripts/check-techdebt.sh: total_stages=5 but stage
  headers=[1, 2, 3, 4]`), and deleting `check-custom.sh`'s counter drops it
  from the derived set and fails the coverage test. Reproducibility — stdlib
  only, no network, deterministic: the check reads the scripts as they are and
  a fixed tree yields a fixed x/y; the measurement reports the tree as it is,
  independent of this record (E-001).

  contains `--negtest` and declares `total_stages` — so a suite that prints
  stages without a counter is out of scope by design (`scripts/check-handoff.py`

  a closing summary line was added, which changes only the negtest's printed

  exits 0 after break→catch→restore).
