## Experiment: E-201 — The orientation digest counts the stories its step bound withheld

- **Date:** 2026-11-22
- **Status:** completed
- **Record Kind:** contract
- **Theory:** The orient digest turns live sprint state into next steps — one line per story in 'review' and one per story in-progress — and both lists were sliced at three with no marker. Observed live on 2026-11-22: a board listing five review and five in-progress stories produced exactly three steps per status, and the rendered digest read as the whole backlog. That is the failure mode that costs the most here: the digest is the run opener, so an agent reads three review stories, finds them already handled, and never learns two more are waiting in review for a verdict that only a review produces. E-198 fixed the same silent bound on the sprint line that the digest prints right above these steps, and E-196 on the lists inside the inject; this is the action list itself. The fix names the three and, when more exist, appends one counting step carrying the sprint file's own total — so the truncation is visible and the reader knows where the rest is.
- **Hypothesis:** H-201: "orient_step_bound_accuracy == 1.0"
- **Measurement Metrics:** orient_step_bound_accuracy == 1.0
- **Experiment Design:** Inputs: a scratch project root per probe (the working copy for the claim, git archive of PREFIX_REV for the control) holding a sprint-status.yaml under docs/development/native with the probe's statuses, read through the shipped orient.build (and the shipped orient.py text render for one probe). Eight probes: five review stories yield three named steps plus a counted remainder, the same for five in-progress, seven review stories count four and name the file's total of seven, the three named keys per status are the file's keys, a board that fits carries no remainder line, the text render shows the counted line, the ready-story fallback still fires when no live story exists, and orient.py carries no bare three-item step slice. Procedure: each probe writes its sprint file, calls the shipped digest, and reads the next_steps it emits. Control: --broken repeats this against E-200's commit bad08ce, whose digest slices both lists at three — 3/8, the passes being the behaviours the change did not touch (the named keys, a fitting board, the ready fallback). Reproducibility: stdlib plus git, offline, deterministic.
