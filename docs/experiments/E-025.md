## Experiment: E-025 — §3's Re-Measured-By marker must be read from the canonical bullet line, not matched anywhere in the record

- **Date:** 10.10.2026
- **Status:** completed
- **Theory:** Reading `check-plugin.sh` §3's *behavior* rather than its promise,
  on this tree, it reports
  `E-023.md -> CROSS-MACHINE but re-measurement missing/unverified:   `Re-Measured-By:`
  marker; these three were never re-measured). The record has.` and prints the
  same sentence as a candidate filename
  (`or create docs/experiments/  `Re-Measured-By:` marker; these three were
  never re-measured). The record has.md`). E-023 carries **no** re-measurement
  marker — it merely *documents* the P11 repair in prose ("E-001..E-005 already
  carry the documented P11 `Re-Measured-By:` marker; these three were never
  re-measured"). The branch exists to read the operator's declared marker, but
  its guard is the unanchored `grep -q 'Re-Measured-By:' "$rec"`, which matches
  the phrase anywhere in the record, and its extractor
  `grep ... | head -1 | sed 's/.*Re-Measured-By:...\(E-[0-9]*\).*/\1/'` returns
  the whole sentence when no E-id follows the phrase. So a record that talks
  about the marker is misclassified as carrying one, and the audit prints a
  bogus filename and a false CROSS-MACHINE verdict. The canonical marker — as
  shipped on E-001..E-005 — is a bullet line, `- **Re-Measured-By:** E-006
  (08.10.2026)`. This is the same class E-018/E-019/E-020/E-021/E-024 named —
  the audit is only as precise as the surface it actually reads — applied to
  §3: the guard reads a *phrase* where it must read a *line form*. The fix
  anchors both the guard and the extraction to that line form, so a prose
  mention no longer counts and only a canonical marker does.
