## Experiment: E-057 — The inventory surface hides a moved-on foundation, and the re-derivation reads without a budget

- **Date:** 17.10.2026
- **Status:** REJECTED
- **Theory:** E-056 gave the workflow kernel a derived evidence verdict on the two surfaces an operator drives a run from (`status`, `next`). Two holes remained in the same plane, both measured here on the unfixed tree. (1) The INVENTORY surface — `list`, where an operator picks which run to continue — carries no verdict at all: a run whose completed stage no longer holds its evidence is listed as plainly as a healthy one, which is the E-053 plan's F-03 shape ("the most durable, least audited surface") one level down. (2) The re-derivation READ is unbounded: `evidence.artifact_matches` reads a candidate artifact whole (`read_text`) and scans every glob candidate until one matches, and it runs on the SESSION EDGE (the advisory is computed at SessionStart). The module bounds the predicate (`MAX_CONTAINS`) but nothing bounds the read, so a spec that declares a large artifact or a wide glob turns every session start into an unbounded scan — the plan's own doctrine for this class is "bounded, past the bound UNKNOWN with the reason" (`[freshness] max_digest_files`, E-053 §5.5), and this plane does not implement it.
- **Hypothesis:** H-057: "stale_evidence_rate <= 0.0"
- **Measurement Metrics:** stale_evidence_rate <= 0.0 (with `unbounded_read_rate <= 0.0` carried as the read-budget threshold and false_alarm_rate as the paired control, all three parsed from the same bench output)
- **Experiment Design:** Inputs — `scripts/bench/bench_workflow_evidence.py`, extended from E-055/E-056: a throwaway project per trial driven through the kernel's own public API (`create` → `complete` → `status`/`next_stage`/`list_runs`), now probing THREE read surfaces (the peek, the computed next step, and the inventory). Delivery bucket: the same 4 stale + 4 current fixtures as E-056 (8 trials x 3 surfaces = 12 + 12), with the expectation computed by an oracle that never imports the module under test (`pathlib.glob` + `str.count` re-applying the declared predicate). Read-budget bucket: 2 fixtures x 3 surfaces = 6 trials whose artifact sits PAST the read bound (an artifact planted wider than the bound with the token genuinely present, and a glob whose satisfying candidate is buried under more matches than the scan bound) — the honest answer there is UNKNOWN ("cannot be established within the read budget"), so a surface that answers CURRENT has proved it read the whole thing, and a surface that answers STALE has proved it turned an unaffordable read into a definite negative. Fixture sizing is derived from the shipped bound where one exists (`getattr`), with a bench-declared floor of 4 MiB / 200 candidates; a shipped bound wider than the floor fails the bench loudly instead of quietly weakening the fixture. Controls — the oracle's expectation vector (`trials: stale=12 current=12 unbounded=6`) fails a fixture that stopped producing both classes; `false_alarm_rate` fails a "mark everything UNKNOWN" non-fix (a satisfied, in-budget artifact must stay CURRENT); `--baseline` reproduces the pre-fix delivery semantics. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
- **Sample Size n:** 30 (12 stale + 12 current + 6 past-bound trials; the gate parses the denominators from the bench output)
- **Code Scope:** scripts/bench/bench_workflow_evidence.py, docs/experiments/E-057.md
