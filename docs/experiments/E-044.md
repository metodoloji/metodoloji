## Experiment: E-044 — The relay graph was checked by its source half only: a wrong target and an undocumented relation passed as [OK]

- **Date:** 2026-10-14
- **Status:** completed
- **Theory:** The blackboard commit cc5a02c taught the handoff lint to check the relay graph: one `EXPECTED_LINKS` entry per producing skill. But the entry was a SOURCE-ONLY marker — `"bmad-prd": "link --a prd."` — checked with a substring test (`EXPECTED_LINKS[skill] not in blob`). The target node and the `--relation` were never looked at, so the same drift E-043 closed for the change radar was still open one surface over: a close-out could trace the relay to the WRONG downstream, or ship a relation outside the vocabulary GUIDE/KILAVUZ §14 documents (`informs|constrains|validates`, with `owns` reserved for the engine's automatic canvas edge and `supersedes` for re-runs), and the lint printed `[OK] … close-out traces the relay on the graph`. It is provable on the pre-fix rule: `"link --a prd." in "link --a prd.acme --b TOTALLY-WRONG.node --relation nonsense"` is True, exactly as for the correct edge — the check could not tell them apart. A wrong target is not cosmetic: `neighbors --node <key>` (the operational trace the same commit built, and the one the downstream activation peeks) would name a node the relay never reached. Nothing checked the relation vocabulary either, so a hand-written `--relation owns` — the engine's reserved automatic edge — would corrupt the graph plane silently. The class is the project's recurring one (E-037): an artifact asserting a fact nobody measured. The closure makes the whole edge the contract and derives the shipped graph from the tree independently, so the declared table cannot fall behind a new skill.
- **Hypothesis:** H-044: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure — run `python scripts/bench/bench_consistency.py`; the new check `_check_relay_graph_edges_match_declared` derives every shipped edge from `skills/*/SKILL.md` (plus their steps/) and `custom/*.toml`, requires `EXPECTED_LINKS` to equal it both ways (a surface that ships an edge undeclared, and a declaration with no shipped edge, both fail), and requires every shipped relation to be in the runbooks' documented vocabulary and named in the §14 Graph bullet. The lint's `EXPECTED_LINKS` now carries the full `(source prefix, target prefix, relation)` triple and checks it exactly: a wrong target, a wrong relation, a missing relation, and an undeclared extra edge each warn. Controls — the falsifiers ran BEFORE the fix: the pre-fix rule was shown to accept `link --a prd.acme --b TOTALLY-WRONG.node --relation nonsense` (one-line probe, documented above), and the new bench check goes red on a wrong target and on a rogue relation (`owns`) when driven against those fixtures. Reproducibility — stdlib only, no network, deterministic (pure text plus one regex derivation over the tree).
