## Experiment: E-066 — The run's declared artifact is delivered as the tracking location even when it sits outside the project

- **Date:** 17.10.2026
- **Status:** REJECTED
- **Theory:** The kernel confines what it READS (E-060: an artifact outside the root is never opened; E-062: the run's spec is never resolved from outside the project). It does not confine what it HANDS OVER. A spec's top-level `artifact` is its declared durable source of truth — the file the workflow's own state lives in — and two read surfaces repeat it verbatim: `status` returns it as `artifact`, and the session advisory ends with `tracked in <path>`, the line a resumed agent obeys first. Nothing checks where that pointer resolves. A spec authored elsewhere, copied from another project, or simply written with a `../` can therefore tell the agent to track its work in a file the run does not own — a path outside the project root — and both surfaces deliver it as if it were the run's own. That is one hop past the two containment planes already built: E-060 stopped the plane from READING an outside artifact, E-062 stopped it from RESOLVING an outside spec, and this one is the pointer neither of them governs — it is never opened, only repeated, which is exactly why it was never noticed. The class is the same, and so is the honest answer: a claim about a run's own project may only name its own files.
- **Hypothesis:** H-066: "artifact_field_escape_rate <= 0.0"
- **Measurement Metrics:** artifact_field_escape_rate <= 0.0 (with `artifact_field_control_rate <= 0.0` carried as the paired control — an IN-root `artifact` must still be delivered verbatim — and `artifact_field_accepted_rate <= 0.0` as the gate side of the same claim — `create` must refuse a spec that declares an outside pointer), all parsed from the same bench output
- **Experiment Design:** Inputs — `scripts/bench/bench_workflow_evidence.py`, extended with a sixth bucket. Escape bucket: 3 spellings of an out-of-root pointer (`../outside.md`, `docs/../../outside.md`, an absolute path) × 2 surfaces (`status.artifact`, the session advisory) = 6 trials, plus 3 gate trials and 2 control trials. Every trial is measured through REAL code on both trees: the run is created from a spec with no `artifact` and the SAVED spec copy is then given one — precisely what an older tree, a hand edit or an authored-elsewhere spec leaves behind — so nothing here is a model of pre-fix behaviour. The defect is a surface that hands the path over as the run's tracking location (`status.artifact` resolving outside the root, or the advisory saying `tracked in <path>`); the gate defect is `create` accepting the spec at all, and the control is an in-root `docs/notes.md` still delivered verbatim by both surfaces — it fails a "strip every declared artifact" non-fix, which would silently delete a legitimate durable pointer. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
- **Sample Size n:** 6 (escape trials; the 2 control trials and 3 gate trials are reported separately and the gate parses each denominator from the bench output)
- **Code Scope:** scripts/bench/bench_workflow_evidence.py, docs/experiments/E-066.md
- **Lineage:** E-060 (the READ containment this bucket extends: an outside artifact is never opened — this one is never opened either, it is handed over, which is why it survived that plane), E-062 (the STORAGE containment: a run's spec is resolved only from inside its own project; the `artifact` field lives in that spec and was the one part of it no boundary governed), E-056 and E-058 (the plane's shared vocabulary: a claim the plane cannot establish answers UNKNOWN with the reason, and a view reports while a gate refuses), E-064 (the immediately preceding plane, and the same lesson at a different angle: the pointer a surface repeats is context the agent acts on, so it has to be true of the run's own project), E-061 and E-059 (the sibling baselines on this bench, both measured on surfaces that ran unattended), E-055 and E-057 (the earlier baselines whose scope this draft re-treads, so their lesson is carried: a bucket needs a paired control, and a delivered half-truth is a defect).
- **Raw Results:** measured=1.0; n=6
- **Uncertainty:** none (lower-bound claim: no small-sample risk)
- **Metric:** consistent (measured artifact_field_escape == claimed artifact_field_escape)

- **Known Gaps:** the bucket scores DELIVERY of the pointer, not whether an agent follows it — no fixture can measure what a model does with a path, so the claim is deliberately about what the surfaces hand over. `status.artifact` is checked by resolving the returned string, so a surface that returned the raw string with a "this is outside" sibling field would still count as a defect here; that is intentional (the field an agent consumes must not carry a non-owned path) and the fix must make the consumed field safe rather than annotate it. The advisory is scored by its rendered sentence, so a different wording of the same leak (for example naming the path without "tracked in") would evade the detector — the fix keeps the wording in one place, but the bench cannot prove the absence of every phrasing. The bucket is 3 spellings of one question: a symlink inside the root that points out is not fixtured (E-060 pins that shape for artifact evidence), and a declared artifact that does not exist yet is not a defect class at all (a spec may declare a file the run will create).
