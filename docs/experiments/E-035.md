## Experiment: E-035 — The free zone must be gapless AND fail-closed: docs/*/raw/ hosted gate-accepted benches, and the case rule belonged to no filesystem

- **Date:** 12.10.2026
- **Status:** completed
- **Theory:** The free-zone doctrine (GUIDE §10.1/§10.2) states two rules at once: every guard-free surface refuses a measurement bench, and the free zone is gapless. Reading the shipped code against the last three session-evidenced fixes (E-031…E-034 — the class where two gates read one fact differently) showed both rules broken on the free-zone surface itself. (1) `bench_in_free_zone` (the gate's standalone matcher, which cannot import the engine) enumerated FREE_PREFIXES by hand and knew nothing of FREE_DOC_MD / FREE_DOC_RAW: `docs/foo/raw/` is guard-free — an agent writes a script there with no approval — yet `python3 docs/foo/raw/bench.py` was ACCEPTED as a measurement, the fabricated-bench vector the rule exists to refuse; the parity checks (test_config, bench_consistency) iterated the same hand-list, so the enumeration could not notice its own gap (E-018/E-021/E-026/E-030's class: derive the surface set from the tree, pin it falsifiably). (2) The prefix tuples matched case-sensitively while the docs regexes and the bench matcher carried a blanket `(?i)` — the zone's case rule was the regex's, not the filesystem's: on a case-sensitive host `DOCS/e/raw/p.py` was freed although it is a different directory (fail-open), and on a case-insensitive one — this repo's own Windows dev host — `SCRATCH/p.py` was gated although it IS scratch/, the documented "gapless" zone (fail-closed). One rule now governs every surface (utils.is_free, bench_in_free_zone, check-plugin.sh's engine-less fallback, GUIDE/KILAVUZ §10): membership folds case exactly where the filesystem does (`os.name == "nt"`), and every script-hosting free surface — prefixes, docs raw trees, documents, root `explore_*` — refuses a bench in BOTH directions, pinned by parity probes that read guard-free from `utils.is_free` instead of a hand-list.
- **Hypothesis:** H-035: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates independent doc/code-consistency claims and prints `consistency_accuracy=(x/y)`; the extended `_check_free_surface_parity` replays every guard-free surface through the gate's matcher (prefixes, the two docs surfaces, the explore_* doctrine) and cross-checks the case rule against `utils.is_free` in both directions on both filesystem classes. The behavioral regressions live in `hooks/engine/tests/test_utils.py` (`test_free_zone_case_follows_the_filesystem`), `hooks/engine/tests/test_config.py` (`test_bench_zone_covers_free_prefixes_and_explore_files`), `skills/bmad-research-experiment/scripts/tests/test_run_experiment.py` (`test_bench_in_free_zone`, `test_bench_free_zone_guard_parity`, `test_bench_free_zone_case_parity`) and the gate's own `--selfcheck` block. Controls — the falsifiers were executed BEFORE the fix and failed as predicted: on this Windows host `is_free("SCRATCH/explore.py")` returned False (the gapless claim broken) and `bench_in_free_zone("python3 docs/e_surface/raw/bench.py")` returned False (the fabricated-measurement vector open); re-adding the blanket `(?i)` or shrinking the enumeration back to FREE_PREFIXES turns the bench check and the suites red again. The bench's "pytest suite green (falsifier)" check pins that the code under test still passes the full suite; the same 10 Windows-only `OSError WinError 6` subprocess failures appear in a full-suite run of the pristine tree and are environmental, not this change's. Reproducibility — stdlib only, no network, deterministic: a fixed tree yields a fixed x/y, independent of this record (E-001).
