## Experiment: E-134 — Every witness diff is computed over the whole tree, even when the claim scopes one directory

- **Date:** 2026-11-12
- **Status:** completed
- **Record Kind:** experiment
- **Theory:** E-132 measured the overrun and E-133 verified the memo that removed the re-parsing, but this repository still answers a write-shaped command in 18-20s. Profiling after the memo moves the dominant term: 16.6s of that 18-20s sits in subprocess version-control calls, thirty-one of them, each a full diff --name-only from one witness point to HEAD. The scan is scope-blind at this layer: it knows every record Code Scope, yet it asks the version-control store for every changed file in the tree and then filters in Python. One such diff here spans 1,794 files and costs 0.90s, while the same diff restricted to a single directory from that scope costs 0.019s - a 47x difference on identical work. A record whose scope is hooks/engine pays for 1,794 paths to learn about 44. So the defect is not that the diff is expensive; it is that the price is set by repository size rather than by the claim being tested, which means it grows with every unrelated change anyone lands.
- **Hypothesis:** H-134: "freshness_diff_waste_rate >= 0.999"
- **Measurement Metrics:** freshness_diff_waste_rate >= 0.999
- **Experiment Design:** Cells are the corpus records whose Code Scope names a literal directory prefix - the ones a pathspec can narrow. For each cell the bench times the diff its witness point actually needs two ways: repo-wide, which is what the shipped code asks for, and restricted to the literal prefixes of that record scope. A cell is waste when the repo-wide diff costs at least twice the narrowed one, because that is work the scan paid for and could not use. The rate is the share that are waste. Records whose scope is pure glob with no literal prefix (for example a bare **/*.py) are excluded from the census rather than counted as failures: nothing can be narrowed for them, and pretending otherwise would make the claim false by construction. The control applies the pathspec to both sides, so the ratio collapses to 1.0 and no cell can reach 2x - it must score 0.0 and therefore cannot clear the claim.
