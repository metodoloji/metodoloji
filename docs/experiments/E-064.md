## Experiment: E-064 — Date a command completion to the tracked code state it ran in

- **Date:** 17.10.2026
- **Status:** completed
- **Theory:** E-063 measured the plane delivering a completed `command` stage with no verdict at all: `verify` skipped every completed stage whose witness was absent and whose spec kind was not `artifact`, so a green test suite read exactly like a green test suite that ran forty commits ago. The doctrine behind that skip (E-056's rule 5) was half right — a `note` is a statement, not a claim — and half wrong: a command's result IS the thing that most needs dating, precisely because it cannot be re-derived by looking. The fix dates it. The completion records the TRACKED code state the command ran in (the commit HEAD names AND a digest of the tracked working-tree changes, so a completion made on a dirty tree is dated to that dirty state rather than to a commit it never had), and every read compares that with the state in force. Unchanged answers CURRENT — a genuinely useful verdict the silence could not give; moved answers UNKNOWN naming both states, which is the honest shape because a look cannot falsify "this argv exited 0" (so this plane never answers STALE for a command, and never blocks an advance over one); an oracle that cannot answer at all (no git, no commit yet, git unavailable, an old git without `--porcelain=v2`) answers UNKNOWN with the reason instead of a guess. The oracle is the one the board plane already dates its decisions to (E-053/E-054). The cost is bounded the way E-058 bounded the artifact read: ONE probe per read pass, shared by every run an inventory classifies and lazy enough that an artifact-only project never pays for it — and only TRACKED files are in the fingerprint, which the verdict's wording says out loud.
- **Hypothesis:** H-064: "command_silence_rate <= 0.0"
- **Measurement Metrics:** command_silence_rate <= 0.0 (with `command_hold_rate <= 0.0` carried as the paired control — an unchanged tracked code state must answer CURRENT — parsed from the same bench output)
- **Experiment Design:** The SAME bench, fixtures and detectors as the E-063 baseline — `scripts/bench/bench_workflow_evidence.py` — with the only difference being what a completed command stage delivers: a derived verdict instead of silence. Every other bucket is re-measured in the same run (delivery 12+12, read budget 6, artifact escape 9+3, storage 6+3), so the change is shown not to disturb the planes already hardened. Controls: `command_hold_rate` fails a "mark every command UNKNOWN" non-fix (the unchanged fixture must answer CURRENT — the whole point of dating rather than disclaiming), `false_alarm_rate` still fails a "mark everything UNKNOWN" non-fix on artifacts, and `storage_control_rate` stays 0.0; `--baseline` reproduces the pre-fix delivery semantics (no verdict on any surface) so the recorded red is reproducible on the fixed tree. Procedure — `python scripts/bench/bench_workflow_evidence.py`.

- **Known Gaps:** the probe's cost is bounded by a DECLARED timeout (5 s) and by one-call-per-pass, not measured — the bench scores the verdict, not the wall-clock of the oracle, so a pathological repository would pay 5 s per read pass at worst and that ceiling is asserted, not timed. The fingerprint covers TRACKED files only: an untracked file that a command reads (a fixture, a lockfile) can change without moving the verdict, which every reason string says (\"tracked\") but no fixture pins. A project that is not a git work tree cannot be dated, so its command completions read UNKNOWN forever — honest, and useless as a verdict, which is the price of having no oracle (the bucket does not fixture that case; the unit tests do). The dated witness is not retroactive: completions recorded before E-064 carry no `code_state` and read UNKNOWN with \"re-complete the stage to date it\", which is the same non-blocking shape as E-056's legacy artifacts. Re-running the command to re-establish it remains manual (`complete --force` after a re-run) — the kernel does not re-execute a command to re-date it, because a command has effects.
