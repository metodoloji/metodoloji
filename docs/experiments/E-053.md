## Experiment: E-053 — Date every decision to a code state, so a moved-on claim is never delivered as live work

- **Date:** 16.10.2026
- **Status:** completed
- **Theory:** A recorded decision — a board hand-off signal, an APPROVED experiment scope, a run key — is a claim about the CODE STATE at the moment it was written. E-052 measured the failure on the unfixed tree: the engine's validity vocabulary held two states (delivered / absent), so a signal whose claim the code had moved past was delivered as live work and validity was proxied by AGE alone (the write-path TTL). The remedy the external report named — "date every recorded decision to a commit" — is applied here as a first-class plane: every claim carries a WITNESS (`{commit, tree, scope, ts}`), freshness is DERIVED and never stored, and the verdict is three-valued (`CURRENT | STALE | UNKNOWN`) with `UNKNOWN` a real answer rather than a silent `CURRENT`.
- **Hypothesis:** H-053: "stale_delivery_rate <= 0.0"
- **Measurement Metrics:** stale_delivery_rate <= 0.0 (with false_alarm_rate reported as the control metric)
- **Experiment Design:** Inputs — `scripts/bench/bench_freshness.py`, which builds its own throwaway git repo per scenario (no dependency on this checkout, no gate key, stdlib + `git` only). Scenario A (derived witness): six fixture records (`E-900`/`E-902`/`E-903` declare `Code Scope: src/**`, `E-901`/`E-904`/`E-905` declare `lib/**`), a hand-off posted from each BEFORE any code moves, then one commit that rewrites `src/engine.py` — so the `src/**` claims are stale and the `lib/**` claims are not, dated only by the record's own last-touching commit. Scenario B (stored witness): `E-910`/`E-911` posted after the module exists, then the same commit. Each signal is probed on TWO delivery surfaces — the peek (`pending_handoffs`) and the session-start inject text — so n=8 stale trials and n=8 current trials. Procedure — `python scripts/bench/bench_freshness.py`. The EXPECTED verdict is computed by an oracle that never imports the module under test: `git log -1 -- <record>`, `git diff --name-only <commit>..HEAD` plus untracked files, intersected with the record's declared `Code Scope` prefix. A trial leaks when the oracle says STALE and the surface delivers something other than STALE (an unlabelled delivery reads as CURRENT); it is noise when the oracle says CURRENT and the surface says STALE. Controls — the oracle's own expectation vector is printed as `trials: stale=8 current=8`, so a fixture that stopped producing both classes fails loudly instead of scoring 0; the false-alarm rate is the paired control that a "mark everything stale" non-fix cannot game. Reproducibility — deterministic, no network, each run in a fresh `mkdtemp`.
