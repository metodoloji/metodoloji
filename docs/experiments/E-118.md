## Experiment: E-118 — The same drift contract, measured on the tree it landed in

- **Date:** 09.11.2026
- **Status:** completed
- **Theory:** E-117 approved the TTL-normalized drift comparator, and then the fix it authorised changed the very files its witness pointed at: `_doctor_drift` in `hooks/engine/modules/blackboard_diagnostics.py` and the census in `scripts/bench/bench_board_drift.py` both moved inside the claim's Code Scope, so the freshness plane reported E-117 as STALE — "uncommitted edits inside the claim's scope". That is the plane working, not failing: `ae2878c` was the state before the write, and a record cannot testify for a tree it predates. The documented remedy applies (the same one E-115 used when E-054 re-measured it): re-run the identical bench against the LANDED state in a new record, mark the old one `Re-Measured-By`, and let the cascade say the decision now anchors to the tree an operator actually has. Nothing about the claim changes — the hypothesis, the command and the twelve samples are the same; only the code state the witness names is new.
- **Hypothesis:** H-118: "board_drift_classification_accuracy >= 0.95"
- **Measurement Metrics:** board_drift_classification_accuracy >= 0.95
- **Experiment Design:** The E-117 bench, unchanged, run on the clean committed tree (`cbdd8e4`). It builds twelve isolated fixture project roots through the shipped write paths (`post_alert`, `write_key`, `retire`) and stages the two shapes a mutation cannot reach by editing the fixture files directly: an expired handoff signal (aged past the 24-hour TTL in both representations) and a deliberate one-sided key, alert or link. The bench asks the shipped comparator for its verdict and compares it with the fixture's declared truth. On the landed tree the module carries `_DRIFT_TTL_NORMALIZED`, so the samples measure the shipped code rather than the candidate transform. The stale-handoff cases are the discriminator: a correct comparator says "in sync" because both representations apply the same TTL, while a true divergence still says "drifted". Control unchanged: the pre-fix comparator (`--broken`, the same normalization without the TTL filter) must fail the claim. Deterministic, offline, stdlib only; no network, no signing dependency, no temp path in the samples.
- **Sample Size n:** 12 checks
- **Census:** The twelve cases are the same enumeration E-117 used: four states that must read in sync (empty board, fresh handoff, stale handoff alone, stale handoff beside a key both representations carry) and eight states that must read drifted (a snapshot-only key, a snapshot-only fresh alert, a snapshot-only stale session alert, a snapshot-only link, a snapshot-only stale handoff, a fresh handoff missing from the snapshot, a retired stale handoff that both sides TTL-prune, and a stale handoff plus a replay-only key). They are the surface itself, not a sample drawn from a larger one; no sampling inference applies, and the control still has to fail the claim.
- **Code Scope:** hooks/engine/modules/blackboard_diagnostics.py, scripts/bench/bench_board_drift.py
- **Lineage:** E-117 (the decision this record re-anchors), E-115 (the landed-tree re-anchor idiom this follows), E-113 (the census framing and `--broken` control shape), E-053 (the freshness plane whose STALE verdict is the signal here)
