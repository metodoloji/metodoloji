## Experiment: E-071 — A forced completion records that it was forced

- **Date:** 17.10.2026
- **Status:** completed
- **Theory:** E-070 measured the kernel recording a claim it never established: `--force` accepted a stage whose evidence did not hold, and `witness_for` then derived a witness from the SPEC, so the record looked exactly like a satisfied one. The plane re-derived a verdict from it and produced one of two lies — STALE (blaming the workspace for the kernel's own claim, and entering `stale_evidence`, which refused the next advance until the operator forced that one too) or CURRENT (vouching that a command passed against this code state when its argv exited 3). The fix is to make the record say what happened: a completion accepted only because `--force` asked for it marks its witness `forced`, with the refusal detail that force overrode, and `classify` answers UNKNOWN before it looks at any predicate — naming the force and the reason, and naming the remedy (`re-complete the stage on real evidence to date it`). UNKNOWN is already the plane's third value for "cannot establish" (an unreadable artifact, an undatable command), and it never blocks; so forcing a stage stops being a trap and stops being a reassurance, and becomes what it is — a known gap in the run's foundation that the operator can close by producing the evidence later. The gate is untouched: unsatisfied evidence is still refused without `--force`, and a genuine completion still reads CURRENT (the paired control), because the marker is written only where the marker is true.
- **Hypothesis:** H-071: "forced_claim_rate <= 0.0"
- **Measurement Metrics:** forced_claim_rate <= 0.0 (with `forced_control_rate <= 0.0` carried as the paired control — a genuine completion must still answer CURRENT on every surface, and the same unsatisfied evidence must still be refused without `--force` — parsed from the same bench output)
- **Experiment Design:** The SAME bench, fixtures and detector as the E-070 baseline — `scripts/bench/bench_workflow_evidence.py` — with the only difference being what a forced completion records. Every earlier bucket is re-measured in the same run (delivery 12+12, read budget 6, artifact escape 9+3, storage 6+3, command 6+3, declared artifact 6+3+2, name question 2+2). Controls: `forced_control_rate` fails a "turn every completion into UNKNOWN" non-fix (the same fixture completed on real evidence must still read CURRENT, and the unforced attempt must still be refused), `false_alarm_rate` and the two other controls stay 0.0. `--baseline` strips the forced marker from the recorded witness — the state the unfixed tree wrote — and classifies it with the same code, so the recorded red is the old record rather than a model of old delivery. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
- **Sample Size n:** 6 (two shapes × three read surfaces; the control's 4 trials are scored separately and the gate parses each denominator from the bench output)
