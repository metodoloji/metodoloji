## Experiment: E-102 — The judge must catch the rules the document never states

- **Date:** 02.11.2026
- **Status:** completed
- **Theory:** E-101 measured a 14-case set and approved the judge at 28 verdicts, then the first real training run over that set promoted nothing: every candidate tied the incumbent on validation. Measuring the incumbent across all 14 cases explained why — 13 of 14 already passed, so there was no gradient to descend. Probing the document for behaviour it never states found the gap the case set was blind to: `SKILL.md` describes the gate's verdict and token but never the **gate key's lifecycle**. Asked how to get a key on a new machine, the skill answered "there is no separate gate key to obtain, the token is generated by the gate itself" — confidently wrong, because `run_experiment.py --init-secret` creates `~/.bmad/gate-key` and `--import-key` puts a peer's key in the trust ring. A case set that omits a rule cannot train it, and a judge that never sees the wrong answer cannot prove it would have caught it. The theory under test is that the case set must include the document's unstated behaviour, and that the judge separates a compliant answer from the wrong answer on every one of those cases.
- **Hypothesis:** H-102: "training_accuracy >= 0.90"
- **Measurement Metrics:** training_accuracy >= 0.90
- **Experiment Design:** Measure `scripts/bench/bench_skill_training.py --samples docs/experiments/E-102/raw/samples.jsonl` over the expanded `evals/training-cases.jsonl`: 17 cases × 2 answers = 34 verdicts. Three cases are new and each was first observed as a real failure of the incumbent against a live model (`Beam-1.0-501B-A23B`, 8192 completion budget): the key bootstrap (`--init-secret`), the cross-machine trust ring (`--import-key`), and the set of gate-written record fields. The first two are assigned explicitly to the training and validation splits (`split` fields) so the training run can both learn from one and be measured on the other. Each verdict is `ok` when the judge's decision equals the expected one — compliant answer passes, forbidden answer fails. The control substitutes a judge that accepts everything, so the same 34 assertions run against the failure mode the bench exists to catch. Deterministic, offline, stdlib only; the bench writes one JSON object per verdict and accepts a `--samples` path so a record owns its own evidence file (an earlier run overwrote E-101's, which the truncation check caught: the first 28 lines reproduce E-101's recorded sha256 exactly).
- **Sample Size n:** 34 verdicts (17 cases × 2 answers), recomputed by the gate from the sample file
