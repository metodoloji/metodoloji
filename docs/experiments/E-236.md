## Experiment: E-236 — Every chain-advancing skill advances only after its record is approved

- **Date:** 2026-11-23
- **Status:** completed
- **Record Kind:** contract
- **Theory:** Measured on this tree 2026-11-23: an audit of 116 CLI invocations across the eight chain-active skills found every script, subcommand and option real (0 rejected), so the surfaces are not describing a CLI that does not exist. The defects are ordering and capability use. (1) bmad-code-review and bmad-quality-record place the workflow.py complete --stage quality-review instruction in activation_steps_append before the step that authors the QR, and neither says to wait for Status: APPROVED; read in order, the advance fires when no QR exists and is refused, and nothing returns to it. bmad-check-implementation-readiness and bmad-sprint-planning have the same physical order (KERNEL before BRIDGE), though their wording is conditional. (2) skills/bmad-workflow/running.md says a blocked run must be recorded with workflow.py block rather than silently abandoned, yet no chain skill calls block when a QR is REJECTED or a PR is WAITING, and none names resume as the recovery. (3) bmad-quality-record extracts the 'Epic reference (E-id)' while E-XXX is the experiment namespace, inviting the epic and experiment ids to be conflated. The class is an instruction that names a kernel capability but cannot execute it where it is read.
- **Hypothesis:** H-236: "chain_skill_contract_accuracy == 1.0"
- **Measurement Metrics:** chain_skill_contract_accuracy == 1.0
- **Experiment Design:** Inputs: the eight chain-active skill surfaces (SKILL.md + customize.toml) and the builtin chain spec. Procedure: bench_chain_skill_contract enumerates nine probes: the three same-file advance steps come after their record-authoring step (code-review, IR, SP); the two QR-owner advance steps are explicitly gated on APPROVED (code-review, quality-record); the QR REJECTED branch records a kernel block; the PR WAITING branch records a kernel block; the recovery path names workflow.py resume; and the QR workflow no longer labels the epic reference E-id. Control: --broken runs the same probes against the unmodified HEAD tree extracted with git archive, where all nine are false.
