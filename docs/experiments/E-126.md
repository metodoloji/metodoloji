## Experiment: E-126 — The release step's own interpreter and refusal paths

- **Date:** 2026-11-12
- **Status:** completed
- **Record Kind:** contract
- **Theory:** E-124 scoped the checker and E-125 hardened the board; the release step itself was never exercised against a host that lacks a bare python. The step derives every number with python scripts/versioning.py, so on a python3-only host --is-auto fails for the wrong reason and the else branch reads the tree as a DECLARED line: position 100 (0.2.0) is refused as 'never declared' and the release is never tagged. The same substitution kills the job with an empty log when the manifest carries no version line (set -e + pipefail inside the command substitution), and any unparseable version reads as a declared line rather than a refusal.
- **Hypothesis:** H-126: "release_step_contract_accuracy == 1.0"

- **Experiment Design:** Inputs: the four closed cases in scripts/bench/bench_release_step_contract.py, each driving the REAL step body extracted from .github/workflows/release-numbers.yml (the release-test harness, not a reimplementation). Procedure: run the step against throwaway repositories with a real remote — an ordinary positional release, a block-boundary release at position 100, and a commit whose manifest has no version line — and assert on its exit code, its tags and its output. Control: --broken swaps in the pre-fix step body (bare python, no empty-version guard), so rule 7 can see the bench tell them apart. Reproducibility: stdlib + git only, temp dirs, no network.
