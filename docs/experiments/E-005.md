## Experiment: E-005 — Make the workflow kernel and the blackboard CLI behave with the honesty and root discipline the engine already owns

- **Date:** 07.10.2026
- **Status:** completed
- **Theory:** The engine already owns two honest behaviours this project cares about as
  its own invariants: (1) the engine resolves project root as
  CLAUDE_PROJECT_DIR > OPENHANDS_PROJECT_DIR > cwd (repo_root), so that a CLI
  invoked in a hook session never silently touches the wrong tree; (2) a read
  that cannot be satisfied returns a distinct honest signal rather than failing
  open silently. Behavior probing of the *other* production CLIs found both of
  those taken for granted where they should have been:
  - `bmad/scripts/blackboard.py` resolves the root with `os.getcwd()` only and
    ignored CLAUDE_PROJECT_DIR — so a CLI run from the plugin tree under a hook
    context read the PLUGIN repo's board, not the project's; probe proved that
    CLAUDE_PROJECT_DIR now honors.
  - `bmad/workflow/engine.py` + `bmad/workflow/store.py` let a corrupt state
    file masquerade as a real, if empty, run: `list_runs()` emitted a row of
    nulls and `status`/`next`/`history` said `no workflow 'slug'`. The fail-open
    `read_state() -> {}` is the storage contract (documented, tested) and stays;
    the ENGINE layer must not collapse "missing" and "unreadable" into one
    silent empty.
- **Hypothesis:** H-005: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
