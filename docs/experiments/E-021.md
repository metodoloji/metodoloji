## Experiment: E-021 — Every producer's record path must be audited, not 7 of 17

- **Date:** 10.10.2026
- **Status:** completed
- **Theory:** `check-plugin.sh` §2 does two jobs for the bridge: it demands the
  `dev-skill-to-methodology-bridge` reference and it demands the *record path*
  (`docs/development/stories/`, `docs/quality/QR`, `docs/development/`) on each
  entry of `BRIDGE_SKILLS` — the guarantee that a producer's BRIDGE still points
  at the record it claims to create. That dict listed 7 skills, so 10 of the 17
  producers GUIDE.md names were never checked: every gds producer, both
  gds-agent personas, the wds agentic-development surface, and the bmad agent
  persona. A behavior probe confirms the split (7 audited / 10 unaudited) and
  also confirms all 17 TOMLs currently do carry their record path, so widening
  costs nothing today while closing the hole. The root cause is the same class
  E-018/E-019/E-020 named — an audit is only as wide as its hardcoded tuple —
  and the fix is the same shape: extend the dict to the full documented set and
  pin the keys to GUIDE.md's producer list with a bench check, so the target
  audit cannot silently narrow back. Taken with E-018 (producer VERIFY) and
  E-020 (feeder QR target) it closes the record-wiring trio — the three
  hardcoded lists that decide whether a BRIDGE surface is checked at all
  (the narrower layer/depth sets of check-custom §3/§4 and QR_FEEDERS_SKILLMD
  remain, see Known Gaps).
- **Hypothesis:** H-021: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-021 claim (it parses
  GUIDE.md's `Producer (N, creates/updates records)` line, parses §2's
  `BRIDGE_SKILLS` dict out of `check-plugin.sh`, demands the two sets are equal,
  and re-checks the bridge reference plus the record target on each producer
  TOML), plus the regression tests by name. Control — the bench's own "pytest
  suite green (falsifier)" check pins that the code under test still passes the
  full suite, which now includes two new tests in
  `scripts/tests/test_selfcheck_scripts.py` (the bench check returns `None` on
  this tree; §2's dict is asserted to contain the previously-unaudited
  producers). The probe is falsifiable by construction: deleting the
  `bmad-agent-dev` entry from `BRIDGE_SKILLS` turns the new bench check red
  (`§2 BRIDGE_SKILLS != GUIDE producers (missing ['bmad-agent-dev'])`), and §2
  itself reports `checked surfaces: 123 / problems: 0` with the widened dict.
  Reproducibility — stdlib only, no network, deterministic: the check reads the
  tree and script as they are, and a fixed tree yields a fixed x/y; the
  measurement reports the tree as it is, independent of this record (E-001).
- **Sample Size n:** 81 (informational — the gate parses the denominator from
  the bench output; the count grows from 80 with the one added E-021 check)
- **Code Scope:** scripts/check-plugin.sh, scripts/bench/bench_consistency.py, scripts/tests/test_selfcheck_scripts.py
- **Raw Results:** measured=1.0; n=81
- **Uncertainty:** none (n=81, 95% Wilson lower bound 0.95 >= threshold 0.9)
