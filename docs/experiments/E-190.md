## Experiment: E-190 — Every plan surface is one shipped path, and each is measured through itself

- **Date:** 21.11.2026
- **Status:** completed

- **Theory:** Found on this tree, 2026-11-21, re-reading the record approved minutes earlier: modules/plan.py exported progress_line under a comment naming it the 'Stop-report hook surface', but no shipped path ever called it — the real Stop note (stop._plan_progress_note) formats through open_plan_line, the same function the SessionStart clause and the digest use. E-189's bench probe 'stop_report_keeps_counts' drove exactly that dead function and reported PASS, so the record's Census sentence ('one asserts the Stop report still counts a decided record's plan') was false about the shipped surface: with E-189 applied, the real note is '' for a decided record while the dead formatter still printed 'plan progress: 1/2 planned files on disk (1 pending)'. A second defect surfaced while the new bench was written: active_plan_for prefers the NARROWEST covering plan, so a completed program's one-file plan beat an open operation's plan on the same file and E-189's filter then silenced the note entirely — the open operation covering the file was reported as nothing. That is the reachability rule (E-154) turned on a measurement and on a formatter: a probe that reaches no shipped path cannot report on one, and a decided plan must not shadow an open one.
