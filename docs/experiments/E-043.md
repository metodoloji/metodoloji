## Experiment: E-043 — The change radar was documented, not measured: the runbooks drifted from the skills on the very commit that documented the radar

- **Date:** 14.10.2026
- **Status:** completed
- **Theory:** The last blackboard commit (cc5a02c, "Extend blackboard integration with graph edges and change radar") shipped three things at once: the §14 change-radar bullet in GUIDE/KILAVUZ (which skills watch which upstream patterns, on which channel), the skills' `subscribe` lines, and a handoff-lint entry (`EXPECTED_SUBSCRIPTIONS`) meant to keep them honest. The lint checked only that the line `subscribe --watcher <self>` existed — the watcher NAME, not the pattern or the channel — so it printed `[OK] bmad-spec: watches upstream` while the documented radar claimed a `prd.*` watch the skill did not ship. A name-only check cannot see a wrong pattern, and nothing checked the runbooks at all, so the doc and the skills drifted on the same commit: measured against the tree, the §14 bullet claimed `bmad-spec` watches `architecture.*,prd.*` (shipped: `architecture.*` only), summarised "story/dev watches `epics.*,story.*`" (shipped: create-story `epics.*,SP-*`, dev-story `story.*`), asserted "all on the `session` channel" (two skills — quality-record and production-readiness — subscribe on `stop`), and omitted four subscribing skills entirely (sprint-planning `IR-*`, quality-record `story.*`, production-readiness `QR-*`, research-experiment `retro.*`). One gap is a real behaviour defect, not just prose: bmad-spec's own handshake text names `bmad-prd` as a typical upstream ("an upstream run (typically `bmad-prd` or `bmad-architecture`)"), so a mid-run PRD change must surface on the radar — the skill shipped only the `architecture.*` watch. The class is the project's recurring one (E-037): an artifact asserting a fact nobody measured. The closure makes the radar a single declared, mechanically-checked contract — the skills must carry the exact (pattern, channel) set (lint), and the runbooks must enumerate exactly the radar the skills ship (a bench check derived from the tree, the E-039 doctrine).
- **Hypothesis:** H-043: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure — run `python scripts/bench/bench_consistency.py`; the new check `_check_change_radar_contract_matches` derives the shipped radar from every `skills/*/SKILL.md` (`subscribe --watcher W --pattern "P" --channel C`), then requires each runbook's change-radar bullet (anchored on its marker phrase) to enumerate exactly that skill→(pattern, channel) table — both directions, so a missing skill and a phantom skill both fail. Controls — the falsifier ran red BEFORE the fix: the new check reported the bullet omitting all ten subscribed skills on the pre-fix tree (proven directly through `_check_change_radar_contract_matches()`), and the strengthened lint's new unit test drives a right-watcher/wrong-pattern, a right-pattern/wrong-channel and a foreign-watcher skill red, each green only on the exact contract. Reproducibility — stdlib only, no network, deterministic (pure text plus one regex derivation).
- **Sample Size n:** 99 (informational — the gate parses the denominator from the bench output; the count grows by the one added E-043 check)
