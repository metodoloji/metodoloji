## Experiment: E-192 — Bound the stop channel's alert preview with the shared cutter

- **Date:** 21.11.2026
- **Status:** completed
- **Record Kind:** contract
- **Theory:** Found live on this tree, 2026-11-21, by posting an alert and letting the Stop hook report it: 'routed alert(s) on the stop channel: release run finished and the report is ready: notes/segment/…/no — clear with …'. The alert text was sliced at exactly 160 characters with NO marker at all: the reader cannot tell it was shortened, a path stops mid-name so it cannot be opened, and a gate token near the boundary would arrive as a fragment that reads whole. This is the sibling of E-187/E-191 on the surface that ends a session, and it is worse than those because the chop is silent rather than marked. The engine already owns the right cutter (utils.brief_text: cut on the last boundary that fits, drop an unclosed bracket group whole, mark the elision); the stop note simply was not using it.
- **Hypothesis:** H-192: "stop_alert_bound_accuracy == 1.0"
- **Measurement Metrics:** stop_alert_bound_accuracy == 1.0
- **Experiment Design:** Inputs: throwaway project trees carrying alerts posted on the stop channel — a long baton whose gate token starts past the 160-char boundary, a short baton, a two-alert queue, and batons whose cut would fall inside an unclosed bracket. Procedure: scripts/bench/bench_stop_alert_bound.py runs ten probes through the shipped stop() report — the token is never present in half, the elision is marked and the preview differs from a raw 160-char slice, the cut lands on a boundary character of the original text, a short baton prints verbatim, the preview stays inside the bound, the unit-named (+N more alerts) tail survives, an unclosed bracket group is dropped whole, a long path run is dropped whole rather than maimed, Stop still returns allow, and the preview equals utils.brief_text(text, 160). Control: --broken runs the same probes against the pre-change tree at git 0953f6b, whose preview is text[:160]. Reproducibility: stdlib plus git only, offline, deterministic; each probe gets a fresh tree and its own process.

- **Known Gaps:** The bound still costs one character past the limit when no boundary exists inside it (a single giant token prints 160 chars plus `…`). When a long run of non-space text sits before the limit (a path with no spaces), the boundary rule drops that run whole — the preview can therefore show much less than 160 characters, and the full alert is only available through `blackboard.py alerts`/`consume`, which the note names. Only the FIRST alert is previewed; the `(+N more alert(s))` tail names the count, not the others' text (unchanged behaviour). Other fixed-offset cuts in the engine were not re-measured here, e.g. guard's task-text `[:60]...` and chain-gate's `out[:300]`; those are separate surfaces and get their own record if they matter.
