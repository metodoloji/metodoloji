## Experiment: E-033 — A command the engine prints into the session must exist: the hand-off nudge named a bare subcommand

- **Date:** 12.10.2026
- **Status:** completed
- **Theory:** A real Claude Code session (muse-spark-1.3-contributor-free,
  0.1.28) opened its first tool call with `handoffs --skill bmad-quality-record`
  and the shell answered verbatim: `(eval):1: command not found: handoffs`. That
  command was not invented by the model — it is copied from the engine's own
  SessionStart context, which injects "…peek `handoffs --skill {s}`, then consume
  its handoff channel" (audit.py `session_start` → `pending_handoff_channels`).
  Two things are wrong with it: `handoffs` is not a program at all, it is a
  SUBCOMMAND of the plugin's `blackboard.py`, and the plugin tree is not on the
  operator's PATH. So the proactive nudge — the engine telling the operator how
  to pick up a waiting baton — instructs a command that cannot run, and the
  observed session lost turns to the dead end. Reading the tree shows the same
  shape on four more injected surfaces: the stop report
  ("peek `handoffs --skill <self>`", "clear with `blackboard.py consume --channel
  stop`"), the mid-session mirror note ("peek `handoffs --skill <skill>`"), the
  SessionStart plan line ("extend an operation's plan with run_experiment.py
  --amend-plan"), and the blackboard CLI's own rotation hint ("archive history
  with `blackboard.py rotate`"). This is the E-029 class — a remedy exists only
  where its wiring is — on the one surface E-029 did not reach: the commands the
  ENGINE prints, rather than the commands the gate's deny messages carry. The fix
  puts one anchored-command helper (`utils.plugin_script_cmd`, the same root
  `guard._plugin_script_cmd` already used) behind every injected command and names
  the real entry point (`blackboard.py handoffs --skill …`, `blackboard.py consume
  --channel …`, `run_experiment.py --amend-plan`).
- **Hypothesis:** H-033: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-033 claim (it posts a
  real waiting hand-off to a temp project's board, drives the real
  `session_start`, and demands the injected context name the plugin-rooted
  `blackboard.py handoffs --skill …` and never a bare subcommand; it then walks
  the STRING constants of `audit.py`, `stop.py`, `mirror.py` and `blackboard.py`
  via `ast` — comments and docstrings that no longer present a command are not
  flagged — and fails on any backtick-quoted bare plugin subcommand), plus the
  regression test by name. Control — the bench's own "pytest suite green
  (falsifier)" check pins that the code under test still passes the full suite,
  which now includes
  `test_session_start_handoff_nudge_names_a_runnable_command`, and the existing
  E-029 tests keep `guard._plugin_script_cmd` (now delegating to the shared
  helper) honest. The probe is falsifiable by construction: restoring the bare
  `` `handoffs --skill {s}` `` nudge turns the bench check red twice over
  (`hand-off nudge does not name the runnable command: …eek \`handoffs --skill
  bmad-quality-record\`…; hooks/engine/modules/audit.py: a printed remedy names a
  bare plugin subcommand: …`). Reproducibility — stdlib only, no network,
  deterministic: the check drives the engine module and parses the sources as
  they are; a fixed tree yields a fixed x/y; the measurement reports the tree as
  it is, independent of this record (E-001).
