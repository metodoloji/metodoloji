## Experiment: E-164 — The plugin audit passes on a fresh clone, where no gate key exists

- **Date:** 2026-11-15
- **Status:** completed
- **Record Kind:** contract
- **Theory:** Measured 2026-11-15 on this tree: .github/workflows/quality.yml runs `sh scripts/check-plugin.sh` on every pull request, and that audit exited 1 on any machine without a gate key. Two independent causes, both structural. (1) §0 made a missing key a hard ERROR, but the HMAC key lives OUTSIDE the repo (~/.bmad/gate-key), so no fresh clone and no CI runner can have one; every approved record then reads UNVERIFIABLE, which the audit's own header already declares a WARNING class. (2) §3b builds its approved-scope union from records that VERIFY under this machine's ring; with no key no record verifies, the union is empty, and a genuinely-approved file (conftest.py, in E-146's scope) reads as 'outside every approved Code Scope' — the section reported the absence of an operator secret as a scope violation. Both made the CI audit step unconditionally red for reasons no contributor could fix from the tree. E-157 measured this exact defect class on the tag bench: an instrument that goes red on every run measures the environment, not the claim.
- **Hypothesis:** H-164: "keyless_audit_accuracy == 1.0"
- **Measurement Metrics:** keyless_audit_accuracy == 1.0
- **Experiment Design:** Inputs: the plugin tree at this commit plus the pre-repair tree at PREFIX_REV (e18a677), each audited under a HOME with no .bmad directory — exactly what a CI runner has. Procedure: scripts/bench/bench_keyless_audit.py asserts four properties. (1) A missing key warns and does not count as a problem by default; under --strict-keys it stays fatal. (2) §3b announces itself unmeasured when no record can verify, and names no MISS. (3) The audit exits 0 with no key — the CI condition itself. (4) The audit still exits 0 with a key present and §3b still runs, so the guard disabled the section rather than fixing it. The repair makes the missing-key branch warn unless --strict-keys is set, and wraps §3b in the same guard so it reports itself unmeasured instead of inventing violations. Control: --broken evaluates PREFIX_REV, where probes 1 and 2 fail and therefore 3 and 4 do too. Reproducibility: stdlib + git + sh, offline, deterministic.

- **Known Gaps:** (1) The guard makes §3b UNMEASURED on a keyless machine, so a real scope violation committed by a contributor whose CI runs without a key would not be caught there. That is the honest trade: the section cannot distinguish 'no record approves this file' from 'no record can be verified here', and inventing the former was the defect. A release job that must enforce scope coverage runs with --strict-keys and a key. (2) The same reasoning applies to §3's record verdicts: they already warn rather than fail without a key, which this record leaves as it was. (3) The missing-key warning is printed once per audit run, not per record; a keyless run still lists each UNVERIFIABLE record as a WARN, so the volume is unchanged. (4) This record does not add a key to CI as a secret: the gate key is an approval-signing key, and putting it in a runner would let any PR sign its own approvals. The audit is designed to be useful without one, which is what this fix restores. (5) Probes 1-4 shell the real audit three times, so the bench costs ~30 s; it is inside the runner's 900 s per-bench ceiling.
