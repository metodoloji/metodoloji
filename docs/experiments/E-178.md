## Experiment: E-178 — The audit classifier walks the whole harness envelope

- **Date:** 2026-11-17
- **Status:** completed
- **Record Kind:** contract
- **Theory:** E-177 bounded the failure classifier to the harness envelope instead of the whole payload, but the envelope is not always flat: this checkout's own trail (2026-11-17) carries a real terminal row whose tool_response is {'output': {'exit': 0, 'truncated': False, 'output': '/bin/bash: line 1: rg: command not found'}, 'status': 'ok'}. The flat extractor reads only top-level stream keys, then falls back to top-level strings, so it returns the word 'ok' and the real command-not-found is lost — a silent miss replacing a correct row. A second adapter shape (a nested result/stdout envelope) is one wrapper away. The defect is structural: output can live at any depth inside the envelope, metadata sits at every level, and an extractor that assumes one layout trades false positives for silent misses.
- **Hypothesis:** H-178: "audit_envelope_accuracy == 1.0"
- **Measurement Metrics:** audit_envelope_accuracy == 1.0
- **Experiment Design:** Inputs: the shipped engine module hooks/engine/modules/audit.py and the pre-E-177 tree at git 205fa6d. Procedure: scripts/bench/bench_audit_output_shapes.py runs twelve probes in their own process against the tree under test: flat strings, flat stdout/stderr mappings, the nested OpenCode-shaped output envelope recorded in this checkout, a nested result/stdout envelope, nested metadata-only payloads, list-shaped output, a bounded-depth payload, and two end-to-end audit() calls that decide whether a trail row is written. Control: --broken runs the same probes against 205fa6d, whose classifier stringifies the envelope and reports the harness label as an abort. Reproducibility: stdlib only, offline, deterministic (git archive prefix tree; no network, no clock dependence).
