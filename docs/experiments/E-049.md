## Experiment: E-049 — The documented audit inventory was hand-maintained in three docs, and four independent drifts were live: an unlisted audit, a range one section short, two stale maps and a suite size stale by 112

- **Date:** 15.10.2026
- **Status:** completed
- **Theory:** The audit family and its sections are both derivable from the tree — `scripts/check-*` is the family, and each script's `== N)` headers are its sections — but three reader-facing docs restate them by hand: five runnable blocks (README's "Verify your install", GUIDE's and KILAVUZ's Step 6, GUIDE's and KILAVUZ's §16), nine `#0–#6N` range claims, two `# map:` lines, four count sentences and three suite-size claims. Nothing measured any of it, and four independent drifts were live when this rule was written (measured 2026-10-15, before the repair): (1) the blocks omitted `check-triggers.py` — it ships, runs as §6f inside check-plugin.sh and is directly runnable, but README's block named five audits, GUIDE/KILAVUZ's Step-6 blocks three, and the §16 blocks five; (2) five `#0–#6f` claims called the plugin audit a full range while its last section is `#6g` (the tool-contract commit 3648e29 added `#6g` and nothing updated the docs that quote the range); (3) both `# map:` lines listed 22 section ids and omitted `#6g`; (4) the count sentences — README's "The six checks stay local" and "the six checks above", GUIDE's "run the 6 checks locally (pytest + 4 static checks + handoff lint)", KILAVUZ's "6 kontrolü yerelde koş (pytest + 4 statik check + handoff lint)" — describe a family of seven (6 audits + pytest), and the parentheticals add up to 6. A fifth claim surfaced in the same block: README stated "1,331 tests" while the suite collects 1,443, stale by 112 with nothing noticing. The class is the project's recurring one (E-037): an artifact asserting a fact nobody measured — here a documented inventory, drifting in four directions at once because every part of it was maintained by hand. The closure derives both sets from the tree and requires every claim in the inventory to agree, including the suite size (collected, never copied).
- **Hypothesis:** H-049: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure — run `python scripts/bench/bench_consistency.py`; two new checks. `_check_audit_inventory_matches_the_shipped_one` derives the audit family from `scripts/check-*` and each script's `== N)` section ids, then requires: (a) every anchored runnable block to name exactly that family (no omitted audit, no audit that does not ship); (b) every `#A–#B` claim to equal the span of the script it belongs to, where the owner is the nearest audit script name before the claim on the same line, else a name within three lines; (c) every `# map:` to equal some shipped script's section set exactly (a map is anchored by its content, not by the file's nearest script name); (d) every count sentence to equal the family plus one, and every spelled-out split (`pytest + N static checks + handoff lint`, both languages) to add up to the same number. `_check_documented_test_count_is_honest` collects the suite (`pytest --collect-only`, 1.3s) and requires each verify block's `# N tests` claim either to match the collected count exactly or to be a floor that does not exceed it. Controls — the falsifier ran red BEFORE the repair, on 18 claims across the three docs, and green after; the strict `#<digit>…–#<digit>` pattern was itself measured against the false-positive traps in these docs (markdown slugs like `(#0-how` and prose like `#8 — run`) and rejects them, so the rule does not cry wolf on anchors. Reproducibility — stdlib plus one pytest collection, no network, deterministic.
