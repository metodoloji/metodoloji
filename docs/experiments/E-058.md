## Experiment: E-058 — Put the derived verdict on the inventory surface, and give the re-derivation a read budget

- **Date:** 17.10.2026
- **Status:** completed
- **Theory:** E-057 measured two holes in the workflow evidence plane on the unfixed kernel: the inventory surface (`list` — where an operator picks the run to continue) carried no verdict at all, so a run whose completed stage no longer holds its evidence was listed exactly like a healthy one; and the re-derivation read was unbounded (whole-file `read_text` per candidate, every glob match scanned) while it runs on the SESSION EDGE, because the advisory is computed at SessionStart. Both are closed by the doctrine the board plane already follows: the verdict is DERIVED on every read and lives on every surface, and a read that cannot be afforded answers UNKNOWN with the reason instead of a guess (`[freshness] max_digest_files`, E-053 §5.5). The bound is deliberately asymmetric: a POSITIVE answer stays exact (a match found inside the budget really is a match), so the budget can never invent a STALE; only the negative side degrades to UNKNOWN. The COMPLETION path stays unbounded, because accepting a stage reads the artifact the operator just produced — once — which is the price of accepting the work.
- **Hypothesis:** H-058: "stale_evidence_rate <= 0.0"
- **Measurement Metrics:** stale_evidence_rate <= 0.0 (with `unbounded_read_rate <= 0.0` carried as the read-budget threshold and false_alarm_rate as the paired control, all three parsed from the same bench output)
- **Experiment Design:** The SAME bench, oracle and fixture families as the E-057 baseline — `scripts/bench/bench_workflow_evidence.py` drives a throwaway project per trial through the kernel's public API and probes three read surfaces (peek, computed next step, inventory); delivery bucket 8 fixtures x 3 surfaces (12 stale + 12 current), read-budget bucket 2 past-bound fixtures x 3 surfaces (6 trials), with the oracle (`pathlib.glob` + `str.count`) computing every delivery expectation and never importing the module under test. The only difference from the baseline is WHAT the surfaces deliver: the inventory now carries the same derived per-stage verdict map as the other two, and a past-bound artifact answers UNKNOWN with the reason instead of being read whole. Controls unchanged: the expectation vector (`trials: stale=12 current=12 unbounded=6`) fails a fixture that stopped producing both classes, `false_alarm_rate` fails a "mark everything UNKNOWN" non-fix (a satisfied, in-budget artifact must stay CURRENT), and `--baseline` reproduces the pre-fix delivery semantics and must return 1.0 — the bench is its own negative test on the fixed tree. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
- **Sample Size n:** 30 (12 stale + 12 current + 6 past-bound trials; the gate parses the denominators from the bench output)
