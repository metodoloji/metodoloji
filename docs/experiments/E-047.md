## Experiment: E-047 — The skeleton contract was declared in four places and only two legs were pinned: any of the copies could drift silently

- **Date:** 15.10.2026
- **Status:** completed
- **Theory:** The record-skeleton contract (`/metodoloji:init`) is stated in four shipped places, and only one of them is an owner. `bmad/scripts/skeleton.py` declares `DIRECTORIES` / `TEMPLATE_PAIRS` / `SKELETON_PROBES`; `commands/init.md` lists the same nine directories and the same eleven `templates/<src>` → `<dest>` rows and tells the reader the runbook and the script "can never drift"; `hooks/scripts/bootstrap.sh` probes the same three template paths at every SessionStart ("keep the two in step"); `scripts/check-plugin.sh` §6d carried a literal third copy of the probe set under a comment that still counted "the same two template paths". skeleton.py's own header repeated the request ("Keep the three in step") and nothing measured it — `SKELETON_PROBES` was referenced only inside skeleton.py and its own test, and `commands/init.md` was audited by nothing at all (bench `_check_documented_commands` only matches `sh|bash|python3 <path>.sh|py` lines, and §6d2 only checks that a named `bmad/scripts/*.py` exists). Measured 2026-10-15, running the new rule against the shipped tree reported the live drift immediately: §6d carried a second copy of the probe set (all three paths), while the runbook and the bootstrap probe happened to still agree — i.e. two of the four sites were in step by hand, not by construction. Drift there is silent by construction and lands exactly where a user looks: a probe set that gains a path in skeleton.py leaves the SessionStart hint advertising a FULL init on a project whose (new) skeleton exists, and leaves §6d reporting ERROR on a healthy skeleton that lacks the old trio — the mailjs 2026-09-23 "skeleton present but no marker" shape (the incident SKELETON_PROBES and §6d were written for) one level up. The class is the project's recurring one (E-037): an artifact asserting a fact nobody measured — here three artifacts asserting the installer's contract. The closure makes skeleton.py the single vocabulary (`declaration_problems()`), gives it a CLI (`--probe-paths`, `--audit-declarations`), makes §6d derive the probe set instead of restating it and run the audit, and drives every remaining restatement — the runbook's directory list and template table, the session-start probe loop, and §6d itself — through the rule on a mutated copy, so each drifted site must be rejected BY NAME.
- **Hypothesis:** H-047: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure — run `python scripts/bench/bench_consistency.py`; the new check `_check_skeleton_contract_declarations_agree` loads `bmad/scripts/skeleton.py`, demands the shipped tree is clean, drives the real `--audit-declarations` CLI on the shipped tree (exit 0) and `--probe-paths` (the printed set must equal `SKELETON_PROBES`), pins that `scripts/check-plugin.sh` §6d actually invokes the audit (a rule nobody runs is dead code) and that `bmad/tests/test_skeleton.py` holds both new falsifier tests, then rebuilds the declaration sites in a temp tree and mutates one at a time — a dropped directory bullet and a moved template destination in the init runbook, a narrowed probe set in the bootstrap probe, a restated probe set and an unhooked audit in §6d — requiring the copied script's CLI to exit 1 and to name the drifted file each time. Controls — the falsifier ran red BEFORE the fix: the rule reported §6d's duplicate probe set (and §6d's stale "two template paths" comment) on the shipped tree while the runbook and the bootstrap probe were in step, and each of the five mutations is rejected by name after the fix; the healthy tree and the healthy temp copy both exit 0. Reproducibility — stdlib only, no network, deterministic (three file reads plus five subprocess runs).
