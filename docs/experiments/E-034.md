## Experiment: E-034 — The command the gate documents must be a command the gate accepts: `--verify <rec>` died on argparse

- **Date:** 12.10.2026
- **Status:** completed
- **Theory:** While closing E-033 (the engine's injected nudges named a bare
  `handoffs` subcommand that does not exist) the gate was verified the way its
  own module docstring teaches: `run_experiment.py --verify
  docs/experiments/E-033.md`. That exited **2** with
  `run_experiment.py: error: unrecognized arguments: docs/experiments/E-033.md`
  — `--verify` is a `store_true` flag and the record is a separate `--record`
  argument, so the advertised form cannot run. The correct form
  (`--verify --record <rec>`) is what the runbooks already print, which is why
  the stale docstring survived: nothing read the gate's OWN usage text as a
  claim. This is E-029/E-033's class — a printed instruction that cannot be
  executed where it is printed — on the one surface those experiments did not
  scan: the module docstring an agent reads to learn the command (E-033's scan
  covers the emitted STRING constants of the four nudge modules; the gate's
  docstring is neither an emitted string nor a deny remedy). The fix rewrites
  the two `--verify <rec>` usage lines to the documented, argparse-accepted
  form, and adds a check that extracts EVERY `run_experiment.py <flags>`
  invocation from the source and drives the real gate with exactly that argv, so
  no future doc edit can re-introduce a dead instruction.
- **Hypothesis:** H-034: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-034 claim, and the
  regression test for it lives in `scripts/tests/test_selfcheck_scripts.py`.
  The new check is behavioral, not textual: it regex-extracts each
  ``run_experiment.py <flags>`` line from the source, drops `[optional]` groups
  and trailing prose, substitutes the placeholders (`<rec>`/`E-001.md` → a temp
  record, `<cmd>` → `true`), and runs the REAL gate with that argv (plus
  `--no-blackboard`, so the temp record's derived project root cannot post to
  this repo's board; no flag under test is altered), demanding argparse accept
  the flags — a semantic refusal (undecided record, missing Lineage, no measured
  value) is fine, a parse error is not. It also fails if the usage block shrinks
  below three invocations, so the extraction surface cannot be emptied to make
  the check vacuous. Control — the bench's own "pytest suite green (falsifier)"
  check pins that the code under test still passes the full suite, which now
  includes `test_documented_gate_invocations_parse_under_argparse`, and E-029's
  pilot (`_check_gate_remedy_paths_are_runnable` + `test_no_remedy_uses_a_bare_
  plugin_script_path`) keeps the path form of the same class honest. The probe is
  falsifiable by construction: restoring the stale ``--verify <rec>`` line turns
  the bench red with `documented invocation dies on argparse: `run_experiment.py
  --verify <rec>` -> … error: unrecognized arguments: …` (observed, then
  restored). Reproducibility — stdlib only, no network, deterministic: the check
  drives the gate module on a fixed temp record and reads the source as it is; a
  fixed tree yields a fixed x/y; the measurement reports the tree as it is,
  independent of this record (E-001).
- **Sample Size n:** 94 (informational — the gate parses the denominator from
