## Experiment: E-018 — The producer-VERIFY audit must read every producer BRIDGE surface, including the agent-principles ones

- **Date:** 10.10.2026
- **Status:** completed
- **Theory:** The repo's own promise is explicit and shipped twice: GUIDE.md
  (and KILAVUZ.md) state that a producer BRIDGE carries a **VERIFY** step —
  "the LLM must confirm the file exists with `ls -la` right after creating the
  record (automatic anti-skip check; audit #2c)" — and name the producer set as
  17 skills, three of which (`bmad-agent-dev`, `gds-agent-game-dev`,
  `gds-agent-game-solo-dev`) keep their BRIDGE inside `[agent].principles`
  rather than `workflow.activation_steps_append`. Reading the audit's behavior
  rather than its promise shows the gap: `check-plugin.sh` §2c iterated a
  hardcoded list of 13 skills and read exactly one key,
  `workflow.activation_steps_append`. A behavior probe makes the failure
  concrete: with the VERIFY marker stripped from `bmad-agent-dev.toml`, §2c
  still reported `checked BRIDGE skills: 13 / problems: 0` — a green audit on a
  broken surface. The three agent-principles producers are therefore never
  read (their BRIDGE is not in the key §2c looks at), and
  `wds-5-agentic-development` — a producer named by GUIDE.md — is not in the
  list at all. That is 4 of 17 producers the documented anti-skip audit does
  not actually cover. The root cause is the class E-002/E-017 named: an audit
  is only as wide as its hardcoded tuple, and nothing pins that tuple to the
  surface it claims to guard. The fix widens §2c to the whole producer set with
  a per-surface key map (the same key §2b already uses for agent principles)
  and pins the map to GUIDE.md's documented producer list so a surface cannot
  silently drop out of the audit again.
- **Hypothesis:** H-018: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit.
  Procedure — run `python scripts/bench/bench_consistency.py`, which evaluates
  independent doc/code-consistency claims and prints
  `consistency_accuracy=(x/y)`; one new check pins the E-018 claim (it parses
  GUIDE.md's `Producer (N, creates/updates records)` line, parses §2c's
  `PRODUCER_KEY` map out of `check-plugin.sh`, demands the two sets are equal,
  demands the three agent-principles producers are read from
  `agent.principles` and every other producer from
  `workflow.activation_steps_append`, and re-evaluates the verify-marker
  invariant on each producer TOML), plus the regression tests by name. Control
  — the bench's own "pytest suite green (falsifier)" check pins that the code
  under test still passes the full suite, which now includes two new tests in
  `scripts/tests/test_selfcheck_scripts.py` (the bench check returns `None` on
  this tree; the agent-principles map is asserted directly). The probe is
  falsifiable by construction: stripping the VERIFY marker from
  `bmad-agent-dev.toml` turns the new bench check red
  (`bmad-agent-dev: no verify marker in agent.principles`) and makes §2c report
  `checked BRIDGE skills: 17 / problems: 1` where it used to report 13/0.
  Reproducibility — stdlib only, no network, deterministic: the check reads the
  tree and scripts as they are, and a fixed tree yields a fixed x/y; the
  measurement reports the tree as it is, independent of this record (E-001).
