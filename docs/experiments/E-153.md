## Experiment: E-153 — A check that cannot run is not a failed check

- **Date:** 2026-11-14
- **Status:** completed
- **Record Kind:** contract
- **Theory:** E-090 closed its own record with a Known Gap: the pytest falsifier on the bare PATH. Measured 2026-11-14 on this checkout: python3 scripts/bench/bench_consistency.py reports 5/120 failed, and three of those five disappear when the same bench runs under the project's .venv interpreter (118/120). The three are the falsifier, the documented test count and the registry isolation test — each ran sys.executable -m pytest and got 'No module named pytest', then reported the suite as red. The suite never ran. The fourth is the same shape one language over: the OpenCode bridge suite imports its declared dependency @opencode-ai/plugin, which a Python-only checkout has not installed, so node's ERR_MODULE_NOT_FOUND read as 'the OpenCode suite fails'. Both contradict the rule this repository already states for its own audits — a check that cannot run is worse than one with a stale word list, because it accuses the code of a failure that was never measured. The remaining fifth failure (the release tag chain) is a genuine repo-state failure and is not touched here: repairing it means rewriting published tags.
- **Hypothesis:** H-153: "measurement_integrity_accuracy == 1.0"
- **Measurement Metrics:** measurement_integrity_accuracy == 1.0
- **Experiment Design:** Inputs: the plugin tree at this commit, plus the pre-change tree extracted from PREFIX_REV (ac0c05b) with git archive for the control arm. Procedure: scripts/bench/bench_measurement_integrity.py imports scripts/bench/bench_consistency.py from the tree under test and runs twelve probes, each driving one branch of the decision surface: (1) the pytest resolver ships; (2) it resolves an interpreter that can actually import pytest; (3)-(5) the falsifier, the documented-count check and the registry-isolation check each resolve their interpreter instead of hard-coding sys.executable; (6)-(8) under an environment with no pytest-capable interpreter each of the three reports SKIP naming pytest, not FAIL; (9) a genuinely red suite still reports FAIL, so the skip path cannot swallow a verdict; (10) a missing declared OpenCode dependency reports SKIP with the npm install remedy; (11) the same missing module with the dependency installed still reports FAIL; (12) a failing suite that is not a module error still reports FAIL. The interpreter is pinned through METODOLOJI_PYTEST_PYTHON (empty means no interpreter available), so the skip probes are deterministic and do not depend on the host's PATH. Control: --broken loads bench_consistency from the pre-change tree, where no resolver exists and sys.executable is hard-coded, and must score below the threshold. Reproducibility: stdlib only, no network, deterministic; the bench writes one JSONL sample per probe.
