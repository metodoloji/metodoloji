## Experiment: E-086 — An existing context can be revalidated without losing its analysis

- **Date:** 29.10.2026
- **Status:** completed
- **Theory:** E-084 gave external contexts a create/complete/index path and E-085 added a safe archive for abandoned drafts. The remaining lifecycle hole is the one the template itself anticipates (`Revalidate when:`) and the finder reports (`version_match: false`): a source moves, the agent must analyze it again, and the only supported action is "edit the file by hand". That path has no mechanical signal that the analysis is in progress, so `check` keeps reporting the entry as reviewed while its provenance is stale, and the index line keeps the old ref until someone remembers to run finalize. A refresh step that flips the entry back to `draft` and dates the new analysis makes staleness visible without discarding the previous work.
- **Hypothesis:** H-086: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the current consistency bench and its `--broken` seeded-defect control. Add a refresh contract that takes a reviewed entry, runs the CLI refresh, and asserts the status becomes `draft`, the analysis body survives byte-for-byte, the analyzed date moves, the audit reports the in-progress state, and finalize re-indexes the updated ref. Add unit tests for refresh (preserved body, missing entry, idempotence, CLI) and archive hygiene (`.archive/` cannot be committed). Seed removal of the status reset in broken mode. Reproducibility is local and offline.
