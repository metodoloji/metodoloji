## Experiment: E-045 — The suite was green from a console and red from the gate: twenty spawn sites inherited a stdio handle the host could not duplicate

- **Date:** 15.10.2026
- **Status:** completed
- **Theory:** Closing E-044 needed its gate run, and the gate reported `ERROR: measurement run timed out after 600s` while the suite it runs as its falsifier failed ten tests — the same suite that had passed for E-043. Neither failure was the code under test. `subprocess.run([...])` with no `stdin` hands the child the PARENT's `STD_INPUT_HANDLE`: CPython's `_get_handles` calls `DuplicateHandle` on it, and when the host has no duplicable stdio handle — the gate runs the measurement through an agent harness, the bench runs pytest as a grandchild, a session runs a skill script — the call raises `OSError: [WinError 6]` in the PARENT, before the child exists. The suite reports it as a failed assertion, and it is order- and environment-dependent: `python -m pytest scripts/tests` fails ten tests with stdin closed and passes with a valid stdin, which is why three runs of the same suite produced 13, then 10, then 8 failures and read as flakiness instead of as a defect. The repo knew the class — thirty call sites already pass `stdin=subprocess.DEVNULL`, one of them with the comment "pytest's fd capture leaves stdin unusable on Windows" — but the remedy had been applied one site at a time as each was noticed, so the twenty that were not noticed stayed unprotected, including the two that matter most for verification: the bench's own `_run_pytest` falsifier and the gate's `run_and_measure`, the process that starts EVERY measurement. The class is E-037's: an artifact asserting a fact nobody measured — here a verification claim that silently depends on the operator having a terminal. The closure makes the rule an invariant of every shipped python tree (AST, derived from the filesystem) instead of a habit, so the next spawn helper cannot reintroduce it silently.
- **Hypothesis:** H-045: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure — run `python scripts/bench/bench_consistency.py`; the new check `_check_every_spawn_hands_stdin` parses every `.py` under `hooks/`, `scripts/`, `bmad/` and `skills/` with `ast` and requires every `subprocess.run/Popen/call/check_call/check_output` call to pass `stdin=` or `input=` (either detaches the child from the parent's handle; `input=` implies `stdin=PIPE`), reporting `file:line` per offender and reporting a spawn hidden behind `**kwargs` as unverifiable rather than passing it. Controls — the falsifier ran red BEFORE the fix: `python -m pytest scripts/tests` with stdin closed failed 10 tests pre-fix and passes post-fix (paired, same command), the full suite with stdin closed is green post-fix (305s) where the pre-fix full suite already failed 8 tests with a VALID stdin, and the new check is driven red on a bare spawn and on `**kwargs`, green on both accepted forms, then pinned clean on the shipped tree. Reproducibility — stdlib only (`ast`), no network, deterministic (pure source inspection).
