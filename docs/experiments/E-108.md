## Experiment: E-108 — An orphaned ledger is not a methodology: deferred work must be installed, counted, audited and named by the core

- **Date:** 03.11.2026
- **Status:** completed
- **Theory:** Deferred work is the methodology's only debt surface that crosses the whole E→QR chain: `bmad-code-review`, `bmad-quick-dev`, `bmad-dev-auto` and the gds variants append flat entries to `{implementation_artifacts}/deferred-work.md`, and `bmad-loop-sweep` triages them into the canonical DW format. The core, however, has no concept of the ledger. `skeleton.py` installs the record skeleton but not the ledger (`DIRECTORIES`/`TEMPLATE_PAIRS` contain no entry), `state.record_inventory` — the parser `orient.py` and the SessionStart inject share — never counts it, `check-methodology.sh` never parses it, the commit quality gate never mentions it, and `development-methodology.md` never names it. The only declaration in `bmad/` is `bmad/bmad-loop/module-help.csv:3`, a catalog row for the sweep skill, not an obligation. So a project that never runs bmad-loop owns a file nothing installs, surfaces, checks or documents: the orphan the maintainer's live tests found. The theory under test is that a ledger no core surface installs or reports is not part of the methodology — installing it in the skeleton, counting it in the shared digest inventory, auditing its format, naming it in the manifestos and advising at commit time makes it a first-class debt surface for every project. Blocking is deliberately out of scope: open deferrals are a normal state, so the integration must be visible and honest, not a new gate.
- **Hypothesis:** H-108: "deferred_work_integration_accuracy >= 0.90"
- **Measurement Metrics:** deferred_work_integration_accuracy >= 0.90
- **Experiment Design:** Measure `scripts/bench/bench_deferred_work_integration.py`: 26 samples in six groups, each exercising the SHIPPED surface against synthetic project trees or the repository's own files. (1) Skeleton install — a fresh `skeleton.install()` copies `templates/deferred-work.md` to `docs/development/native/deferred-work.md`, the copy carries the canonical header and DW entry shape, an existing ledger with entries is preserved byte-for-byte, `status()` reports the ledger missing when a marker-bearing project lacks it, and `declaration_problems()` stays empty after the `commands/init.md` row is added. (2) Digest inventory — `state.deferred_work_inventory()` reports open/done/total from `status:` lines, tolerates a missing ledger as zeros, counts malformed entries (a `### DW-` block with no `status:`), recognizes legacy freeform content, and `state.record_inventory()` exposes the `DW` key with open as its count and the highest `DW-N` as newest (omitted when absent). (3) Audit — `check-methodology.sh` CHECK 9 prints the open/total line for a well-formed ledger, warns on malformed and legacy ledgers, reports absence as "none" without an issue, and exits 0 in every DW case. (4) Commit advisory — `quality_gate.deferred_work_warning()` names the open count, returns empty at zero open, and stays silent when the ledger is absent. (5) Documentation — `development-methodology.md` names the ledger, the `DW-N` format, the three writers and the `bmad-loop-sweep` triager plus the canonical format path. (6) Canonical surface — `templates/deferred-work.md` exists and points at the shipped format doc, which is unchanged. The `--broken` control EXECUTES the pre-fix surface: the skeleton and audit run from the parent revision, the manifest is read from that revision, and the state/quality-gate symbols are verified absent in the pre-fix source. It must score below the threshold. Deterministic, offline, stdlib only; one JSON object per sample with a boolean `ok`.
