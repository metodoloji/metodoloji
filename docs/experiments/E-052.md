## Experiment: E-052 — A hand-off signal whose claim has moved on is delivered as live work (the stale-context baseline)

- **Date:** 16.10.2026
- **Status:** REJECTED
- **Theory:** A board hand-off signal (`handoff.<skill>` alert) is a claim about the code state at the moment it was posted: the sender's run key (`E-NNN`, `story.*`, `IR-*`) named a decision that was true then. Two independent external reports converge on the same mechanism — the LinkedIn note that opened this line ("The failure mode we hit most isn't lost context, it's stale context. Yesterday's decision is still in the handoff file, and the agent obeys it after the code has already moved on. Our fix was dating every recorded decision to a commit, so a handoff can say 'this no longer applies' instead of just repeating the past.") and this repository's own live board, where 11 batons aged 1.07–2.02 days sit unclaimed on `handoff.bmad-check-implementation-readiness` with `consumed: {}`. The engine's validity vocabulary holds exactly two states — a signal is either *delivered* or *absent* (consumed/TTL-pruned) — so "this may no longer apply" is not representable: the read surfaces (`pending_handoffs`, `session_start`'s inject) deliver every waiting alert as live work, and validity is proxied by AGE alone (a write-path TTL). A signal can therefore be perfectly fresh by age and already false by code state.
- **Hypothesis:** H-052: "stale_delivery_rate <= 0.0"
- **Measurement Metrics:** stale_delivery_rate <= 0.0 (with false_alarm_rate reported as the control metric)
- **Experiment Design:** Inputs — `scripts/bench/bench_freshness.py`, which builds its own throwaway git repo per scenario (no dependency on this checkout, no gate key, stdlib + `git` only). Scenario A (derived witness): six fixture records (`E-900`/`E-902`/`E-903` declare `Code Scope: src/**`, `E-901`/`E-904`/`E-905` declare `lib/**`), a hand-off posted from each BEFORE any code moves, then one commit that rewrites `src/engine.py` — so the `src/**` claims are stale and the `lib/**` claims are not, dated only by the record's own last-touching commit. Scenario B (stored witness): `E-910`/`E-911` posted after the module exists, then the same commit. Each signal is probed on TWO delivery surfaces — the peek (`pending_handoffs`) and the session-start inject text — so n=8 stale trials and n=8 current trials. Procedure — `python scripts/bench/bench_freshness.py`. The EXPECTED verdict is computed by an oracle that never imports the module under test: `git log -1 -- <record>`, `git diff --name-only <commit>..HEAD` plus untracked files, intersected with the record's declared `Code Scope` prefix. A trial leaks when the oracle says STALE and the surface delivers something other than STALE (an unlabelled delivery reads as CURRENT); it is noise when the oracle says CURRENT and the surface says STALE. Controls — the oracle's own expectation vector is printed as `trials: stale=8 current=8`, so a fixture that stopped producing both classes fails loudly instead of scoring 0; the false-alarm rate is the paired control that a "mark everything stale" non-fix cannot game. Reproducibility — deterministic, no network, each run in a fresh `mkdtemp`.
- **Sample Size n:** 16 (8 stale + 8 current trials; the gate parses the denominators from the bench output)
- **Code Scope:** scripts/bench/bench_freshness.py, docs/experiments/E-052.md
- **Lineage:** E-051 (the immediately preceding closure: a claim restated by hand in several surfaces and measured in only one direction — the same "the surface asserts more than it checked" shape), E-049 (the audit inventory: a claim that cannot be read is not a measured claim, which is why the stale list here is derived rather than hand-written), E-048 (the relay throttle that strips `(Nm ago)` stamps to compare tables — the measured proof that the delivery plane carries no state signal beyond age), E-037 (the class itself: an artifact asserting a fact nobody measured — here, that a waiting signal is still true).
- **Raw Results:** measured=1.0; n=8
- **Uncertainty:** none (lower-bound claim: no small-sample risk)
- **Metric:** consistent (measured stale_delivery == claimed stale_delivery)
- **Decision:** REJECTED — H-052: measured=1.0 <= threshold=0.0 (gate FAIL)

- **Known Gaps:** the oracle reads the record's LAST-TOUCHING commit as the claim's dating anchor. For a record whose approval commit is not the commit that last touched the file (a later typo fix to the same record), the derived anchor is newer than the approval — conservative in the direction that hides staleness rather than inventing it. Scenario B's stored witness is written by the posting path, so it only exists for signals posted after E-053 lands; the fixture therefore measures the derived path for older boards and the stored path for new ones, and cannot speak to a board whose snapshot predates either.
