## Experiment: E-092 — External-context writes are transactional, boundary-safe, and clock-independent

- **Date:** 31.10.2026
- **Status:** completed
- **Theory:** E-089 consolidated the registry, but three residual failure classes remain visible in current behavior. (1) `finalize` mutates the entry before it validates it: a probe that marks an incomplete scaffold `Status: reviewed` and calls `finalize` gets `ok: false` with 8 findings, yet the file on disk has gained `Last reviewed on` and a `| reviewed |` revision row — a failed registration leaves review evidence behind. (2) The boundary guard only checks the registry root: `_entries` reads `registry/<slug>/context.md` after checking `entry.is_symlink()` but never checks whether the **parent folder** resolves outside the project, and `migrate` writes `entry["entry"]` directly, so a symlinked entry folder can make the authoring half read or rewrite a file outside the registry; `finalize`, `refresh` and `discard` build the same path without an `inside()` check. (3) The audit and the listing read the wall clock (`date.today()`), unlike the finder's `--today`, so `check --strict` can turn red on a date boundary with no repository change and a test cannot pin the freshness it asserts. Two smaller gaps share the same root cause — `prepare` checks for collisions outside the registry lock and can overwrite a concurrently created entry, and a folder without `context.md` is silently skipped by the audit instead of being reported. The theory under test is that a registry command either completes and is indexed or leaves the entry byte-identical, that every entry path is proven inside the registry before any read or write, and that every date-sensitive command accepts a pinned `--today`.
- **Hypothesis:** H-092: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the repository consistency bench and its `--broken` seeded-defect control. Split `_entry_report` into a path-boundary read and a text validator so `finalize` validates a **candidate** text and writes it only when there are no errors; a failed finalize must leave the entry byte-identical. Add a shared `require_entry`/`inside` guard used by `_entries`, `finalize`, `refresh`, `discard` and `migrate`, so an entry folder that resolves outside the registry is refused (fail closed) instead of read or rewritten. Thread an optional `today` through `_entry_report`, `check`, `list_entries`, `finalize`, `refresh`, `discard` and `migrate`, expose `--today` on their CLIs, and reject an invalid date instead of silently falling back to the wall clock. Run `prepare` under `registry_lock` and re-check the slug/source collision inside the lock. Report an entry folder without `context.md` as an audit warning. Make the finder import `REGISTRY_REL` instead of repeating the literal and reject an invalid `--today` with exit 2. Pin every behavior with unit tests, a bench transaction contract and a re-seeded defect that breaks the no-op-on-failure guarantee. Reproducibility is local, deterministic and offline.
