## Experiment: E-007 — Bound the recursion seams so every mode ends a decision (parse, coerce, handler)

- **Date:** 08.10.2026
- **Status:** completed
- **Theory:** The engine's published contract — every hook mode must END with a
  decision, because a crashed PreToolUse hook is a no-decision turn the runner
  may read as an allow (E-002/E-003/E-006 each closed one seam of this class).
  Behavior probing with recursively nested wire payloads mapped three still-open
  sites, all reachable from plain stdin: (1) `json.load` in main() raises
  `RecursionError` at depth ~20000 (CPython 3.14: "Stack overflow … while
  decoding"), which the input boundary does not catch — ALL SEVEN modes then
  exit 1 with empty stdout; (2) a deep value on a routing key (path/command)
  survives the parse but recurses without bound in `_coerce_json_scalar`
  (function frame + genexpr frame per level) → `RecursionError` escaping at
  main.py `result = handler(json_in)` — guard, pre, quality, deploy, audit all
  FAIL-OPEN at depth ≥500 (stop/session_start never coerce, which is why they
  survived); (3) any other handler exception lands on the same unguarded line.
  Unknown tool_input keys and tool_response at the same depth are safe today
  (nothing recurses native containers), so the seam is the coercion point, not
  native values. Fixing all three keeps ONE policy: a recursion-class failure
  behaves exactly like bad input — fail-closed on stop/guard/pre, allow on the
  report-only hooks — instead of escaping as a traceback.
- **Hypothesis:** H-007: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure —
  run `python scripts/bench/bench_consistency.py`, which evaluates independent
  doc/code-consistency claims and prints `consistency_accuracy=(x/y)`; two new
  checks pin the E-007 claim (a depth-4000 value coerces to a bounded string
  without raising while shallow renderings stay byte-identical, and the seam is
  covered by unit, end-to-end and boundary tests), and the suite's pytest
  falsifier covers the new regression tests. Control — the bench's own "pytest
  suite green (falsifier)" check pins that the code under test still passes the
  full suite. Reproducibility — stdlib only, no network, deterministic (a fixed
  tree yields a fixed x/y); the measurement reports the tree as it is,
  independent of this record (E-001).

- **Known Gaps:** the depth bound truncates a routing value beyond
  `_COERCE_MAX_DEPTH` with a deterministic marker — a deep path renders as
  marker text and resolves outside the root (deny direction, fail-closed), not
  as a lossless rendering; deep UNKNOWN keys and tool_response stay native by
  design (E-003) and are only safe as long as no reader recurses them — a
  future `json.dumps` of a >~20k-deep native value would raise inside a handler
  and now lands on the handler boundary (decide, never crash) but loses the
  record body. The handler boundary mirrors the input policy (stop/guard/pre
  fail-closed; quality/deploy/audit/session_start allow) — it does not change
  which hooks are blocking, only that an escaped exception no longer produces
  a no-decision turn. Python-version drift: the parse-site failure text
  ("Stack overflow … while decoding") is CPython 3.14-specific; the fix keys on
  the exception type (RecursionError), not the message.
