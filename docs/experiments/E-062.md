## Experiment: E-062 — One sanitizer for every filename, and one containment helper for both planes

- **Date:** 17.10.2026
- **Status:** completed
- **Theory:** E-061 measured the storage plane resolving a run's spec from outside the project root: `store.load_spec` joined the RAW slug into the specs dir (so `../../../../loaded` read a JSON file beside the project and handed it to every surface as the run's workflow definition), and it opened the state's `spec_file` wherever that pointed. The fix is not a new policy but the missing half of two existing ones. (1) The sanitizer is the seam E-008 closed for the STATE file; the spec filename was left building paths from raw input, so it now goes through the SAME function — extracted as `store.safe_slug` and used by `state_path`, `save_spec` and `load_spec`, because a second copy of the rule is exactly how the two paths disagreed in the first place. (2) The containment is the boundary E-060 drew for the artifact read; both candidates a spec can come from (the slug-named file and the recorded `spec_file`) are now resolved through it, and the implementation moved to `bmad/workflow/paths.py` so the evidence plane and the storage plane call ONE function — a second copy would be a second opinion on the same boundary, and the two planes would drift at the first platform that resolves links differently. Neither half refuses anything the kernel itself writes: a legitimate in-root spec file and a legitimate slug still resolve exactly as before, which is what the paired control measures.
- **Hypothesis:** H-062: "storage_escape_rate <= 0.0"
- **Measurement Metrics:** storage_escape_rate <= 0.0 (with `storage_control_rate <= 0.0` carried as the paired false-refusal control, parsed from the same bench output)
- **Experiment Design:** The SAME bench, fixtures and detectors as the E-061 baseline — `scripts/bench/bench_workflow_evidence.py` — with the trial-scoring corrected in the same change (a row lookup that only knew the raw slug scored an ABSENT inventory row as a difference; it now resolves the sanitized spelling too, which is also what revealed that the inventory is immune to the slug addressing by construction, because it enumerates filenames and a filename carries no separator). The only other difference is what the plane resolves: the sanitized slug candidate, checked for containment before it is opened, and the recorded `spec_file` opened only when it still resolves inside the root. Everything else is unchanged and re-measured in the same run: the delivery bucket (12+12), the read budget (6), the artifact escape (9 + 3 gate trials) and the storage control (3). Controls: `false_alarm_rate` and `storage_control_rate` must both stay 0.0 (a satisfied, in-root artifact stays CURRENT, and a legitimate run keeps resolving its own spec — the failure mode of a containment applied too eagerly); `--baseline` restores the pre-fix `load_spec` verbatim, so the recorded red is produced by the old resolution rather than modelled. Procedure — `python scripts/bench/bench_workflow_evidence.py`.
