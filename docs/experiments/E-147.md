## Experiment: E-147 — The retired config paths are removed, not merely outranked

- **Date:** 2026-11-13
- **Status:** completed
- **Record Kind:** contract
- **Theory:** E-146 gave the plugin config one owner (`/config.toml`) but left the four old paths readable as lower-priority fallbacks, and left the `{project-root}/bmad/*.toml` project layer in the merge. A file that is still read is still a second owner: the merge order is the only thing keeping the two coherent, and any reader that skips the merge disagrees with the ones that do. That is the same duplicate-owner class E-146 closed, left half-open — and a fallback whose stated purpose is "an upgraded install keeps its gate policy" cannot be exercised by any test in this repo, because the repo itself no longer ships the file it falls back to. Six paths are retired here: the four plugin-side ones (`bmad/config.toml`, `bmad/config.user.toml`, `custom/config.toml`, `custom/config.user.toml`) and the two project-side ones (`{project-root}/bmad/config.toml`, `{project-root}/bmad/config.user.toml`). None is read, written or created; a project configures itself through `docs/` alone, so the merge drops from six layers to four.
- **Hypothesis:** H-147: "config_equivalence_accuracy == 1.0"
- **Measurement Metrics:** config_equivalence_accuracy == 1.0
- **Experiment Design:** Inputs: the plugin tree at this commit, the pre-consolidation baseline fixture (`scripts/bench/fixtures/config-baseline.json`), and the E-146 resolver/engine read from git commit 7249e5b as the pre-fix implementation. Procedure: `scripts/bench/bench_config_consolidation.py` runs six checks — (1) exactly one plugin team config ships and no retired path survives in the tree, (2) the full merged dump still equals the baseline, (3) the documented targeted `--key` read still equals it, (4) every live hook-engine read still equals it, (5) no shipped reader names a retired path (resolver, hook engine, hook shell entry, check scripts), and (6) all four retired files planted hostile on both a plugin root and a separate project root move neither the resolver's answer nor the engine's gate mode. Control: `--broken` runs the E-146 resolver and the E-146 hook engine from commit 7249e5b, so the control is the old reader rather than a paraphrase of it; it must honour the planted retired files. Reproducibility: stdlib only (tomllib, subprocess, tempfile), no network, deterministic apart from git availability.
- **Code Scope:** config.toml, bmad/scripts/resolve_config.py, hooks/engine/modules/config.py, hooks/scripts/hook-entry.sh, bmad/tests/test_resolve_config.py, scripts/bench/bench_config_consolidation.py, scripts/bench/fixtures/config-baseline.json, scripts/check-plugin.sh, scripts/check-methodology.sh, scripts/tests/test_check_methodology_status.py, commands/init.md, docs/config.toml, GUIDE.md, KILAVUZ.md
- **Lineage:** E-146 (the consolidation this completes: its four legacy fallbacks are deleted here, and its bench cases 5–6 are replaced because "the legacy file is still read" is no longer the invariant), E-047/E-048 (the duplicate-manifest class), E-145 (ask the owner instead of restating it), E-017/E-009 (a config layer must never kill the decision path)
- **Control Command:** python3 scripts/bench/bench_config_consolidation.py --broken
- **Raw Samples:** docs/experiments/E-147/raw/samples.jsonl
- **Measure:** categorical
- **Census:** The closed input set is the six checks the bench enumerates: (1) one plugin team config ships and none of the four retired paths exists in the tree, (2) the full merged config dump equals the pre-consolidation baseline, (3) the documented targeted --key read equals it, (4) all eight live hook-engine reads equal it, (5) no shipped reader names a retired path, and (6) retired files planted on both a plugin root and a separate project root change neither the resolver's answer nor the engine's gate mode.
