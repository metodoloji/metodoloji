## Experiment: E-048 — The version-owned file set was declared in five places, none of them measured; and the lists E-047 derived were read with the CR still on them

- **Date:** 15.10.2026
- **Status:** completed
- **Theory:** The set of files that carry the release number is one contract with three consumers — `scripts/bump-version.py` rewrites them, `.githooks/pre-commit` refuses an unstaged edit in them and `git add`s them after the bump, and `scripts/check-plugin.sh` §6d3 audits them for the skew that a stale marketplace cache serves. It was restated in four shipped places and nothing measured the agreement: the hook's `FILES` (plus a prose count, "The seven files whose version claims follow the number"), §6d3's literal `VERSION_FILES`, and the `MANIFESTS` tuples of both release tests. `bump-version.py`'s own header called itself the §6d3 agreement set and stopped there. Measured 2026-10-15, running the new rule against the shipped tree fired immediately on three of the four sites: §6d3 carried a second copy of the five manifests AND neither derived the list from its owner nor ran any audit of it, while `scripts/tests/test_git_hooks.py` and `scripts/tests/test_release_pipeline.py` each seeded their throwaway repositories from their own hand-written tuple. The failure mode is the one §6d3 exists for: a manifest added to the owner would be rewritten by the bump, not staged by the hook (a skewed tree in the very commit that owns the number) and audited for skew by nothing — the stale-cache incident one level up. The same measurement exposed a second, live defect in the artifact E-047 shipped the day before: a Windows python writes CRLF into a pipe, so `--probe-paths` / `--manifest-paths` read through `for x in $(…)` hand every token but the LAST a trailing CR, and the consuming test (`[ -f "$PROJECT_ROOT/$f" ]`) can never match it. Demonstrated directly — `od -c` shows `…_template.md\r|` without the strip and a clean `…_template.md|` with it — and through the real audit: on a fixture project holding only the FIRST probe plus the marker, §6d with E-047's derivation printed `[ERROR] .metodoloji/initialized present but no skeleton copy found — stale marker` (a false ERROR on a healthy install), and `[OK] init marker consistent with skeleton` once the strip was added; the same signature made §6d3 report "no version" in four of five manifests. The class is the project's recurring one (E-037): an artifact asserting a fact nobody measured — here five artifacts asserting the release-set contract, and two derivations asserting that a shell read them as written.
- **Hypothesis:** H-048: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Inputs — the plugin repository at this commit. Procedure — run `python scripts/bench/bench_consistency.py`; the new check `_check_version_owned_sites_agree` loads `scripts/bump-version.py`, demands the shipped tree is clean, drives the real `--audit-sites` (exit 0), `--manifest-paths` and `--owned-paths` against the module's own constants, pins that §6d3 invokes the audit and that the two falsifier tests exist by name, reads §6d3's derivation through a real shell and requires the tokens to equal `MANIFESTS`, verifies `test_release_pipeline.py` seeds from `bump.MANIFESTS`, then rebuilds the contract in a temp tree and mutates one site at a time — the hook dropping a file, gaining a phantom file, and carrying a stale count in its own comment, §6d3 restating the manifest list, §6d3 unhooking the audit, and a release test regaining a hand-written tuple — requiring the copied script's CLI to exit 1 and to name the drifted file each time. The E-047 check gained the same treatment for its own artifact: §6d's derivation is now run through a real shell and must yield `SKELETON_PROBES` exactly. Controls — the falsifier ran red BEFORE the fix (three sites), and after it the healthy tree and the healthy temp copy both exit 0 while all six mutations are rejected by name; the CR defect was measured both ways (od plus the §6d fixture before/after). Reproducibility — stdlib only, no network, deterministic (file reads plus subprocess runs).
