## Experiment: E-076 — Relevant external context discovery has one deterministic contract

- **Date:** 28.10.2026
- **Status:** completed
- **Theory:** E-075 established a persistent external-context registry and wired discovery instructions into research, architecture/readiness, implementation, review, and release preparation. A behavior review found the remaining weak point: every skill independently tells the agent to enumerate folders and decide relevance. There is no shared executable discovery contract, so naming/index drift or different matching choices can make the same registered context appear in one stage and disappear in another. This experiment extends the repository's measured self-consistency claim while adding a shared read-only registry finder, regression tests, and one pinned discovery contract used by each stage.
- **Hypothesis:** H-076: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the current tree with `python scripts/bench/bench_consistency.py`; use its existing falsifiable control `python scripts/bench/bench_consistency.py --broken`, which mutates a temporary copy and must remain below 0.90. After approval and implementation, run targeted finder tests, the full pytest suite, the consistency bench, and the finder contract check. The feature-specific tests will cover missing/empty registries, relevance ranking, deterministic paths, analyzed-version mismatch, bounded results, and symlink containment. The benchmark will require the finder to be exercised by tests and required workflow surfaces to invoke it and consume the returned context paths. Reproducibility is offline and deterministic on a fixed tree.
