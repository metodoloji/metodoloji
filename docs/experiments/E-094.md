## Experiment: E-094 — One source has one identity in the external-context registry

- **Date:** 31.10.2026
- **Status:** completed
- **Theory:** E-089→E-093 made the external-context registry safe, transactional and boundary-checked, but its duplicate rule still compared the raw source text. A probe on this host registered `https://github.com/mastra-ai/mastra` and then `https://github.com/mastra-ai/mastra.git` as two entries, and a second probe did the same for `https://mastra.ai/docs` versus `https://mastra.ai/docs/#intro`, `.../docs/`, `https://mastra.ai:443/docs` and `./src.md` versus its absolute spelling. `check` could not see the split either, because its duplicate test also used the literal cell text. A local `src.md` and a relative spelling from another working directory name the same file but look different. The theory under test is that a source has one identity independent of the spellings that do not change the resource, that both the writer and the audit derive that one identity, and that the normalisation must not collapse genuinely different pages.
- **Hypothesis:** H-094: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90
- **Experiment Design:** Measure the focused source-identity bench `scripts/bench/bench_external_context_identity.py`: four duplicate spellings that must be refused (repository `.git` suffix, `#fragment` and trailing slash, explicit default port, a local path written through a `..` segment) and two paired false-alarm controls that must still register (two different local files, two different URL paths). The `--broken` control restores the pre-E-094 behavior in memory — `classify_source` returns the raw text and `source_key` compares it — and the four duplicate cases must fail while the two distinct controls still pass. Add `normalize_source`/`source_key` to `external_context_common.py`: URLs lose host case, a default port, a fragment, a trailing slash and a repository `.git` suffix while path/query case is preserved; local paths are resolved, with a relative legacy path resolved against the project root rather than today's working directory; the key is normcased on the host filesystem's own rules. `classify_source` now stores that canonical spelling, `prepare` compares it under the existing collision check, and `check` derives cross-entry duplicate-source findings from the same key so an entry written before this change is reported instead of surviving on a different spelling. Pin the rules with unit tests (URL and path spellings, stored canonical text, refused duplicate `prepare`, reported legacy duplicate) and one consistency-bench contract. Reproducibility is local, deterministic and offline.
