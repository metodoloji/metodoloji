## Experiment: E-002 — Close the engine's non-object-input leak and widen its self-guards

- **Date:** 07.10.2026
- **Status:** completed
- **Theory:** Self-hosting discipline (P4 + ASLA #60): the plugin governs its own
  repository with the same mechanical instruments it ships to projects. Its
  documented contract is that the guard/stop/pre hooks stay *fail-closed* on
  malformed input — a leaking guard is the class the whole engine exists to
  prevent. Behavior evidence (probing `main.py` with `[]`, `"x"`, `null`, `5`)
  shows the contract held only for *unparseable* JSON: valid JSON that is not an
  object reached the handler and raised `AttributeError` inside
  `normalize_hook_input`, printing a traceback and NO decision — a crashed
  PreToolUse hook the runner may read as an allow. A second class: a mechanical
  guard is only as wide as its scope list, and the consistency bench's
  duplicate-def scan omitted three live engine modules.
- **Hypothesis:** H-002: "consistency_accuracy >= 0.90"
- **Measurement Metrics:** consistency_accuracy >= 0.90

  now covers every engine module and the engine input-boundary regression tests.
  Control — the bench's own "pytest suite green (falsifier)" check pins that the
  code under test still passes the full suite, including the new non-object-input
  tests. Reproducibility — stdlib only, no network, deterministic (a fixed tree
